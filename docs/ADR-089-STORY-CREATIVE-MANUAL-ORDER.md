# ADR-089：创作请求遵循当前编排与已选素材

日期：2026-09-22。状态：实施。

用户已选定 35 张照片和镜头时长，要求先修正后两种制作方式的实现限制，再制作对比视频。旧 editable-story-v1 把拍摄时间单调递增当作时间线合法性条件，与手动排序冲突；Atelier 2.0 只容纳 26 张素材。仅修改按钮不能解决制作端校验。

## 决定

- 可编辑协议 1.1 保留请求 shots 的全部成员及顺序；拍摄日期仅作事实，不决定剪辑顺序。未知日期可用，但不得以 factRefs 引用缺失事实。锁定/明确编辑的字幕、时长、章节归属及已编辑章节标题保护不变。
- Atelier 协议 2.1 允许 1–100 张当前已选照片，包含未知日期。选中顺序必须贯穿冻结的场景素材顺序，锁定字幕/时长仍校验。100 是本次有界交换上限，不是模板张数。
- 本地能力声明发布新版本；新请求与回传版本绑定。旧 1.0/2.0 请求维持旧约束，旧请求及成片不重写。
- Atelier 提交渲染时校验当前已选集合，不再误与整个候选图库数量比较。指纹、素材版本/hash、路径防护及本地使用限制不变。
- 检查连接有运行状态、重复点击保护和带时间的检查结果。

- OpenMontage 两个交换模块：15 项通过，包含 35 张准备、顺序/锁定保护、旧协议拒绝超限及不可变结果/来源安全回归。
- 正常构建与严格签名通过，日常 App 已更新。构建与日常 debug dylib SHA-256 相同：`da41f6e043bb2b9ee3b3e211ff96e8a41090a7c9a5554cb98f22b900dd956dd4`。
- 日常 App 重开已保存故事显示 332 张候选、已选 35 张、0:56.03；创作页显示“本地制作已连接”和带时间的“已连接并可制作”。检查按钮后的 UI 自动化出现 noWindowsAvailable，未完成真实新请求发布验收，不将合成测试称为真实视频交付。
