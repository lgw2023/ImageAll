# ADR-122：日常 USB 自动连接

2026-10-27。用户要求已配对手机插线后尽量自动连接，保留首次身份确认，减少双端反复操作。仅连接自动化，不自动开始或恢复照片上传，不改变校验、提交、清理、传输路线及真实数据范围。

Mac连接监控归App生命周期所有，无须打开设置；每2秒发现物理USB设备，单设备时自动尝试，多个设备时等待用户选择。不使用Wi-Fi发现作为USB替代。失败按2→4→8→15秒退避，单一连接尝试；会话世代阻止旧回调复活。关闭“允许连接”会终止通道；手动断开暂停该设备直到手动恢复或观察到拔插，不立即自动连回。

手机未选择过连接方式时默认等待USB；明确选择网络的偏好继续保留。前台返回恢复USB监听，后台停止，临时inactive不废弃身份确认。仅同时持有刷新凭据、有效设备ID、已存TLS身份、同一Mac ID及相同证书指纹、未过期请求时跳过重复点击。随后仍经过原证书固定与刷新凭据验证；失效或撤销的凭据不会自动新配对。首次或身份变化在手机主界面显示原确认/重新配对流程，拒绝后停止监听，本次App会话内须用户主动恢复才继续；正常重启App重新进入自动连接。

Mac复用未过期的配对请求，避免每轮发现使二维码/正在确认的请求作废；USB通道的就绪不代替业务认证。手机确认的新请求仍限定请求及世代，身份替换必须明确确认。自动连接本身不增加访问权限、不生成新导入任务、不改动选片。

验收：合成证明首次/缺失身份/不同主机/不同证书/过期/非TLS拒绝自动恢复，同身份可自动进入既有认证；双端构建；日常手机打开后无双端连接点击恢复，手动暂停保持，重新打开手机前台可自动恢复，Mac设置关闭仍可连接。对比原手机任务和Mac照片/整理记录，新增上传为零。真实拔插若需实体动作单独记录；不以软件重启冒充物理拔线。

实测补充：快速停止并重启NWListener时，旧端口尚未异步释放会得到Address already in use。采用等待旧监听cancelled回调后再启动新监听，并以监听实例身份隔离旧连接/失败回调；不靠固定延时或反复叠加监听。新增立即停止/重启合成测试复现后通过，九项USB协议测试通过。

验收结果：日常双端自动连接、前后台恢复、手动暂停保持与恢复通过；首次/身份变化保留确认由合成策略和手机生命周期测试覆盖。3,727项相关数据库摘要及手机任务语义保持，未开始新导入。报告：`/Volumes/SSD1/.codex-builds/USB-AutoConnect-20261027/Evidence/REPORT.md`。
