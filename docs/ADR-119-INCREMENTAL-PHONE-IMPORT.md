# ADR-119：新增手机内容追加到既有来源

2026-10-26。状态：已实施并通过真实增量迁移、双端收尾与正常重启验收。

用户明确授权将上次导入后新增的全部照片和视频作为新批次迁移，并追加到上次保存目录与现有来源。此次真实任务替代当前完整规模合成串联作为优先实机路径，不能将真实批次时长等同先前固定 4 GiB 基准。原手机照片保留，不启用 iCloud 下载。

新内容按当前 PhotoKit 可见非隐藏照片/视频减去原任务冻结范围及之后已保留任务范围计算，不按拍摄日期判断。旧范围只从本机任务与身份映射读取，不为旧范围逐项探测可用性或追查历史差异。要求完整照片权限、原 install/epoch 一致，先预览新增计数后冻结。旧范围之外的更早拍摄内容同样纳入，避免日期误判；该范围定义是相对既有任务的增量，不声称有系统“加入时间”的完整历史。

原任务保存到私有 CompletedTasks，累计范围记录绑定 install/epoch 后原子保存，再在本机数据库事务中替换待分享范围。存在未提交同步操作/快照或预览版本过期时拒绝切换，不丢弃整理修改。事务失败保留原选择；任务记录切换失败则沿用持久化错误阻断导入。预览与确认均不传输原件，之后正常开始一个新 taskID/migrationID。

Mac 已有来源键为 install、epoch、归档父目录；相同键复用 sourceID，批次文件保存在新的 imageallarchive 子目录。发布只添加本批资产/引用，已有资产和编辑不覆盖。用户本轮授权对既有父目录写入该新批次及收尾其暂存，不扩大到旧原件读取、修复或清理。故障注入仍仅合成；真实批次只进行正常暂停、重连、续传、校验、发布与新任务自动收尾。

验收：先合成证明排除旧范围、版本冲突与待同步修改拒绝；复用既有同来源多批次测试。实机预览/确认新增范围、独立批次身份、原 sourceID 不变；最终核验本批完整性、原批资产与编辑摘要保持、完成后同任务重启无新增上传。


实机补充（2026-10-26）：手机收尾误将 `inventoryWatermark` 用作 `minimumFactWatermark`。真实新批次清点序号为 77、整理修订为 0，合法快照被误拒为 `publishedFactsChanged`；两者属于独立计数域。按已有完整归档校验语义，收尾最低整理水位改为清单媒体的最高 `factRevision`，清点序号仍独立约束快照顺序。该修复不改动摘要、作用域/身份、旧回执拒绝、完整性及路径检查。合成 RED/GREEN 与旧整理修订/摘要变化拒绝回归通过；实机沿原任务恢复，不改写现有任务或归档内容。

修复版于 17:40 实机自动收尾完成，17:41 正常重启/重连后同任务 complete 保持。855 项加入原来源，总数 3,721；双端临时载荷为零、必要记录保留，原资产与整理摘要保持。证据见 USB-NewBatch-20261026/Evidence/REPORT.md。

## 2026-10-27：日常新增入口与交接提示

用户要求在手机主界面直接导入新增内容。已有接收完成任务时，“此 iPhone”和“待分享”首页提供“导入新增内容”，复用既有范围预览与确认；确认后直接进入待分享进行连接和发送。无完成任务时首页进入当前导入，未完成任务继续复用原任务，不将入口点击当成新建任务或发送授权。旧的沿用当前选择操作保留在更多操作中并明确确认，防止误当新增范围。

Mac 顶部说明统一为手机发起、持久接收交接后可拔线、Mac 自动核验入库发布收尾、原来源浏览。旧封存批次的手动入库只在其适用上下文展示。只在已有 Mac 接管回执的状态展示可以拔线，传输中提示保持前台及连接；保持 Mac App 运行和目标磁盘连接。此切片不改动传输、范围计算、数据提交、校验及清理契约。

验收使用当前 Xcode 双端构建与既有任务的入口/文案只读检查，不为界面测试重复导入。核对上一批 6 张照片在原来源的网格与单图浏览，前后资产和整理数据库摘要保持；故障测试继续使用独立合成数据。

## 2026-10-27：Mac 导入设置收敛

用户指出设置分散、说明过多，当前优先级调整为先收敛日常导入界面。默认仅一张“从 iPhone 导入”卡：允许连接、实际 USB 通道、保存位置、简短发送/拔线提示、当前任务与查看照片。删除整页四步教程；历史批次、维护/恢复工具与容量/离线导入默认折叠；网络配对、网页配置和旧分享目录放到独立高级展开区。USB设备以传输实际使用的 usbmux 发现为准，不再用独立 ImageCapture 发现结果在同一卡生成矛盾状态。

未完成或失败任务优先展示，不能被已完成历史任务遮蔽。显示“本批可以拔线”只依据 Mac 已持久接管的 host job，不因系统发现手机或导入历史存在而推断当前传输完成。查看照片只查询既有发布来源并导航；不存在或凭据失效时显示原因，不自动重新发布。原核验、提交、容量保护、清理与旧维护动作的门禁不变。验收为日常 Xcode 构建、实际设置页默认一屏、按需展开维护/网络配置、查看既有来源，以及资产与整理记录前后摘要一致；不新增真实导入。

默认状态刷新每3秒仅读小型接管记录，内容未变不重发状态更新；旧版封存目录只在展开接收选项时检查，其维护错误在该区域显示。实机出现接收记录路径安全拒绝后，发现该提示在后续读取成功时未清除；现在仅在同类读取成功后清除旧错误，仍失败则继续显示。旧版维护错误独立呈现，原安全拒绝不放宽、不修写历史目录。启动时图库尚未就绪会自动重取一次有效结果。

## 2026-10-27 连接设置层级修正

用户明确要求网络连接相关功能与“从 iPhone 导入”同级。移除“网络连接与高级设置”的外层折叠和容器；连接新设备、已配对设备、公网访问、网页访问白名单及本机调试直接作为顶层卡片显示。仅连接服务诊断、旧版分享目录及导入卡内部维护选项保留各自按需展开。此决定取代上文网络配置统一放入高级展开区的布局，不改变权限、认证、传输或数据处理。验收为 Mac 构建通过及日常设置页确认独立卡片层级。
