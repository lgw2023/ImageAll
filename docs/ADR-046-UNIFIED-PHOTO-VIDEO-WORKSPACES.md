# ADR-046：照片 / 视频同入口、分媒体域工作区

> 状态：已决定，待实施（2026-07-29，项目所有者对话批准）
> 相关：`docs/VIDEO-MEDIA-WORKSPACE-SPEC.md`、`docs/TRAINING-WORKSPACE-SPEC.md`、
> ADR-041、ADR-044、ADR-045
> 取代：`docs/PERF-OPT-STORAGE-IDLE-VIDEO-HANDOFF.md` 中“视频任何阶段均不入库并清除标签”的产品决策；
> 该文档其余存储迁移与空闲预热历史仍有效。

## 背景

ImageAll 当前把资产、查询、预览、标签、建议、训练和图库瘦身默认视为静态图片，并在枚举与启动清理中
主动排除视频。项目所有者决定引入完整视频能力，但不新增一套平行的 App 导航：用户仍从现有图库、
待审核建议、训练工程和图库瘦身入口进入，只在各工作区内部切换照片 / 视频。

视频首版不分析完整时间轴或音频，统一以一张稳定的代表缩略图参与现有图像 AI 能力。

## 决策

### PV-P1：外层入口完全复用，工作区内增加大标签页

- App 侧栏及最外层信息架构保持不变，不新增“视频图库”“视频训练”等平行入口。
- 图库浏览、待审核建议、训练工程、图库瘦身的内容顶部均显示醒目的
  **「照片｜视频」**大标签页。
- 每次从外层进入一个工作区时默认选择“照片”；在同一工作区内切换来源、标签、Run、筛选或详情时，
  保持当前媒体页，不得自动跳回照片。
- 两页复用相同交互结构与功能入口，视频页的资产集合、计数、选择、任务、建议、Run 和模型状态只包含
  视频，不与照片混合。

### PV-P2：`MediaKind` 是贯穿全链路的媒体域

- 领域值固定为 `image` / `video`；用户界面显示为“照片” / “视频”。
- `media_type` 继续表示 UTI / 编码容器，不能拿它代替媒体域。
- 资产查询、无标签计数、搜索、来源筛选、Review、训练 Run、模型槽位、建议生成、图库瘦身任务都必须
  显式携带媒体域，默认值为 `image` 仅用于兼容旧记录。
- 切换媒体页时清空跨页资产选择和详情选择，防止在视频页对隐藏的照片执行标签、训练或回收动作。

### PV-P3：标签字典共享，标签事实与统计按资产自然隔离

- 照片和视频共用一套标签 / 标签组字典；不创建两套同名标签体系。
- `asset_tag_decision` 仍以 `asset_id + tag_id` 表示人工事实，因此照片与视频的决定天然分离。
- 标签旁计数、无标签数量、批量打标范围和 Inspector 内容按当前媒体域计算。
- 视频标签支持与照片相同的人工确认、拒绝、撤销、批量操作和 Review 流程。

### PV-P4：视频以代表缩略图复用现有图像 AI

- 每个视频生成一张稳定的 **代表缩略图（video poster）**；图库卡片始终叠加播放标识与时长，避免被
  误认为照片。
- 图库中的视频卡片在指针稳定悬停后原位静音循环播放；全局同时只允许一个悬停播放器。移出卡片、
  卡片滚出可见区、离开图库或 App 失去焦点时立即停止并释放播放资源。
- 悬停播放不取代代表缩略图：准备、失败、仅云端或不支持播放时继续显示代表图。视频卡片的 hover
  手势优先用于播放，详细元数据由 Inspector 承担；照片卡片继续保留悬浮说明。
- Feature Print、DINO / embedding、标准模型建议、个人质心模型、个人 AdamW 模型与相似度能力，
  首版均把代表缩略图当作该视频的唯一视觉输入。
- 视频训练 Run 的样本身份仍是视频资产 ID，但必须记录 `media_kind=video` 与代表缩略图策略版本；
  不得把视频伪装成照片样本写入历史。
- 首版不声称理解视频动作、时序、镜头变化、字幕、语音或音频内容；相关能力另立 ADR。

### PV-P5：照片与视频共享算法实现，但模型产物严格分槽

- 两种媒体可复用同一编码器和训练实现，以取得 Module 的深度、调用方的 leverage 和维护的 locality。
- 训练 Run、published 槽、模型头、预测和阈值按 `media_kind + method` 分槽。
- 视频页不得读取照片页训练出的个人模型或 pending 建议，反之亦然。
- Review 行身份扩展为 `asset_id + tag_id + suggestion_origin`，其所属媒体域由资产确定；查询必须显式
  限定当前媒体域。

### PV-P6：图库瘦身保持同构入口，但相似语义必须诚实

- 视频瘦身只分析代表缩略图，不读取或遍历完整视频来计算内容哈希；文件大小和时长不影响分析内存。
- 代表缩略图相同也不能证明完整视频相同，因此视频不进入“字节完全相同”或自动清理组，只进入
  “代表缩略图重复 / 相似”组；UI 必须显示“按代表缩略图”，不得表述为完整视频内容相同或相似。
- 新的 visual-digest 指纹算法版本继续使用 `videoPoster.v1`，以规范化代表图视觉摘要作为完整性标记，
  并使旧的完整视频 SHA-256 结果失效。
- 视频回收、恢复和永久清理复用现有来源安全规则；Apple Photos 资产仍只使用公开 PhotoKit 语义，
  不直接修改 Photos Library 包。

### PV-P7：本地优先与云端下载规则不变

- 文件夹视频只在现有 security-scoped 授权内读取；播放期间必须保持授权租约。
- Apple Photos 视频枚举必须通过 PhotoKit。自动化测试不得读取受保护真实图库。
- iCloud-only 视频默认只展示可用占位 / 系统提供信息，不因缩略图、预热、AI 或训练隐式下载原视频。
  需要下载时必须由用户显式发起并显示进度。

## 架构后果

1. 新增统一的媒体域 Module，其小 Interface 至少负责：
   - 当前工作区媒体域；
   - 查询 / 任务范围注入；
   - 媒体域切换时选择清理；
   - 用户可见名称和图标。
2. 新增代表缩略图 Module；文件夹与 PhotoKit 是位于同一 seam 的两个 Adapter。
3. 当前把“照片”写死在页面文案、查询和训练配置中的实现必须逐步改为媒体域驱动；禁止复制整套
   `VideoWorkspaceModel` 造成两套易漂移实现。
4. 建议新增 migration `v026`，至少保存 `asset.media_kind`、`asset.duration_ms` 与
   `training_run.media_kind`，并将模型槽唯一键扩展为媒体域 + 方法。
5. 现有启动期视频清除逻辑与枚举跳过逻辑必须删除或改造；旧清理已经删除的历史视频标签无法从源文件
   重扫恢复，只能依赖用户已有备份 / 导出。

## 非目标

- 首版不做逐帧、多关键帧、音频、字幕或时序模型；
- 不新增独立视频侧栏或第二套标签字典；
- 不在 Companion / Remote 首版传输完整视频；
- 不因视频接入放宽真实照片只读保护、缓存配额、数据库原子性或 Git 边界。

## 验收摘要

- 任一外层工作区进入时默认照片；切到视频后，页面结构和主要动作与照片页一致。
- 照片 / 视频的计数、选择、标签、建议、训练、模型槽和任务结果无交叉污染。
- 一个本地视频可完成：入库 → 代表缩略图 → 人工标签 → AI 特征 / 建议 → 视频训练 Run →
  Review → 重启后结果仍在。
- 视频卡片可辨识、可预览播放；AI 与相似度界面明确说明使用代表缩略图。
- 合成 fixture 覆盖文件夹与假 PhotoKit Adapter；自动化过程零访问 `/Volumes/HDD2` 受保护数据。
