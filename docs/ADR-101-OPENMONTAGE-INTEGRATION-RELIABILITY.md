# ADR-101 OpenMontage 集成稳定化

2026-09-23，已实施。用户授权完整落实版本发布、统一启动、状态恢复、受控重试及诊断。

## 差异与决策

现有内容身份、原子提交、严格哈希、正常退出升级继续保留。当前构建原地修改共享 Runtime，协议常量分散，三个入口启动规则不同；历史成片恢复被在线能力门禁阻断，轮询异常保留等待进度。

1. `scripts/openmontage/integration-contract.json` 为集成常量的唯一来源；生成 Swift 常量，Python 补丁读取同一清单。构建校验清单、Schema/lock、创作版本以及生成代码，未知版本拒绝打包。
2. 在构建私有目录从固定源码归档重新应用补丁；复制预装依赖，不修改 Vendor Runtime。按输入身份缓存经过校验的产物，payload 内容身份仍绑定全部实际文件。
3. 所有本地自动制作入口使用同一个合并并发启动的协调器；helper 核验运行路径、正常排空旧工作、启动后校验握手。不强杀活动任务，不因 App 重启自动重发模型请求。外部 Agent 协作发布不冒充自动执行。
4. 历史任务读取独立于当前连接。任务状态与观测错误分开，错误时隐藏陈旧百分比，明确状态待确认，保留取消/重新检查。仅已确认失败或取消的本地任务允许从冻结副本重试，任务关系独立记录，不改原终态；未知/活动任务拒绝重试。
5. 诊断采用字段白名单，不导出原请求、照片、路径、密钥、模型提示词或原始错误全文。
6. 日常安装通过统一发布脚本：构建/签名、契约检查、随包 helper + Swift 合成任务 + 真渲染 + App 客户端验证结果，以及旧执行器升级检查后，再备份/更新日常路径。验收用独立任务目录、合成媒体，不连接生产图库，不调用付费模型。

依次完成契约及构建、运行和状态、恢复和诊断、真实打包验收。验收证据另记。无需更换文件协议或重写渲染引擎。

补充：模板制作在发布后也维持输入锁，重开项目恢复模板任务观测；终态才解除，状态未知不开放重复提交。模板与普通渲染均读取原有冻结任务，恢复不等于重新创建任务。

最终运行证据见 [稳定化验收记录](OPENMONTAGE-STABILITY-ACCEPTANCE-20260923.md)。
