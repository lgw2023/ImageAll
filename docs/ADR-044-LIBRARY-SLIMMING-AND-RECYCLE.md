# ADR-044：图库瘦身（相同/相似聚类）与受限原图回收

> 状态：已决定并实施（2026-07-27；2026-07-30 高危回收契约修订；2026-08-03 快速清理修订，项目所有者对话批准）
> 取代：`ARCHITECTURE.md` §3.2「不修改、移动或删除来源中的原图」与「不在 MVP 中自动合并或删除重复图片」中与本能力冲突的部分；其余原图只读原则仍有效  
> 相关：`docs/LIBRARY-SLIMMING-SPEC.md`（产品与实施契约）  
> 角色边界：本文锁定产品/架构决策；本轮可执行实现依据临时 Codex 实施授权交付

## 背景

用户需要「图库瘦身」：找出批次相同或高度相似的照片，对比后决定保留/删除。相同包含拷贝与转码后像素几乎一致但文件表象不同的情况；相似包含同场景、同地点或连拍产生的真实不同照片。自 2026-08-03 起，文件夹资产以“快速释放来源磁盘空间”为默认主操作，另保留 ImageAll 30 天可恢复回收作为次级选项；Apple Photos 资产始终进入系统「最近删除」，恢复、保留期限与永久删除遵循 macOS「照片」App 的规则。

既有 MVP 将「原图只读 / 不删不移」列为非目标。本 ADR 在**明确用户主动确认**的前提下，批准一条受限写入路径，而不是全面取消只读原则。

已批准的所有者选择（2026-07-27 至 2026-08-03）：

## 决策

### 1. 能力成为正式产品阶段，不是后台静默去重

- 侧栏「图库」区增加一级入口「图库瘦身」。
- 用户可基于标签/筛选范围，或基于选定的 1..N 张种子照片，发起相同/相似检索。
- 结果按簇聚类、簇内按相似度排序；用户自由多选、大图对比后确认处置。
- **禁止**自动合并或自动删除。普通可恢复回收单张或 5 张以内可遵循用户明确启用的「永不再确认」；
  普通批量超过 5 张、一键清理完全相同及任何快速/永久删除必须每次显式确认。
- 用户可主动点击「一键清理完全相同」，对当前分析结果中的全部 `byteIdentical` 分组生成一次批量
  预览；该入口不处理 `perceptualDuplicate` 或 `nearDuplicateScene`。每组严格保留一张，待删顺序为：
  Apple Photos 优先，其次按来源 `displayName` 的用户可见字符数从长到短；长度相同只以显示名、
  source UUID、asset UUID 的稳定降序打破平局，从而保留稳定升序的最后一张，不引入画质等未批准规则。
- 确认页必须用本次运行时计划中实际选出的 asset ID 显示核验、保留、待删、分组、Photos/文件夹
  待删与跳过数量，并提供去留比例、完全相同组规模和待清理来源图表；安全跳过组不进入处置统计。
  计划同时冻结每个成员的 source identity/kind、当前 locator、`content_revision` 及经原始字节验证的
  SHA-256。执行前重新读取当前 asset/source/locator/revision/摘要来源与完整组成员，任何差异都停止
  而非沿用过期预览。批量中的全部 Photos 资产合并为一次公开 PhotoKit change request，并要求
  PhotoKit fetch 集合与请求集合精确相等；系统确认仍不可绕过。文件夹资产继续逐项遵循 quarantine
  失败不丢源契约。
- 一键清理在任何物理 mutation 前预检全部待删文件夹来源与 Photos 的写入授权；任一项缺失或失效
  时整批不开始。补授权重试仍调用一键计划校验入口，不能降级为普通回收调用。
- 批量动作结束后执行独立结果核验。核验从 catalog 与回收记录重新读取本次涉及资产的当前状态；
  只有某组当前恰好剩余计划 survivor，且所有计划删除成员均已完成回收，才把该 survivor 计入
  “已确认保留的非冗余照片”。结果弹窗以“已完成去重 / 目标组数”为主口径，明确区分运行时计划的
  “目标保留数”和删除后实读的“当前实际可用数”；顶部动作摘要使用相同核验口径。部分失败或读取
  异常必须如实展示，禁止用删除前预览值或“每组一张”推算删除后实际结果。
- 用户确认批量清理后，从执行前方案复核直到删除后核验结束，任务提升为前台独占操作。App 用覆盖
  整个工作区的进度层锁定侧栏、工具栏、图库瘦身内容和导航，防止筛选、刷新、分析、回收、恢复等
  操作与删除交叉。逐项文件回收和合并 Photos 请求只报告实际到达终态的资产计数；方案复核、等待
  系统授权、刷新状态和结果核验显示明确阶段。为避免留下难以解释的半完成状态，不提供中途取消；
  只有核验成功、核验失败或清理明确终止后才解除锁定并展示结果。正在分析、刷新来源或初始化来源
  索引时不得启动一键清理，须先等待对应任务完成或暂停。

### 2. 双轨回收（文件夹 ≠ Photos）

所有者同时批准「含 Photos」与「应用 quarantine」。二者物理上不能共用同一文件移动语义，因此拆成双轨，统一呈现在 ImageAll 回收站 UI：

| 来源 | 主要处置 | 恢复 | 到期永久删除 | 倒计时真相源 |
|---|---|---|---|---|
| 文件夹 `file` locator | **主操作：**验证当前文件身份后直接 `unlink` 并同步源目录，立即让来源卷空间变为可回收，ImageAll 不可恢复；**次级操作：**同卷 `rename` 或跨卷 copy+verified-delete 进入 App quarantine | 仅次级可恢复回收可从 quarantine 移回原相对路径 | 主操作在源删除后后台清理 App 像素缓存；次级操作按倒计时删除 quarantine | 主操作无恢复倒计时；次级操作使用 DB `purge_after_ms` |
| Apple Photos `photos` locator | **仅**经公开 PhotoKit 删除 API，进入系统「最近删除」；**禁止**导出副本进 App quarantine，禁止直写 `.photoslibrary` | 用户在 macOS「照片」App 恢复；ImageAll 只在资产重新公开可见后收敛本地状态 | 由 macOS「照片」App 的保留策略与用户操作管理；ImageAll 不提供永久删除入口，也不调用未公开的「最近删除」访问能力 | Photos 系统策略是真相源；ImageAll 的 `purge_after_ms` 只表示何时清理本地回收记录，不代表系统永久删除时间 |

补充约束：

- “快速清理”不得伪装成“移入回收站”：按钮、确认和结果必须明确写出文件夹原文件将永久删除、
  ImageAll 无法恢复。每次都强制确认，不读取或写入“永不再确认”偏好。删除成功后文件系统块通常立即
  变为可回收；打开文件描述符、APFS 快照或卷实现仍可能延迟物理容量统计刷新，App 不承诺绕过这些系统语义。
- 快速删除先以目录 FD / no-follow 打开常规文件并核对 size、mtime、路径 inode 与 catalog 身份。
  有稳定 resource ID 时不读取整份文件；没有 resource ID 时必须以已登记 SHA-256 完整校验，二者皆无则
  fail closed。随后 `unlink` 并同步源父目录；目录同步失败保留 `pending` 意图，由恢复器按源路径是否仍存在
  收敛，禁止误报可恢复。
- 源字节删除和 catalog 隐藏是前台完成边界；缩略图、预览和其他 App 自有像素缓存转入持久 `purging`
  状态，由现有 purge Job 或启动恢复继续清理，不延长按钮忙碌时间。此后台清理不提供原图恢复能力。

- 文件夹来源首次导入的同一次系统目录选择同时生成独立的只读 catalog bookmark 与 write-capable
  mutation bookmark，并与来源和首次扫描 Job 原子落库。App 知道来源身份，回收站、恢复或其他模块
  不得再次要求用户寻找目录。旧版本来源若缺少 mutation bookmark，只允许一次明确的兼容升级，
  且系统窗口必须直接定位到该照片所属的已登记来源根目录。已经保存 mutation bookmark 但解析或
  启动失败时，不得在删除动作中再次弹出 Finder；应报告授权失效，并只允许用户从来源菜单显式执行
  「更新回收权限…」。Photos soft-delete 失败或有限图库访问不足时不得套用该文案；应提示系统
  「最近删除」路径，并允许从 active Photos 来源菜单执行「请求照片写入权限…」。
- 回收站 UI 对每条记录显示独立时间提示；文件夹条目显示永久删除倒计时，Photos 条目显示 ImageAll 本地记录清理时间。两类条目可混排，但必须显示来源徽章。
- Photos 进入系统「最近删除」后，PhotoKit 可能不再返回画面，catalog 对账也可能推进
  `content_revision`。仅当资产仍有活动的 Photos `recycle_entry` 时，回收站允许读取删除前已登记、
  完整性校验通过的最近一版 App 缩略图；该例外只用于展示 App 已拥有的缓存，不访问系统「最近删除」、
  不重新下载、不跨资产复用。普通缺失资产没有活动回收记录时仍严格按当前 revision 查找。
- 来源重扫不得在 size / mtime 未变化时清空已完成 SHA-256；历史竞态已清空文件指纹 SHA 时，
  回收校验可复用相同 `content_revision` 的相似分析内容 SHA，禁止跨 revision 复用。
- 回收动作结果使用独立状态面展示，不能被仍在运行的分析进度遮盖或覆盖。
- 普通打开、切换或刷新回收站时先直接读取并展示 ImageAll DB 记录，不得同步等待 Photos 对账。
  前台维护仍负责收敛 Photos 回收状态，但必须把同轮全部 local identifier 合并为一次 PhotoKit
  批量可见性查询，禁止逐条 `PHAsset.fetchAssets`。移动结果形成后立即结束普通回收按钮的忙碌状态，
  后续列表刷新不得继续显示「正在移入回收站」。
- 移入回收站确认只允许提交一次 mutation；结果分组与回收站大列表首屏各最多构造 100 项，用户通过
  「再显示」按 100 项继续加载，避免数千条 SwiftUI / Accessibility 节点阻塞交互。
- 回收确认提交后，所选卡片须在下一次主线程刷新时从活动簇中乐观隐藏，不能等待跨卷 copy、hash
  或目录刷盘结束才反馈。独立状态条持续显示「等待后台磁盘任务、准备、复制、同步目标、校验目标、
  复核来源、移除来源、同步源目录、等待 PhotoKit、完成」以及文件复制字节。该状态只表示操作已接收，
  不得提前声称成功；失败项按操作前的簇、选择和锚点自动放回，成功项才进入持久隐藏。
- 用户发起文件夹回收时，写者优先静默闸门先阻止新的后台来源读取，再等待已经进入的单项读取完成；
  目录重扫、Photos 对账、缩略图生成、Feature Print / DINOv2 输入读取均在有界安全边界登记后台读取。
  显式与空闲缩略图预生成还要取消并等待任务实际退出，结束后才恢复。跨卷 copy 不再在 copy 前单独重复读取整份来源：先核对
  size / mtime / resource ID，copy 并刷盘后校验目标 SHA-256，再以仍打开且加锁的来源执行最终 SHA-256
  复核和路径身份复核后 unlink；若 catalog 已有摘要，目标和最终来源都必须与其一致。这样减少一次完整
  来源读取，但不减少目标文件/目录同步、最终来源复核或失败保源保证。性能日志只记录阶段名、聚合数量
  与耗时，不记录路径、文件名、asset ID 或 Photos local identifier。
- 同卷 quarantine 仍是待单独授权的后续决策：必须为具体卷上的 ImageAll 回收根取得独立持久写入
  bookmark，并扩展回收记录以保存回收根身份和卷断开状态。现有来源 mutation bookmark、既往单张移动
  授权和本 ADR 都不授权在 `/Volumes/HDD2` 创建回收目录；获批前生产继续使用 App Support quarantine。
- 文件夹身份校验返回 `sourceChanged` 时，结果必须明确说明来源已变化，并引导用户执行
  「刷新照片来源 → 等待完成 → 重新分析 → 重试」；不得折叠成通用失败或错误的授权提示。
- Workspace 首次加载不得同步等待 PhotoKit 变化观察者注册；观察者注册必须在独立的 utility 任务中
  启动，即使 Photos XPC 暂时阻塞，主界面和首屏 catalog 仍须可交互。
- Production 启动恢复文件夹监听时只恢复 FSEvents 观察，不为每个 active 来源自动入队全量 reconcile；
  既有持久任务仍按恢复契约继续，之后只有真实文件事件或用户显式「刷新来源」才新建 reconcile。
- 停留在图库瘦身工作区时，文件系统与 PhotoKit 变化仍可进入既有合并队列，但不得自动启动 catalog
  对账，也不在全局工具栏显示来源扫描进度。一次或多次成功回收只记录一个待刷新请求；用户离开工作区
  后，对实际受影响来源合并启动一次对账。工作区提供「刷新来源」按钮，作为用户明确要求立即对账的
  唯一例外；手动刷新必须严格使用工作台当前选中的 active 来源，未选择来源时禁用，作业执行器也只
  能领取这些来源的 reconcile，不能因存在其他历史待处理任务而扩大范围。手动刷新成功入队后不得在
  离开时为同一批回收再次启动扫描。
- Photos 路径需要 `.readWrite` 授权；授权不足时该资产不可执行移入回收站，只能只读出现在相似结果中并提示原因。
- 普通可恢复回收 1–5 张可使用持久化「永不再确认」；超过 5 张时每次显示数量确认并隐藏该选项。
  一键清理完全相同不读取或写入该偏好，每次独立确认。文件夹快速清理和回收站内立即永久删除始终显式确认；
  Photos 条目不显示 ImageAll「立即永久删除」按钮。
- PhotoKit mutation 返回后，如果目标资产在 2 分钟可见性收敛宽限内仍可查询，回收记录保持
  `pending`，不重复提交也不误报失败；不可见后完成，超出宽限仍可见才失败。
- 文件夹 quarantine 恢复前必须按回收记录验证常规文件身份、大小、mtime 和已登记 SHA-256；
  同卷移入/恢复 rename 成功后刷新源与目标父目录，篡改或冲突都 fail closed 并保留 quarantine。
  namespace mutation 已提交但目录刷盘失败时保留 `pending` / `restoring` / `purging` 意图并由恢复器
  按两侧存在性收敛；跨卷源已 unlink 后绝不清理唯一的已验证目标。

### 3. 「相同」与「相似」分层，不可混档

1. **相同 · 字节**：文件夹与 Photos 的原始编码字节统一写入
   `asset_similarity_fingerprint.content_sha256`，并以
   `content_digest_origin = verifiedOriginalBytes` 明确证明来源；真正字节一致优先成簇。
   预览、缩略图或视觉缩放派生内容只能标记为 `visualDerivative`，不得产出删除级
   `byteIdentical`；升级时无法证明来源的旧摘要按未验证/视觉派生处理。
2. **相同 · 感知近重复**：dHash v2 只负责候选召回，最终还必须通过宽高比约束与归一化 `16 × 16 RGB` 像素签名校验；采用 complete-link 保守成簇，避免仅凭连通链把并不相同的两端误合并。产品文案可用「相同」，内部类型仍区分 `byteIdentical` / `perceptualDuplicate`。
3. **相似**：Feature Print 余弦距离做库级粗筛与候选召回；DINOv2-small embedding 对候选做精排与最终簇边界。最终簇采用双特征门槛的 complete-link 条件，种子模式中同一候选全局只能归属一个簇，禁止共享邻居重复认领或连通链误合并。默认模式下，单桶 ≤ 512 张时保留穷举召回；大桶（包括拍摄时间缺失桶）使用确定性 24-bit LSH、Hamming 邻域 ≤ 1，并将每资产精确 L2 候选上限固定为 64。用户可显式选择「全部候选」，此时必须执行真实穷举并绕过大桶 64 候选上限及种子来源索引裁剪，不能只改变 UI 文案。L2 可选择 `0` 或「不限」，DINOv2 下限可选择 `1.00` 或「不限制」；分桶采用「始终 / 自动阈值 / 从不」三态。各开关只关闭自己对应的门槛，不隐式关闭其他粗筛或精排阶段。LSH 不直接产出最终相似结论。策略身份升级为 `near-dup-scene-v3`；数值和模式共同进入结果身份，禁止魔法数或虚假「无限」语义。

Photos「相同」检测需要原始编码内容。若资产只有 iCloud 副本，PhotoKit Adapter 在该分析任务内以
`.original`、高质量且允许网络访问的方式隐式获取；成功结果原子保存到 App Application Support 的
`Photos Originals/v1`。该存储不走 512 MiB 派生预览 LRU，也不自动淘汰；索引记录绑定
`asset_id + content_revision + photos_local_identifier + SHA-256 + byte_size`，任一身份变化或内容校验失败
即拒绝复用。这个例外只授权 App 获取并长期保存一份原始图像，不授权写回 Photos、导入副本或绕过
`docs/LOCAL-TEST-DATA-SAFETY.md` 的真实图库 smoke 授权门。

长期原图默认无限期保留，不设 TTL、容量驱逐或后台自动清理。存储面板分别展示长期原图的数量与占用，
并提供一次性「清除全部长期原图」：执行前必须二次确认；有 `pending` / `running` 瘦身分析时拒绝执行；
只删除 Application Support 中经索引登记、路径与对象类型复核通过的副本及对应索引，不删除 Photos
资产、人工标签、指纹或已有分析结果。清理后未来相同检测可以重新经 PhotoKit 下载。

### 4. 原图只读原则改为「默认只读 + 瘦身例外」

修订原则表述：

- 索引、分析、导出、缓存、训练、建议等路径 **仍然禁止** 修改/移动/删除原图。
- **唯一**允许触碰原图的产品路径是「图库瘦身 → 用户确认」后，文件夹资产进入 ImageAll 回收/清理流程，或 Photos 资产进入系统「最近删除」。
- 自动化测试与开发工具 **不得** 对 `docs/LOCAL-TEST-DATA-SAFETY.md` 保护路径行使该例外；真实受保护照片的删除验证需要项目所有者针对具体操作的新授权。合成 fixture / 可丢弃测试库是唯一默认验证面。

### 5. 数据与任务边界

- 实际 schema 已推进到 migration **v030**：在既有跨来源内容 SHA-256、`16 × 16 RGB` 校验签名、
  长期 Photos 原图索引、冻结成员集与持久结果表之上，为内容摘要新增原始字节/视觉派生/旧版未验证
  provenance；既有 migration 不改写。
- 长耗时：全库哈希补全、Feature Print/DINOv2 缺失补齐、大范围聚类、到期 purge，一律走可恢复 Job Queue。
- 瘦身分析入队与冻结资产宇宙在同一事务完成；指纹按单资产、向量按 16 个资产形成安全 checkpoint。
  用户暂停或 App 退出后从已提交边界继续，启动时自动接管未完成任务；有待分析成员时最多自动再补全
  3 轮，最终结果与 Job 完成状态原子提交。
- 聚类开始前先提交 `.clustering` checkpoint；长聚类通过进度心跳续租。运行期只把租约已过期的
  `running` 任务转入暂停/重试/终止路径，仍有效的 worker 不受影响，避免界面长期显示无执行者的
  “分析中”状态。
- 派生缓存、feature、embedding、标签决定在资产进入回收站后保持可追溯策略：软删除期间保留可恢复所需最小元数据；文件夹永久删除或 Photos 本地记录到期收敛后，级联清理可重建派生物与回收记录。Photos 的本地收敛不声明系统资产已被永久删除。

## 后果

- `ARCHITECTURE.md` 非目标与原则需同步改为「默认只读 + ADR-044 例外」。
- Photos 删除从「永不调用 mutation API」变为「仅瘦身回收站路径可调用公开 PhotoKit 软删除」，需更新 Photos 适配层审计与测试，证明无其它写入路径、无私有「最近删除」探测、无 ImageAll 永久删除调用。
- 跨卷 quarantine 可能短暂双份磁盘占用；UI/任务需显示进度与失败可重试。
- 相似检索依赖 embedding 覆盖率；覆盖不足时工作区必须展示「待计算」而不是空结果伪装为无相似。
- 长期 Photos 原图会占用 Application Support 空间；这是所有者选择的产品数据，不按派生缓存策略自动清理，
  由用户在存储面板查看并显式清除全部；清理只回收 App 副本和索引，未来分析按需重新下载。

## 反例

- 不得在 Review、训练、reconcile、缓存维护中顺带删除原图。
- 不得把 Photos 原图 copy 进 App quarantine 再删 Photos「冒充」统一物理回收。
- 不得对受保护真实路径跑删除/移动自动化测试。
- 不得自动清空相似簇；普通 >5 张、一键清理完全相同或永久删除不得使用「永不再确认」绕过确认。
- 不得把预览、缩略图或其它视觉派生内容的 SHA-256 当作删除级字节相同证明。
- 不得对 PhotoKit 部分命中集合提交删除，也不得让过期 locator/revision/摘要计划继续执行。
- 不得用未版本化的阈值或未缓存身份的 embedding 做精排结果持久化。
