# ADR-111：分离 USB 接收进度恢复与内容完整性确认

状态：2026-10-21 接受。项目所有者确认旧 ADR 可以修订。本条替代 ADR-110 中要求每次冷恢复返回断点前重新读取所有已提交字节的规定；封存与发布的完整性门不变。

## 问题与取舍

2,889 项、4 GiB 非稀疏合成任务中，原首次有效进展 10.308845 秒，begin 占 10.032580 秒。已提交前缀的实际磁盘读取是主要成本。文件大小、时间戳、APFS 内容版本标识都不能替代对当前实际字节的密码学验证。不能把缓存摘要称为新的内容校验。

## 决定

- 接收进度恢复只确认任务归属、持久化接收账本、凭据与账本的一致性、存储对象身份和长度。恢复后显示“接收进度已恢复，完整性待核验”。≤5 秒门针对这一阶段；不与旧的“已重新核对字节”指标混算。
- 新日志绑定接收根、任务目录、package 目录和每个已提交文件的设备号、inode、创建时间。存储对象替换（包括相同字节替换）拒绝恢复；挂载身份改变也保守拒绝，不自动重新授权。
- 凭据绑定任务、已配对设备、安装身份、路径、块账本及此前资源校验结果。旧凭据与当前账本不一致时拒绝。摘要是接收端日志一致性检查，不是抵御拥有日志写权限者的认证或完整日志回滚保护。
- 已写入但未记账的尾部仍按持久化偏移截断；不把尾部差异当成对已提交前缀的重新校验。
- 旧日志缺少对象绑定时先走原有全量块 SHA 校验，再登记绑定；第一次迁移不承诺 5 秒。损坏的旧日志不能通过迁移获取快速恢复资格。
- 同大小内容损坏可能在接收进度恢复阶段尚未被发现，但必须在封存前读取实际全部字节时拒绝；Mac 导入/发布继续独立验证。不得据恢复凭据声称已封存、已导入、可浏览或允许删除源数据。
- 保留严格恢复策略供原调用方和对照测试使用。Mac USB 接收路径显式启用接收进度策略。内存上限、块大小、真实数据边界均不变。

## 验收

先证明新对象替换、旧凭据拒绝；证明同大小损坏不能封存；保留旧日志严格校验回归。再在同一 SSD1、真实 USB、2,889 项、4 GiB 非稀疏资源及 512 MiB 保护下测量新日志的双方冷恢复、剩余 8 MiB 续传、最终验证与状态刷新。日志准备/迁移耗时独立记录，不能藏入计时之外后声称旧日志也达标。

现有 Mac 数据与编辑保持保护；当前范围以 USB-IMPORT-NEXT-PHASE.md 顶部的用户决定为准。生产 UI 与合成探针都必须使用阶段准确的文案。
