# P6 照片与视频片段混合故事

状态：决策已记录，实施待开始。2026-09-28，仅 Mac。

## 差异与影响

当前 TimeStoryCandidate/Shot 不记录视频片段，TimeStoryMediaLoading 只返回图像；StoryRenderPackageExporter 为每个素材生成 JPEG。OpenMontage 自动创作入口过滤 image/ 素材且限定旧 schema。只扩大候选查询会让视频在导出时退化成单帧，不能满足目标。现有故事 UI、渲染包和 OpenMontage 存在并行未提交修改，实施须保留这些内容并按本任务差异提交。

## 决策

1. 先完成用户明确选片的确定性闭环，再扩展自动选材。候选记录媒体类型和可用时长；旧项目缺字段解释为照片。不能推断已有旧照片镜头为视频。
2. 视频镜头显式保存源资产、contentRevision、入点/出点（整数毫秒、半开区间）和原声音量。必须满足 0 <= 入点 < 出点 <= 经资源验证的时长。视频镜头展示时长由片段长度确定，不允许另一独立 duration 与范围冲突；同一资产可有多个不同片段。
3. 原声默认保留，音量范围0...1，0表示静音；配乐独立控制。只做受控增益叠加，不做专业混音或自动响度承诺。无音轨的视频合法；不可读音轨不得悄悄变成成功的保留原声结果。
4. 本地资源按现有授权取得，在受控生命周期内冻结至任务独立目录。冻结资源记录内容修订和文件摘要，前后复核来源；云端不可用时制作前明确拒绝，不自动下载。源文件保持只读。
5. 渲染包区分照片与视频，视频资源必须保留实际运动，镜头带时间范围和音量。输出沿用故事指定画幅和30fps时间基准，应用 preferredTransform 处理方向，按明确 fit 规则缩放；边界按输出帧网格归一并验证至少一帧。渲染和音频使用同一时间范围。
6. 混合包启用明确的新 schema/能力门禁，旧照片包与已完成任务继续可读；不让旧运行时静默忽略视频字段。集成版本常量只改 integration-contract.json 并重新生成 Swift；同步 Schema、验证器和运行时覆盖层。禁止修改 Vendor/OpenMontage/Runtime 种子或安装缓存。
7. 首次最小验收以一张照片、两个不同片段和含可测音频的视频为输入，验证顺序、范围、运动差异、原声保留/静音/配乐增益、方向、输出时长和可解码性。零长度、越界、来源变化必须在发布前失败；旧照片路径保留回归。

## 交付门禁

本 ADR 不代表实现。必须完成 Mac 候选/预览/剪辑/顺序编辑、资源冻结、协议升级、实际混合渲染与历史结果恢复后才验收 P6。使用独立合成任务、直接 XCTest、免费本地确定性渲染，不调用付费模型。打包发布或手工替换遵守既有 release.py 门禁；普通 Xcode 构建不是发布证明。
