# ADR-059：大图库浏览热路径分层优化

- 状态：Accepted
- 日期：2026-08-16
- 范围：图库分页、排序查询、缩略图缓存、PhotoKit 请求与 SwiftUI 网格刷新
- 安全边界：不扩大来源访问或联网权限，不修改原照片，不恢复固定生产并发上限

## 背景

当图库达到数万项后，浏览延迟不再只来自单次缩略图生成。页尾才请求下一页会暴露查询等待；SQLite 可能选中
筛选索引后再对大量匹配行排序；快速滚动会重复解码相同缩略图、频繁写回磁盘缓存 LRU，并让每个可见单元格
响应工作区所有发布；PhotoKit 图片和悬停视频任务离开视口后也需要真正取消底层请求。

## 决策

1. 当任一可见单元格进入最后一个视口大小的已加载区间时启动下一页查询。继续使用既有游标、请求 ID 和
   `isLoadingMore` 去重，不改变页内结果或选择语义。
2. 三种网格排序分别固定使用与排序同向的 current-asset partial index，避免宽查询选择媒体类型索引后建立
   大型临时排序树。筛选、搜索和游标谓词保持原值。
3. 本地 PhotoKit 图片与视频请求都把 Swift Task 取消传递给 `PHImageManager.cancelImageRequest`；取消发生在
   request ID 安装前后的竞态都只完成一次 continuation。网络访问策略保持不变。
4. 派生图片命中仍校验 SHA-256、UTI、单帧和像素尺寸，但不在同一次命中内重复计算 SHA-256；同一缓存项的
   LRU 写回最多每分钟一次，降低快速滚动造成的 SQLite 写放大。
5. 压缩缩略图内存缓存按真实最近读取顺序淘汰。已解码 `NSImage` 另存于可由系统内存压力回收的 `NSCache`，
   cost budget 为物理内存的 1/128；key 绑定 Asset、缓存版本、比例模式和原比例缓存 generation。
6. 网格单元格使用只包含该单元格可见输入的 Equatable 快照，不再各自订阅整个工作区模型。收藏、选择、悬停
   播放、云端预览、缩略图版本或比例变化仍会精确刷新相应单元格。

## 验收标准

1. 三种排序的 SQL 明确走对应索引，全部目录查询回归及 1 万、10 万、100 万合成资产门继续通过。
2. 下一页在最后一个视口区间出现时开始加载，而非等待最后一个单元格出现。
3. PhotoKit 取消在“先安装 request ID”和“先收到任务取消”两种顺序下均只取消、完成一次。
4. 一分钟内重复暖命中不改写 `last_accessed_at_ms`；达到一分钟的既有触碰语义和缓存篡改重建仍通过。
5. 最近读取的压缩缩略图不被新写入优先淘汰；已解码图只在 key 完全匹配时复用。
6. 验证只使用临时数据库、合成资产与临时缓存，不启动 App，不访问受保护真实照片。

## 后果与边界

本决策降低的是目录查询、滚动重挂载和取消滞后的结构性成本。合成规模测试证明查询正确性与既有性能包络，
不等同于真实 Photos 图库的端到端帧率或解码吞吐证明。真实图库验证仍需项目所有者明确授权，并应只记录聚合
耗时、卡顿和命中率，不导出照片内容、路径或个人元数据。
