# ADR-077：待审核工作台的可见边界与滚动条同步

- 日期：2026-09-17
- 状态：Accepted；已完成日常 App 实机回归
- 范围：macOS 原生待审核建议总览

## 问题与证据

用户截图中，右侧滚动条穿过最后一列卡片。日常 App 的检查器展开、收起及后续滚动能够触发同类偏移；重启后初次显示正常不足以证明问题解决。

布局中同时存在 NavigationSplitView、检查器、生成中心分栏和 SwiftUI ScrollView。内容区域、继承的安全边距、AppKit 指示条 inset 在切换期间可能采用不同边界。单纯忽略安全边距会让内容进入检查器；重复扣除检查器宽度又会留下空白。

修复候选的半屏验证还发现了最小宽度反馈：实际窗口为 941 点宽，滚动视图仍可达到 966 点；生成中心展开时整个工作区出现横向裁切。因此最终方案同时约束内容宽度和指示条可见边界。

以上证据来自日常 App 界面及仅包含几何值的临时诊断，不涉及照片文件内容。临时诊断写入最终版本前移除。

## 决定

1. 总览以父容器实际提供的宽高为布局边界，避免子视图的固有宽度反向撑大整个工作区。
2. 生成中心与建议列表采用明确分配宽度的 SwiftUI 布局，移除这一层嵌套 HSplitView。保留 248～320 点的宽度调节和收起/展开操作；分隔线支持拖动及无障碍增减操作。
3. 优先保证列表至少 380 点宽。横向空间不足时，生成中心移至列表上方，占用不超过 220 点或可用高度的 40%，其内部仍可滚动。
4. 卡片最小宽度随列表可用宽度收缩，并计入内容留白和传统滚动条占位。正常宽窗口仍使用既有 310～440 点卡片网格。
5. 局部 NSViewRepresentable 观察所属 NSScrollView 的公开 scrollerInsets，并在布局/窗口尺寸变化后同步右侧边距。目标边界同时考虑内容右缘、传统滚动条预留宽度、原生 visibleRect 和窗口内容边界。
6. 同步采用主线程异步合并与半点容差；退出页面时解除观察。只调整指示条边距，不设置文档滚动偏移、不修改建议或照片数据。

## 验证要求

使用用户日常 App 和真实待审核页面完成以下回归，不以合成页面截图代替：

- 检查器展开时，列表和滚动条停在检查器左侧；收起后恢复到工作区右缘。
- 收起检查器后继续滚动至中部/底部，不残留动画中间位置。
- 生成中心展开、收起及宽度调节后，卡片和滚动条使用一致边界。
- 宽窗口、窄窗口及恢复宽窗口时不横向裁切工作区；空间不足时生成中心转为上下布局。
- 构建、代码格式检查、App 签名校验通过；日常路径中的二进制与最终构建一致。

保留修改前 App 备份。测试不触发建议生成、训练、审核决定或照片删除。
