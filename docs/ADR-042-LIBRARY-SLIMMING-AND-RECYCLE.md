# ADR-042：图库瘦身（相同/相似聚类）与受限原图回收

> 状态：已决定（2026-07-27，项目所有者对话批准）  
> 取代：`ARCHITECTURE.md` §3.2「不修改、移动或删除来源中的原图」与「不在 MVP 中自动合并或删除重复图片」中与本能力冲突的部分；其余原图只读原则仍有效  
> 相关：`docs/LIBRARY-SLIMMING-SPEC.md`（产品与实施契约）  
> 角色边界：本文锁定产品/架构决策；可执行实现须另发切片交接单

## 背景

用户需要「图库瘦身」：找出批次相同或高度相似的照片，对比后决定保留/删除。相同包含拷贝与转码后像素几乎一致但文件表象不同的情况；相似包含同场景、同地点或连拍产生的真实不同照片。删除默认进入可恢复回收站，30 天后永久删除，并显示独立倒计时。

既有 MVP 将「原图只读 / 不删不移」列为非目标。本 ADR 在**明确用户主动确认**的前提下，批准一条受限写入路径，而不是全面取消只读原则。

已批准的所有者选择（2026-07-27）：

| ID | 选择 |
|---|---|
| LS-P1 | 覆盖文件夹来源 **与** Apple Photos 来源 |
| LS-P2 | 应用专属 quarantine 目录 + DB 倒计时（文件夹物理回收） |
| LS-P3 | 「相同」= SHA-256 **与** 感知近重复 |
| LS-P4 | 「相似」= Feature Print 粗筛 + DINOv2 精排 |
| LS-P5 | 授权对用户主动选择的**文件夹资产**执行移入回收站 / 到期永久删除 |

## 决策

### 1. 能力成为正式产品阶段，不是后台静默去重

- 侧栏「图库」区增加一级入口「图库瘦身」。
- 用户可基于标签/筛选范围，或基于选定的 1..N 张种子照片，发起相同/相似检索。
- 结果按簇聚类、簇内按相似度排序；用户自由多选、大图对比后确认处置。
- **禁止**自动合并、自动删除或无确认批处理销毁原图。

### 2. 双轨回收（文件夹 ≠ Photos）

所有者同时批准「含 Photos」与「应用 quarantine」。二者物理上不能共用同一文件移动语义，因此拆成双轨，统一呈现在 ImageAll 回收站 UI：

| 来源 | 软删除（默认） | 恢复 | 到期永久删除 | 倒计时真相源 |
|---|---|---|---|---|
| 文件夹 `file` locator | 同卷 `rename` 或跨卷 copy+verified-delete 进入 App quarantine；catalog 标记 `recycled` | 从 quarantine 移回原相对路径（冲突则失败并保留 quarantine） | 删除 quarantine 对象 + 清理 catalog / 派生缓存 | ImageAll DB `purge_after_ms` |
| Apple Photos `photos` locator | **仅**经 PhotoKit 删除 API，进入系统「最近删除」；**禁止**导出副本进 App quarantine，禁止直写 `.photoslibrary` | **仅**经 PhotoKit 恢复（若系统仍保留）；失败则如实报告 | 经 PhotoKit 从「最近删除」永久删除，或与系统 30 天策略对齐后收敛 catalog | ImageAll 记录 `trashed_at` 起算 30 天，并与 Photos 实际状态对账；冲突时以 Photos 为准并刷新 UI |

补充约束：

- 回收站 UI 对每条记录显示独立倒计时；文件夹与 Photos 条目可混排，但必须显示来源徽章。
- Photos 路径需要 `.readWrite` 授权；授权不足时该资产不可执行移入回收站，只能只读出现在相似结果中并提示原因。
- 任何回收/永久删除必须有显式用户确认（单次或带数量摘要的批量确认）；确认文案必须区分「进回收站」与「永久删除」。

### 3. 「相同」与「相似」分层，不可混档

1. **相同 · 字节**：填充并使用 `file_fingerprint.sha256`（及未来等价内容哈希）；真正字节一致优先成簇。  
2. **相同 · 感知近重复**：在哈希未命中时，用感知哈希 / 像素级近似度量把转码、重封装、轻微重采样导致的近全等归入「相同」档（产品文案可用「相同」；内部类型区分 `byteIdentical` / `perceptualDuplicate`）。  
3. **相似**：Feature Print 余弦距离做库级粗筛与候选召回；DINOv2-small embedding 对候选做精排与最终簇边界。阈值版本化，写入配置/DB，禁止魔法数散落。

### 4. 原图只读原则改为「默认只读 + 瘦身例外」

修订原则表述：

- 索引、分析、导出、缓存、训练、建议等路径 **仍然禁止** 修改/移动/删除原图。
- **唯一**允许触碰原图的产品路径是「图库瘦身 → 用户确认 → 回收站 / 到期清理 / 用户立即永久删除」。
- 自动化测试与开发工具 **不得** 对 `docs/LOCAL-TEST-DATA-SAFETY.md` 保护路径行使该例外；真实受保护照片的删除验证需要项目所有者针对具体操作的新授权。合成 fixture / 可丢弃测试库是唯一默认验证面。

### 5. 数据与任务边界

- 新增 migration（建议 `V005`）承载：相似度版本、近重复索引、回收站条目、purge job 状态；不改写已批准的 V001–V004。
- 长耗时：全库哈希补全、Feature Print/DINOv2 缺失补齐、大范围聚类、到期 purge，一律走可恢复 Job Queue。
- 派生缓存、feature、embedding、标签决定在资产进入回收站后保持可追溯策略：软删除期间保留可恢复所需最小元数据；永久删除后级联清理可重建派生物与回收记录。

## 后果

- `ARCHITECTURE.md` 非目标与原则需同步改为「默认只读 + ADR-042 例外」。
- Photos 删除从「永不调用 mutation API」变为「仅瘦身回收站路径可调用」，需更新 Photos 适配层审计与测试证明无其它写入路径。
- 跨卷 quarantine 可能短暂双份磁盘占用；UI/任务需显示进度与失败可重试。
- 相似检索依赖 embedding 覆盖率；覆盖不足时工作区必须展示「待计算」而不是空结果伪装为无相似。

## 反例

- 不得在 Review、训练、reconcile、缓存维护中顺带删除原图。
- 不得把 Photos 原图 copy 进 App quarantine 再删 Photos「冒充」统一物理回收。
- 不得对受保护真实路径跑删除/移动自动化测试。
- 不得无确认自动清空相似簇。
- 不得用未版本化的阈值或未缓存身份的 embedding 做精排结果持久化。
