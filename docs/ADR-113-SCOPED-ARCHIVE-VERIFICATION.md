# ADR-113：复用同次审计的前置校验，保留提交前全量复核

日期：2026-10-22。状态：已实施，协议、事务与同条件实机验收通过。范围：P3 最小切片。

## 问题与边界

当前导入与发布多次调用完整资源校验。调用次数不能代替耗时归因，本轮先用独立、
有界、默认关闭的 Debug 计时记录每次 verify 的资源字节、读取及 SHA 耗时、复制耗时，
并分别记录导入、发布阶段壁钟。Mac 本地阶段与真实 USB 计时分开报告。

## 最小候选方案

先只处理发布审计内部的重复前置校验：auditImportedArchive 已通过 readVerifiedHeader
完整校验，随后 visitVerifiedRecords 又重复做同一前置校验。允许后者接收本次的内存
校验结果，省掉这一遍；逐条审计后的完整实际字节 SHA 复核仍保留，成功返回后才能发布。
导入的独立目标副本、封存校验与跨重启边界继续各自完整验证，不把不同对象的证据混用。

复用结果必须绑定规范化根路径、根/资源目录、manifest、每个资源的存储对象和文件版本；
只能由实际 verify 产生，不能序列化、从旧日志恢复或通过 public 初始化器构造。进入访问
和最终返回前都核对绑定；逐条读取的 manifest SHA 必须等于预期。完整字节复核不能被
stat、mtime、ctime 或对象身份替代；它们只负责拒绝换对象和过期结果。

这一步将发布审计从三遍完整资源读取减至两遍，不声称整个迁移只验证一次。保留原有
不提供先前结果的调用方式。不改数据库 schema、接收 journal、真实数据、内存保护阈值。

## 验收

- RED→GREEN：同字节新对象在访问过程中替换必须拒绝；发布主路径恰好两次完整读取。
- 复用结果的旧版本、同大小损坏、截断、替换、跨根误用拒绝；最终失败不得部分发布。
- 发布重入不创建重复来源/资产，不重写已存在的 Mac 编辑；现有原子性/恢复回归保留。
- 同 iPhone/SSD1、2,889 项、4 GiB 非稀疏大资源、剩余8 MiB真实 USB复测，计时外的种子
  准备/旧日志升级独立报告；512 MiB 合成和1 GiB日常保护不变。

现行任务范围以 USB-IMPORT-NEXT-PHASE.md 顶部用户决定为准。


## 计时依据与实施决定

2026-10-22 Mac 隔离4 GiB阶段基线：导入33.093秒，5遍完整资源读取；发布23.478秒，
3遍完整资源读取。每遍资源4456558592字节，verify约6.29–6.65秒，其中读取与SHA
约6.01–6.27秒；复制0.210秒。仅为本地阶段测量，不冒充USB计时。

据此采用上述最小方案，只减少发布审计的一遍前置读取。结果中保留不可序列化的
对象/版本绑定；内容相等比较仍允许独立副本，但复用校验必须另过同根同对象检查。
同时绑定facts目录及其文件，阻止事实侧文件在完整核验后被替换或改写。
发布事务在创建原生投影后、写入publication之前再次检查版本连续性；不一致则
回滚整个事务。校验后的版本检查不声称重新检测静默字节损坏，实际全量SHA仍在
审计返回前进行。这不新增文件系统与SQLite跨系统的原子提交保证。

失败测试已确认旧实现允许同字节换对象，也确认原发布审计恰好3遍；协议修正后
116项通过。最终构建、事务回滚与实机结果另记。

## 入库目标副本复用（2026-10-22，已实施并通过实机验收）

上轮入库5遍分别来自：来源头部核验、复制入口来源核验、目标暂存副本核验、入库访问
前置核验、访问后的最终核验。本次只复用目标副本核验到同次入库事务，将新入库5遍
减为4遍；已有目标恢复路径从4遍减为3遍。来源副本与目标副本凭据不能互换。

复制接口增加返回目标URL和其内存校验结果的方法，原URL返回接口保留兼容。仍先
完整校验暂存副本再改名。仅在模块自身执行的同父目录改名后，允许根目录ctime变化；
根的device/inode/birthtime/mtime/size/mode必须一致，所有子目录、manifest、资源及
facts版本无豁免。改名前后都核对对象绑定；调用方不能任意重绑定或持久化凭据。
该受限重绑定仅消除预检重复读取，入库回调后的完整实际字节SHA仍保留。

目标已存在时重新全量核验，绝不从日志加载旧凭据；新旧路径均在事务进入前检查凭据。
事务内写入条目、执行最终全量校验后，在标记catalogCommitted前再次检查对象连续性；
失败或注入提交中断时回滚条目与状态，保留prepared记录和已复制归档供安全重试。
已提交批次的事实恢复、发布及Mac编辑保护继续沿用现有路径，不变更schema或日志。

首个RED已确认旧实现接受校验后同字节换对象并提交catalogCommitted。后续门禁包含
同大小损坏、截断、旧凭据（修改后恢复原字节）、对象替换、提交中断及恢复无重复，
再进行同一iPhone/SSD1/Debug、2,889项、4GiB非稀疏资源、剩余8MiB实机配对复测。

提交中断另以独立XCTest进程在最终全量SHA通过、SQLite事务尚未提交时停止并被外部SIGKILL验证；新进程必须看到prepared和零条目，然后重试入库、发布和重复调用均只保留一份。

失败均无条目或可见资产，fresh重试成功且无重复。独立进程提交窗口SIGKILL后，新
