# ADR-107：已验证手机归档成为主图库来源

2026-10-19，已部署并发布 2,866 项原生来源，数据库逐项对账通过。真实网格暴露的内存问题已按 ADR-108 修复并在当前 Xcode 运行版复验照片网格、RAW 单图和视频网格；视频播放进度及相簿展开仍因界面控制超时待验收，不标记整体完成。取代 ADR-103/104 中将归档浏览器作为日常入口的过渡方案。

## 问题与决定

手机归档已有完整资源、身份和整理账本，但没有主图库的 source/asset 投影。设置页逐项展示内部 ID、另一套归档浏览器，均不能提供正常图库体验。

完整入库并通过逐资源、身份、整理快照核对后，在一个数据库事务中发布主图库来源、资产、红心、标签及相簿/集合成员关系。来源按手机安装身份、epoch 和接收位置聚合。主界面使用现有网格、预览、视频播放、收藏和标签筛选；设置只负责连接、传输、验收状态及折叠的高级操作。

使用受管理的 folder/file 定位器复用现有媒体访问链路，同时增加显式 phone_library_source 身份。只登记清单中的一个主展示资源，其余资源继续由完整归档账本保存；不复制原件、不扫描接收目录。受管理来源禁止普通文件夹扫描、重新绑定和回收授权；不授予原件修改权限。

界面使用手机原文件名；只读媒体访问对清单绑定的资产解析归档中的物理资源名，保留原有路径和文件指纹校验。

相簿和集合是多对多目录，不是磁盘目录。保留空相簿、来源层级、目录顺序与成员序号；相簿文件夹显示所有后代成员。相同名称的不同相簿仍按来源身份区分。标签按手机身份保留独立映射，不能仅因同名就合并已有 Mac 标签。

发布凭据绑定 migration、manifest 和事实快照。首次接入旧批次要重新执行应用内验证，随后启动只检查发布凭据，不反复读取全批原件。失败不暴露部分来源；重复发布不生成重复资产，不覆盖用户后来在 Mac 修改的整理信息。新的手机事实版本另行对账，不能通过启动回填静默覆盖 Mac 编辑。

## 本轮边界与验收

现有 2,866 项及其 4,169 个资源保持原位置；23 项继续暂缓。代码及合成数据隔离构建/测试，不安装新版本，不直接操作生产数据库或受保护照片目录。

验证：正常主图库查询可见；多相簿/空相簿/层级/收藏/标签/集合一致；失败不发布；重放和冷启动无重复且保留 Mac 编辑；管理来源不进入扫描或目录索引重建。真实来源显示与缩略图/视频的 Xcode 验收在用户允许更新后执行。
