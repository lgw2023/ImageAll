# ADR-048：Mac Host 同源 Web Companion

> 状态：已决定并扩展（2026-08-01，项目所有者要求以 Mac 端体验与功能齐备为目标）
> 相关：`docs/ADR-043-MAC-HOST-IOS-COMPANION.md`、
> `docs/ADR-044-MAC-HOST-COMPANION-R3.md`、
> `docs/ADR-047-MAC-HOST-CLOUDFLARE-PUBLIC-TUNNEL.md`、
> `docs/WEB-COMPANION-PARITY-SPEC.md`

## 背景

Mac Host 已通过 `https://imageall.ultrahardcore.net` 暴露现有 Companion API。网页端可以复用
图库、缩略图、预览、标签、审核、任务和 WebSocket 能力，显著缩短手机可用界面的交付路径。

项目所有者明确：

- Web Companion 与原生 iOS Companion 在独立 worktree 中并行开发，互不替代或阻塞；
- 不要求 Mac App、Host 或 Cloudflare Tunnel 离线后网页仍可使用；
- 网页视觉应延续 Mac 端现有风格，不建立第二套设计语言。

## 决策

### 1. 产品和部署形态

- Mac App 继续是唯一数据与写操作权威；Web Companion 不保存或同步 SQLite。
- Web Companion 由 `RemoteHTTPServer` 在同一 Host、同一公网域名下直接托管。
- 同一 Host 额外提供固定的 `http://127.0.0.1:8788` 本机调试入口。该监听器只绑定 IPv4
  loopback，不暴露给局域网；它与公网入口共用 Web 静态资源、API 路由、账号白名单和业务
  权威，不形成第二套服务。
- 公网 Tunnel 继续回源到原有 `8787` TLS 端口。本机明文调试入口不替代或弱化公网 TLS，
  也不改变原生移动端的配对与证书契约。
- 不增加云数据库、静态站点托管服务、Service Worker 离线缓存或后台同步。媒体鉴权使用的
  Service Worker 只做同源请求头桥接，不缓存响应或实现离线能力。
- 原生 iOS 工程和协议继续独立演进；本切片不修改 `ImageAllMobile`。

### 2. 首个纵向闭环

首版必须完成：

1. 用户在 Mac 设置中开始短时配对，并复制带 URL fragment 的网页配对链接；
2. 手机或桌面 Safari 打开公网域名，以一次性配对令牌建立浏览器会话；
3. 网页加载真实来源、标签和资产分页网格；
4. 用户打开单张资产检查器，查看预览与标签状态；
5. 用户执行确认、拒绝或清除标签，Mac Host 持久化结果；
6. WebSocket 收到 Host 事件后刷新相关投影。

配对令牌只放在 `#pair=...` fragment 中，不进入 HTTP 请求、Cloudflare 日志或 Referrer。

### 3. 浏览器会话与安全

现有原生客户端继续使用 `Authorization: Bearer`。浏览器新增同源会话适配层：

- 配对成功后把 access token、refresh token 和 device ID 写入 `Secure; HttpOnly;
  SameSite=Strict` Cookie，JavaScript 不持有长期令牌；
- access Cookie 可用于现有 HTTP API 和浏览器 WebSocket 握手；
- access 过期时，同源 refresh 路由旋转 refresh token 并重发 Cookie；
- Cookie 鉴权的写请求必须通过 `Origin` / `Host` 同源校验；原生 Bearer 请求不受影响；
- 静态资源使用严格 CSP、禁止 framing、禁止 MIME sniffing，所有响应继续 `no-store`；
- Web 静态资源只按固定白名单路径提供，不接受任意文件路径。

浏览器登出只清除本机 Cookie；若要撤销长期授权，仍在 Mac 设置的“已配对设备”中撤销。

网页另提供一条不依赖配对会话的账号白名单路径：

- Mac 设置中的“网页访问白名单”可随时新增账号、更新密码或移除账号；
- 账号密码采用 HTTP Basic 随每次受保护请求提交，不签发 access token、refresh token
  或认证 Cookie，浏览器仅在当前页面内存中保留凭据，刷新页面后需重新登录；
- 密码不明文落盘，Host 使用独立随机盐和 PBKDF2-HMAC-SHA256 派生值持久化，账号文件
  权限限制为当前用户读写；
- 正确凭据只允许白名单账号访问；更新密码或移除账号会立即清除验证缓存；
- 账号模式的写请求继续强制 `Origin` / `Host` 同源校验，连续失败验证受到限速；
- 浏览器 WebSocket 无法安全附加自定义 Basic Header，因此账号模式采用短间隔增量刷新；
  配对 Cookie 模式继续使用 WebSocket 实时事件；在 Host 尚未覆盖业务事件发布期间，
  配对会话额外每 15 秒执行一次投影一致性轮询，待事件覆盖完整后再移除该兜底；
- 账号轮询会比较图库与审核页的可见投影，只在内容实际变化时重绘；未变化时保留现有
  DOM 与图片对象，避免周期性灰屏和重复下载缩略图；
- 静默轮询、WebSocket 事件和手动刷新会重新获取至少当前已载入的照片窗口，不得把用户
  通过“载入更多”展开的多页结果缩回首屏；
- 图库按照片 ID 原位协调卡片；标签计数、选中态等元数据变化不重建图片对象，只有照片
  的内容版本或可用性变化时才重载对应缩略图，不得因单条变化重载整页；
- 账号模式下缩略图和预览由 JavaScript 以受保护请求读取为临时 Blob，不把密码写入图片
  URL、查询参数、日志或持久存储。
- 原生 `<video>` 不能附加 Basic Header；账号模式把当前页面内存中的 Basic 值临时传给
  同源 Service Worker。Worker 只拦截 `/v1/assets/{id}/media` 的 GET/HEAD，保留浏览器的
  `Range` Header，不写入 Cache API、IndexedDB、`localStorage` 或 URL；退出、切换登录模式
  时显式清空。由于浏览器可随时终止 Worker，新的 Worker 在处理媒体请求时会向该请求的
  发起页面临时索取当前内存凭据；若 Chromium 原生视频 Range 请求没有 `clientId`，则回退
  询问同源受控窗口。Worker 以 `mode: same-origin` 重建 GET/HEAD，避免原生视频的 `no-cors`
  Request 剥离 `Authorization`，同时保留 Range；页面关闭或刷新后无法恢复旧凭据。
  配对 Cookie 模式不需要这条桥接。

### 4. 视觉与交互

网页不是独立品牌站，而是 Mac 图库工作区的响应式延伸：

- 使用系统字体、系统蓝强调色、系统背景/分隔色和自动亮暗模式；
- 宽屏保持“来源侧栏—缩略图网格—检查器”三栏；
- 沿用 8px 网格间距、6–10px 连续圆角、次级文字和选中蓝色描边；
- 窄屏把来源变为横向筛选栏，检查器变为覆盖层，但信息层级和操作语义不变；
- 不使用外部字体、图标 CDN、前端框架或第三方运行时依赖。

### 5. 日常工作流补齐

首个纵向闭环稳定后，网页端继续复用现有 Host API 补齐高频工作流，不复制 Mac
数据库，也不把完整图库下载到浏览器后再做本地假筛选：

- 网格支持与 Mac 一致的普通单选、Command 点击切换、Shift 点击连续选择和 Command-A
  全选当前已载入结果；以 `tag-selection` 读取所选资产的标签聚合状态，再批量确认、拒绝
  或清除；
- 检查器单选和网格多选都可调用 Host 的原子 `create-and-apply` 命令新增个人标签并立即
  确认到目标照片；请求带持久幂等操作 ID，重试不得重复创建标签；
- 独立审核工作区按标签和当前来源读取审核队列，支持前后导航、键盘决定和分页；
- 标题栏任务面板显示进度，并只呈现 Host 返回的暂停、继续和取消动作；
- 检查器和审核工作区共享全屏预览，支持前后切换；
- 高级筛选把标签决定、标签组合、标签存在性、可用状态、照片/视频和文件格式条件传给
  Mac 端 `AssetPageFilter`，由权威图库查询执行。

窄屏继续使用检查器覆盖层和横向审核队列；同一操作的名称、状态色和决定语义与宽屏一致。
离线时允许查看已显示内容，但所有标签、审核和任务写操作统一禁用。

### 6. Mac 体验对齐的长期边界

Web Companion 不再以“能浏览和改标签”作为产品停止位置，而以用户可在网页完成绝大多数
日常图库工作、且操作语义与 Mac 端一致为目标。具体功能状态和优先级以
`docs/WEB-COMPANION-PARITY-SPEC.md` 为单一对齐清单。

实现遵循三类边界：

1. 浏览、筛选、选择、标签、审核、任务、训练和瘦身结果等 Host 已能权威表达的能力，
   应在网页端提供同名、同状态、同快捷键语义的完整工作流；
2. 文件夹选择、Photos 授权、受保护空间写入等依赖 macOS 权限或原生面板的动作，可由
   网页发起，但必须在 Mac 端显示明确确认和结果，网页不得伪造已完成状态；
3. 无法安全远程表达的系统权限授予、Mac Host 配置和不可逆系统级操作保留在 Mac，
   网页应说明原因和下一步，不以无响应或隐藏入口代替。

所有列表刷新必须保留用户上下文：当前来源、照片/视频模式、筛选、搜索、排序、已载入
窗口、选择、检查器目标和滚动位置。WebSocket 或账号轮询只刷新受事件影响的投影，不得
让整页回到初始状态。

### 7. 标签管理、一步撤销与审核总览

Web Companion 的标签管理和审核入口继续使用 Mac 端现有领域服务，不在网页中维护第二份
标签树或统计缓存：

- Host 提供标签分组投影，以及标签重命名、移动分组、归档和标签组新增、重命名、删除命令；
  所有命令复用领域校验并以操作 ID 保证重试幂等；
- 新增并应用标签、单项/批量标签决定与审核决定成功后，Host 分别维护当前进程内“标签”和
  “审核”两个最近一步撤销凭据，与 Mac 工具栏的两个独立入口一致。标签写入只替换标签撤销，
  审核写入只替换审核撤销；撤销恢复该次写入前的决定快照，同一通道内只允许撤销当前最近一步。
  重复提交同一撤销操作仍幂等；浏览器为一次撤销生成的操作 ID 必须跨传输失败重试复用，直到
  成功或被该通道的新凭据替代；Host 重启后不宣称旧凭据仍可撤销；
- 为兼容已经持久化的幂等账本，既有操作的落盘响应格式保持不变；撤销凭据只作为当前 Host
  进程中的附加能力。重启后重放旧操作仍返回原结果，但不会虚构可用撤销；
- 审核首页使用 Mac `SuggestionTagOverview` 的权威投影，按照片/视频和可选来源范围展示每个
  标签的待审总数、建议来源构成、已确认/已拒绝样本数与任务状态；点击标签进入同一范围的
  正式审核队列；
- 账号模式的受保护缩略图按可视区延迟加载，避免大批 Basic Auth 图片请求挤占检查器；
  检查器立即显示当前缩略图的本地渐进占位，并以高优先级加载 PhotoKit 预览后原位替换；
- 原始视频通过受保护的 `GET/HEAD /v1/assets/{id}/media` 提供。Host 支持单段 HTTP Range，
  返回 `200` / `206` / `416`、真实视频 MIME、`Accept-Ranges` 和准确的 `Content-Range`；不支持
  多段 Range。
- 文件夹视频通过已授权根目录和 no-follow 文件描述符打开；Photos 视频仅通过 PhotoKit
  请求本机原始 AV 资源 URL。每个 HTTP 响应持有自己的文件描述符及所需来源访问租约，响应
  完成、取消或失败都释放，不把整段视频读入内存；Host 以 256 KiB 有界分块发送。
- 网页检查器用原生 `<video controls playsinline>` 播放和定位；网格“适应/填充”切换只保存
  非敏感布局偏好，不改变资产、标签或原始文件。
- 普通图库视频卡沿用 Mac 的“悬停静音播放”语义：卡片常驻播放标识与时长，细指针停留短暂延迟
  后只创建一个静音循环 `<video>`，继续使用同一媒体端点与账号内存凭据桥。离开卡片、滚动离屏、
  切换媒体、进入单图、窗口失焦或退出会话立即暂停并释放；减少动态效果偏好下不自动播放。
  悬停不得改变选择、检查器目标、分页或滚动位置，触控端保持静态缩略图。
- 单张检查器详情继续复用 Mac `AssetInspectorDetail`，除来源、路径、格式、尺寸、拍摄和修改
  时间、可用状态外，还投影视频时长和文件指纹大小。网页不接收本机绝对路径。
- “在 Mac 上打开”通过受保护的 `POST /v1/assets/{id}/open-original` 命令调用 Mac 现有
  `LibraryOriginalAssetOpening`：照片交给“预览”，视频交给系统默认播放器。该动作只读、
  仅针对单个可用资产，并继续受认证和浏览器同源写请求检查约束；网页不提供原片下载。

### 8. 训练工程先读后写

训练工程按“权威投影 → 幂等启动命令”两步接入，首个切片不让网页直接拼装数据库查询或
绕过 Mac 端训练门槛：

- `GET /v1/training/workspace` 复用 `TrainingWorkspacePort`，按照片/视频和可选方法返回训练
  Run、三种模型槽位、时间、状态、数据范围、配置、过程指标、产物和结果；
- Run 中历史 JSON 在 Host 端先移除 path、bookmark、locator、filename、original 等可能包含
  本机位置的字段；绝对路径、不安全 artifact 引用和原始训练文件不进入浏览器；
- 网页沿用 Mac 端“左侧训练记录—右侧台账详情—顶部模型槽”的结构，账号轮询或任务事件
  只原位协调 Run，不改变当前媒体、方法筛选或选中记录；
- `GET /v1/training/setup` 返回 Host 权威计算的可训练标签、正反样本数、活动来源和方法可用性；
  网页不自行推断标签是否达标；
- `POST /v1/training/launch` 用 `operationID` 幂等启动任务。Feature Print 只允许一个达到 2 + 2
  门槛的标签并复用既有全库建议队列；个人模型复用既有训练快照、Embedding Cache、Centroid /
  AdamW Rebuilder、媒体隔离和单方法运行约束；
- 网页提供与 Mac 相同层级的“方法—标签—来源/当前选择—提交确认”配置面板。提交后只显示
  Host 回执和活动进度，不以浏览器本地状态伪造成功；个人模型失败按安全错误码展示，不回传
  本机路径或原始训练文件；
- `POST /v1/training/activities/{operationID}/actions` 只接受 Host 返回的可用动作。当前个人模型
  训练支持取消，网页发出请求后由同一个 Rebuilder 执行取消并返回权威终态；完成、失败或取消
  后不再展示可执行动作；
- Feature Print Run 通过 `jobID` 关联既有后台任务。暂停、继续、取消继续走对应任务的领域端口，
  恢复建议任务时同时唤醒 Host Runner；网页不靠修改本地数组伪造任务恢复；
- 失败或已取消 Run 提供“重新配置”，只复用仍可验证的方法和标签。旧记录缺少标签 ID 时必须
  重新显式选择标签，提交按钮保持禁用，避免把历史 artifact 引用推断成训练输入。

### 9. 图库瘦身投影与受限命令

图库瘦身先以 Mac 权威结果建立只读工作台；后续分析命令仍复用同一领域服务，不在浏览器
重建算法，也不把媒体回收授权扩展到网页：

- `GET /v1/library-slimming/workspace` 复用 `LibrarySlimmingAnalysisJobPort`，按照片/视频返回
  分析记录、进度、来源范围、候选分组与选中分组成员；成员的文件名、来源、可用性和内容版本
  继续由图库投影提供，网页不接收本机路径；
- 网页沿用 Mac 的“分析记录—候选分组—成员网格”层级。候选组首屏 48 组、成员首屏 96 项，
  之后按需递增；Host 保留 10000 组/5000 成员的防误用查询上限，但前端可逐步到达当前真实
  分析总量，不以固定 500 项截断合法结果；
- 静默刷新、账号轮询和手动刷新保留当前媒体、分析记录、候选分组与仍存在的成员选择；
  普通点击、Command 点击、Shift 点击、Command-A、Space 和双击沿用图库网格的选择/预览语义；
- 浏览器继续复用受保护缩略图和预览路由，不直接访问 Photos Library 包或文件系统路径；
- `GET /v1/library-slimming/setup` 返回活动来源和 Mac 当前共享阈值；`POST .../launch` 支持
  `catalog`、`currentFilter`、`seeds` 三种既有范围。`catalog.sourceIDs == nil` 保留“全部活动
  来源”，空数组是显式未选并由 Host 拒绝，网页不得把二者合并；
- `PUT /v1/library-slimming/thresholds` 保存 Feature Print Top-K/L2、DINO cosine 和拍摄日分桶
  设置。数值先由网页检查，再由 Host 使用现有 `clamped()` 约束；
- `POST /v1/library-slimming/jobs/{jobID}/actions` 只提供暂停、继续和删除分析记录。启动、设置和
  任务动作均使用持久化幂等记录；后台 Runner 仍调用既有 `LibrarySlimmingAnalysisJobPort`；
- 删除分析记录明确不删除媒体。回收站采用独立安全投影与请求协议：
  `GET /v1/library-slimming/recycle` 只返回条目 ID、资产 ID、来源显示名、文件名、媒体、状态、
  保留期限和 Host 判定的可用动作，不返回原路径、隔离路径或 Photos local identifier；
- `POST /v1/library-slimming/recycle/requests` 只接收单项恢复、撤销授权前失败意图、重新检查中断
  状态和文件夹隔离项永久删除。除纯数据库撤销外，Host 先返回 `202 awaitingMac`，再由 Mac
  原生确认；文件恢复若缺少写授权继续使用既有安全目录选择器；永久删除必须再次显示不可恢复
  警告；
- Apple Photos 回收项在网页只显示恢复说明，不开放恢复或永久删除命令；实际操作继续由系统
  “照片 → 最近删除”管理。网页也不直接访问隔离目录，不获得通用文件系统写权限；
- `GET/POST /v1/library-slimming/removals` 提供候选成员批量移入可恢复回收站或立即释放源空间。
  Host 接收命令时冻结并规范化 `jobID + clusterID + mediaKind + assetIDs`，再次确认分析记录、媒体
  和簇成员关系；同一操作 ID 只对应同一冻结快照，且与单项回收站操作互斥；
- 两种批量操作均先返回 `202 awaitingMac` 并显示 Mac 原生批次确认。执行继续复用既有回收服务、
  文件夹写授权和 Photos 授权重试；网页只显示安全进度、隐藏资产 ID 与逐项失败类别，不接收路径
  或 Photos local identifier；完成后权威工作区过滤已进入回收生命周期的成员，小于两项的簇
  不再作为重复/相似候选显示。
- `POST /v1/library-slimming/identical-cleanup/plans` 复用 Mac 的完全相同项规划器，在 Host 内冻结
  带来源身份、内容 revision 与原始字节哈希证明的完整方案；网页只收到临时 `planID`、去留数量、
  来源分布和组规模统计，不收到 locator、哈希或 Photos local identifier。方案最多保留最近 16 份；
- `GET/POST /v1/library-slimming/identical-cleanup/requests` 只接受 Host 仍持有的 `planID`。执行前
  Host 从原分析记录重新生成方案并要求与预览完全相等，再显示包含分组数、保留规则和删除数量的
  Mac 原生确认；确认后调用既有 `move/deleteIdenticalCleanup...` 证明校验路径，结束后独立调用
  `verifyIdenticalCleanup`，网页显示真实完成组数、剩余冗余与未决数量。普通簇内批量、回收站命令
  与一键清理互斥，避免多个原生授权或媒体变更同时发生。

### 10. 来源管理采用“Web 发起、Mac 原生确认”

来源生命周期不能退化为浏览器直接操作文件系统或 Photos 权限。网页只创建短生命周期的
交互请求，Mac Host 才是唯一执行者：

- `GET /v1/source-management` 返回来源状态和最近请求；`POST .../requests` 立即返回 `202`，
  相同 `operationID` 在同一 Host 进程内只对应一个请求，避免网络重试重复弹出系统面板；
- 连接/重新授权文件夹调用既有安全目录选择器；连接或重新绑定 Apple Photos 先显示 Mac
  原生说明，再走系统 TCC；完整修复和删除来源也必须在 Mac 二次确认；
- 请求状态区分 `awaitingMac`、`running`、`completed`、`cancelled`、`failed`。网页轮询状态，
  但关闭网页面板不会替用户确认，也不会取消已经显示的 Mac 系统面板；
- 同一时刻只允许一个交互来源请求，防止多个 NSAlert / NSOpenPanel 互相覆盖。完成后网页按
  Host 新投影刷新来源与资产窗口；后台重扫/Photos 同步继续复用既有队列和 Runner；
- 删除仍只清除 ImageAll 的来源记录、相关索引和 App 自有缓存，不删除磁盘原文件或 Apple
  Photos 原图；存在未解决回收记录时继续由既有领域门禁拒绝；
- 公网地址、配对设备、网页白名单和 Host 开关继续保留在 Mac“网页访问”设置中，网页仅解释
  该边界，不提供能够把自己加入白名单或改变 Host 暴露面的入口。

### 11. 世界地图复用本地渲染器与目录聚合

网页世界地图不另建地理数据库或重新实现照片定位。Host 新增两个只读投影：
`GET /v1/world-map/snapshot` 接收可选视口并返回最多 2000 个聚合，
`POST /v1/world-map/selection` 接收 Host 签发的聚合查询并返回最多 120 张同桶照片。二者复用
`LibraryWorkspacePort` 的 `WorldMapCatalog`，照片资格、跨经线、GPS/地点标签构成和回收生命周期
排除规则与 Mac 一致。

MapLibre、deck.gl、Natural Earth 与 Photo Atlas 样式继续来自 App bundle。Web Companion 只把
`/world-map/*` 固定白名单资源作为同源 iframe 提供：根页面保持 `frame-ancestors 'none'` / `DENY`，
仅地图文档允许 `frame-ancestors 'self'` / `SAMEORIGIN`；地图仍不联网取瓦片或执行 CDN 脚本。
父页面只接收同源、指定 iframe 的 `ready`、`cameraChanged`、`clusterClicked` 和 `renderError`，
相机事件合并查询并以请求代次丢弃过期结果，避免后台轮询造成地图反复重置。

地点详情中的缩略图和全屏预览继续使用受保护媒体路由，响应不含绝对路径、locator 或 Photos
identifier。旧照片位置回填增加 `GET /v1/world-map/location-backfill` 状态投影和
`POST /v1/world-map/location-backfill/requests` 幂等控制：浏览器只能按来源显式开始、重试或取消
既有 reconcile 工作，Host 返回目录覆盖率与后台进度。打开地图、打开面板和轮询都不得自动开始；
关闭面板只停止浏览器轮询，不取消任务。文件夹只读内嵌 GPS，Apple Photos 只经正常授权读取位置，
结果只写 ImageAll 自有目录，不移动、重命名、覆盖或写回原照片。

地点标签解析继续复用 Mac 的 `WorldMapPlaceResolutionService`，不在浏览器增加第二套地理推断：

- `GET /v1/world-map/place-tags` 只返回至少关联一张已确认照片的标签、分组、计数、缓存状态和最多
  8 个地点候选；不返回照片、路径、Photos identifier 或资产 ID；
- `POST /v1/world-map/place-tags/requests` 只接受显式 `search` 或 `confirm`。搜索只把用户输入框中的
  地点描述交给 Host；Host 仍先用 Apple 地图，国际结果无效时再回退 OpenStreetMap。打开面板、
  修改文字和读取缓存均不联网；
- 浏览器只确认 Host 刚返回的 opaque `placeID`，Host 继续以既有事务校验候选、保持 GPS 优先并只为
  无 GPS 照片补全 `placeTag` 位置；网络重试按 operation ID 幂等，过期候选返回冲突而不静默改写；
- Web 面板沿用 Mac 的搜索描述、缓存来源提示、未识别/待选择/已确认/已忽略/未找到状态与候选卡。
  搜索或确认完成后只原位更新对应标签与地图聚合，不重建工作区、跳动滚动位置或丢失输入焦点。

### 11A. 应用存储维护采用脱敏投影与 Mac 原生执行

网页可以查看和发起 Mac 工作区已有的存储维护能力，但不能取得本机目录结构或绕过原生确认：

- `GET /v1/storage-maintenance` 只返回预览缓存、长期 Photos 原图副本的条目数与登记字节数，
  以及“内置 / 外置 / 重启后生效”状态；应用支持目录、缓存目录和外置根目录的绝对路径不进入协议；
- 等待生效的外置位置最多返回最后一级显示名，用于和 Mac 选择结果对照，不返回父目录、书签或
  security-scoped URL；
- `POST /v1/storage-maintenance/requests` 支持导出用户数据、选择外置应用存储、清理预览缓存和
  清理长期 Photos 原图副本。网页立即取得异步回执，相同 `operationID` 不重复执行，同时只允许
  一项等待或运行中的存储操作；
- 导出与外置位置选择必须显示 Mac `NSOpenPanel`；两类清理必须显示 Mac `NSAlert`。关闭网页面板
  不替用户确认，也不取消已经显示的原生面板；
- 清理预览缓存只调用既有可重建缓存服务；清理 Photos 原图副本继续复用图库瘦身活动门禁，
  分析进行中必须拒绝。任何操作都不得修改 Apple Photos 原图、文件夹来源原件或人工标签；
- 网页显示 `awaitingMac`、`running`、`completed`、`cancelled`、`failed` 与安全结果摘要，完成后
  重新读取权威用量和位置状态，不在浏览器推算释放空间或保存第二份存储清单。

### 12. 图库总览复用 Mac 聚合与 Library Atlas 语言

网页不重新计算图库规模、去重、来源、标签或年份统计。Host 以只读
`GET /v1/gallery-overview` 暴露现有 `GalleryOverviewSnapshot` 的远程 DTO；其中只包含计数、
显示名、枚举和稳定 ID，不包含路径、locator、书签、PhotoKit identifier 或媒体内容。刷新继续
只读 ImageAll 目录数据库，不扫描原照片。

界面沿用 Mac `GalleryOverviewView` 的 `LIBRARY ATLAS`、照片蓝/视频橙、保守去重口径和卡片
层级；来源、正样本标签与媒体账本可以下钻回现有 Host 权威筛选。总览有独立请求代次、加载/
错误状态和焦点恢复；资产、来源或标签事件只在总览可见时合并刷新，避免后台轮询形成刷新循环。

### 13. 建议阈值复用 Mac 权威仓储

网页通用设置可以读取和修改与 Mac 设置页相同的三轨建议阈值，但浏览器不保存第二份偏好：

- `GET /v1/settings/general` 在既有通用设置快照中可选返回三种方法的全局默认值、全部活动标签的
  有效值与覆盖值，以及 Host 根据可追溯正负样本计算的只读参考建议；旧 Host 缺少该字段时网页
  继续兼容，只隐藏阈值区域；
- `PUT /v1/settings/general` 只接受一次 `setDefault`、`setOverride` 或 `clearOverride` 操作，继续
  要求 `operationID` 并纳入持久幂等键。Host 校验方法、标签和有限分数后，调用与 Mac 设置页相同
  的 `SuggestionThresholdPort`，再返回完整最新快照；
- 网页沿用 Mac 的三轨名称、0.05 步进、标签搜索、“继承默认”和“采用参考值”语义。参考值只有
  正负样本各至少 5 个时使用中位分隔，否则至少 5 个拒绝样本时使用第 90 百分位；浏览器不自行
  重算参考分数；
- 关闭仍在加载的设置窗口必须同时作废请求并解除 loading 状态；再次打开需重新读取 Host，不能
  因一次快速 Escape 永久禁用控件。提交重绘后按稳定 tag/method 键恢复输入焦点和滚动上下文。

### 14. 来源侧栏上下文操作复用来源管理命令

网页来源侧栏应与 Mac 一样在来源就地提供上下文操作，但只展示 Host 已经允许的动作。右键或
Shift-F10 打开的菜单从当前 `RemoteSourceSummary` 状态推导“查看、同步/重扫、恢复/重绑、完整
修复、删除和打开来源管理”，实际写入继续提交既有 source-management operation，不新增浏览器
直写路径。需要授权或破坏性确认的动作仍在 Mac 原生窗口完成；菜单不开放尚未具备 Remote 安全
契约的缩略图预热、Photos 写权限或文件回收权限入口。

上下文菜单必须支持方向键、Home/End、Escape，并在关闭后回到原来源。来源管理和存储面板在
加载中被快速关闭时，除了作废请求还必须清除 loading 状态，保证再次打开能重新读取 Host。

### 15. 图库个人模型快捷入口复用训练设置

Mac 图库工具栏的“重建个人模型”与“训练超级个人模型”在网页不新建第二条
训练协议。主工具栏与命令面板都打开既有 `training/setup` 设置页，分别预选
`personalCentroid` 和 `personalAdamW`：

- 只把当前图库中“已确认”的标签筛选带入训练，拒绝或排除条件不作为训练标签；
- 图库有多选时默认限定当前选择，否则使用全库确认样本；用户启动前仍在同一
  设置页确认标签和范围；
- Host 快照明确表示方法不可用时，必须显示原因并禁用最终启动，不得静默改成另一方法；
- 菜单支持方向键、Home/End 与 Escape，设置关闭后回到原工具栏按钮。

### 16. 检查器标签交互复用 Mac 分组与主动作语义

单张与多选检查器必须使用同一份 Host 标签组投影，不再把所有标签展示成无层级平铺列表：

- 标签按 Host `groupID` 与标签组 `sortOrder` 分段；未知或旧 Host 标签稳定归入“其他”。组的折叠
  状态只作为浏览器非敏感界面偏好保存，不保存标签决定或第二份标签树；
- 标签主体沿用 Mac 高频语义：左键确认，右键清除；键盘 X 拒绝、Delete/Backspace 清除。右侧
  确认、拒绝、清除三态按钮继续保留，保证触控用户和显式拒绝路径可达；
- 多选标签主体显示 Host 聚合得到的全部确认、全部拒绝、全部未决定或混合状态，任何主体动作
  都提交冻结选区到既有批量决定端点，不以第一张资产状态代替聚合；
- 分组折叠、决定写入和异步刷新后均按稳定 group/tag/action 键恢复焦点；方向键及 Home/End 可在
  分组标题间移动，不能因 DOM 重绘把焦点和检查器滚动上下文丢回页面顶部；
- 标签组内顺序与来源顺序和 Mac 一样属于设备本地界面偏好，不是图库权威事实；网页可在本地保存
  ID 顺序并让侧栏、单张与多选检查器共享。跨标签组移动仍通过 Host 既有幂等 `move` 命令更新
  `groupID`。远程协议没有组内排序字段是正确边界，不再把它误当成实现拖放的前置条件。

### 17. 单张检查器投影待审 AI 建议

Mac 检查器已有的 `AssetPendingSuggestion` 属于 Review 仓储权威事实，网页不得从标签计数或模型
状态自行猜测。`RemoteAssetDetail` 新增可选 `pendingSuggestions`：新 Host 返回标签 ID、显示名和
四轨来源；旧 Host 缺少字段时客户端只隐藏该区，不影响详情解码。

网页沿用 Mac 顺序把“AI 建议”放在预览与元数据之间，默认显示前 5 条并可展开全部。每条只提供
“属于 / 不属于”，写入继续复用现有原子标签决定端点；成功后重新读取同一详情和 Review 仓储，
不在浏览器先删除建议伪装成功。同一标签存在多轨建议时按 `tagID + origin` 保持稳定身份；重绘后
优先回到原动作，原建议已被权威清除时回到相邻建议或区标题。

### 18. iCloud-only 预览保持显式单图授权

网页普通缩略图与详情预览必须继续使用 local-only PhotoKit 读取，不能因为浏览器访问而隐式下载
iCloud 内容。Host 把 `PhotosLibraryError.cloudOnly` 映射为稳定的 409 `cloud preview required`，
只有检查器当前单图显示这一状态时才展示“从 iCloud 获取预览”：

- `POST /v1/assets/{assetID}/cloud-preview` 复用 Mac `downloadCloudPreview` 与不透明
  `PhotosCloudDownloadGrant`，仅请求同一张照片、长边最多 2048px 的标准预览，并原子写入现有
  downloaded-preview 缓存；浏览器不能提交网络访问布尔值、Photos identifier 或本机路径；
- 下载请求成功后网页重新读取普通 `/preview`，不让云端端点变成长期第二套媒体 URL。切换资产
  时旧结果不得覆盖当前检查器；失败态保留同一单图重试按钮，不自动循环；
- 该入口只恢复预览，不开放原图下载、批量云端预取或后台建议隐式下载。视频与非 Photos 预览
  失败仍使用普通不可用提示，不能错误展示 iCloud 操作。

### 19. 首次使用与常用标签复用 Mac 权威能力

网页在尚无来源与标签时，必须显示与 Mac 同义的首次使用空状态，并提供连接照片文件夹、连接
Apple Photos 和添加常用标签三个主动作。添加常用标签不得在浏览器维护另一份模板：

- `POST /v1/tags/install-presets` 只接受 `operationID`，Host 直接复用
  `LibraryWorkspacePort.installPresetTags()`，安装人像、风景、美食、动物、植物、建筑、旅行、
  截图、文档九个既有预设标签，并返回本次实际新建的权威标签投影；
- 操作按固定 `starter-v1` 语义持久幂等，同一操作 ID 重放不重复写入。连接中断后的重试沿用原
  operation ID；全部已存在时返回成功空结果，而不是制造冲突或重复标签；
- 安装只创建标签，不扫描媒体、不分析照片，也不把标签自动应用到任何资产。连接来源仍复用来源
  管理的 Mac 原生选择器与授权门；
- 首次使用空状态、标签侧栏、标签管理面板和命令面板提供同一入口。成功后全部区域重新读取 Host
  标签，隐藏无效的重复安装入口，并把焦点移到首个新标签；幂等空结果则保留在原触发按钮。

### 20. 侧栏拖放排序与检查器共享顺序

网页侧栏按 Mac 的本地偏好模型实现直接整理，不把个别浏览器的排列变成其他设备必须接受的图库
事实：

- 来源行可拖放或使用 Option-上/下调整顺序；只保存来源 ID 数组，Host 返回的新来源稳定追加，
  已删除 ID 自动忽略。排序不调用来源写接口，也不触发扫描或改变当前来源筛选；
- 标签可在组内拖放或用 Option-左/右排序；Option-上/下或拖到相邻分组调用既有
  `POST /v1/tags/{tagID}/move`。网络写入前提供即时预览，成功后重读 Host 权威分组；失败必须恢复
  原分组与两边顺序，不能把乐观状态留在界面；
- 标签顺序由标签侧栏、筛选选择器、标签管理、单图检查器和多选检查器共同消费。标签搜索期间禁用
  拖放，避免在过滤后的不完整列表中制造含糊顺序；重绘、刷新和浏览器重开后按稳定 ID 恢复；
- 标签侧栏分组可折叠并保存为浏览器本地偏好；搜索期间临时展开含命中项的分组，但不覆盖用户原有
  折叠选择。分组标题提供数量、展开状态和方向键/Home/End 导航，与 Mac 侧栏的信息层级一致；
- 单图与多选检查器内的标签主体同样可直接拖放。组内排序只更新本地顺序，跨组仍调用同一 Host
  `move` 命令；Option-上/下调整组内位置，Option-左/右移动相邻分组。完成或失败回滚后焦点必须
  回到发起操作的侧栏、单图检查器或多选检查器，不能被强制送回侧栏；
- 拖放结束或键盘排序后焦点回到被移动项；插入位置使用 Mac 式细强调线和轻量分组轮廓，不引入
  新视觉体系。偏好只含非敏感 UUID 顺序，不保存决定、路径、账号或媒体标识。

### 21. 标签侧栏复用 Mac 筛选手势与上下文操作

网页标签侧栏不再把标签点击退化成“永远只看一个已确认标签”，而与 Mac 采用同一组高频操作：

- 普通点击切换已确认标签并使用任一匹配（并集）；Command/Ctrl 点击切换已确认标签并使用全部
  匹配（交集）；Command/Ctrl-Option 点击切换排除。已有确认、排除和交集状态必须直接显示在标签
  chip 上，并进入同一资产查询参数，不能仅改变颜色；
- 标签右键或 Shift-F10 提供“仅筛选此标签、排除此标签、重命名、归档”。筛选动作直接更新当前
  工作区；重命名和归档继续复用既有 Host 幂等命令及归档确认，不在浏览器建立第二份标签数据；
- 非系统标签组标题右键或 Shift-F10 提供重命名和删除分组。删除仍使用既有确认门，组内标签的迁移
  由 Host 权威服务决定；系统分组不显示破坏性菜单；
- 上下文菜单支持上/下、Home/End 和 Escape。筛选、取消、管理面板关闭或 Host 写入完成后，焦点
  回到原标签或分组；若标签被归档、分组被删除，则回到最近仍存在的组标题或标签管理入口。

## 验收门

1. Web 静态入口无需鉴权可加载，API 仍默认拒绝未配对访问；
2. Web 配对响应不向 JavaScript 返回 access / refresh token，并设置安全 Cookie；
3. Cookie 可访问 capabilities、来源、标签、资产、图片和 WebSocket；
4. Cookie 写请求拒绝非同源 Origin，合法同源标签写入成功；
5. access 过期后可通过 refresh Cookie 恢复；登出会清除 Cookie；
6. Mac Debug 构建和 Remote 定向测试通过；
7. 浏览器验证覆盖配对页、三栏图库、预览检查器、标签修改和响应式窄屏；
8. 自动化验证不读取 `/Volumes/HDD2` 受保护真实照片路径。
9. 浏览器验证覆盖高级筛选请求、两项批量标签、审核决定、任务暂停、全屏前后导航，
   以及 390px 窄屏检查器。
10. Mac 可新增、更新和移除网页白名单账号；账号密码登录响应不返回 token、不设置认证
    Cookie，正确账号可访问 API/图片，错误或已移除账号返回 401。
11. 账号模式写请求拒绝跨站 Origin，网页登录、退出和轮询在宽屏与 390px 窄屏均可用。
12. Host 运行时，本机浏览器可通过 `http://127.0.0.1:8788` 加载同一 Web Companion；
    `8787` 公网回源端口继续可用，`8788` 不监听局域网地址。
13. 用户点击“载入更多”后，账号轮询、WebSocket 事件、切回页面和手动刷新均保留已载入
    照片数量；只有筛选、搜索、来源或排序改变时才重置到首屏。
14. 宽屏网页支持普通点击、Command 点击、Shift 点击和 Command-A 选择语义；选择工具栏
    和单张检查器均可新增标签，重放同一操作 ID 只执行一次原子创建并确认。
15. 照片与视频模式分别保留来源、筛选、排序、选择和滚动位置；网格密度、侧栏和检查器
    可见性在同一浏览器中保持。
16. 网格支持方向键、Page Up / Page Down、Space 预览和空白区域框选；审核工作区使用
    与 Mac 相同的 P（确认）、X（拒绝）、U（稍后）语义，U 不写入标签决定。
17. 标签侧栏、单张检查器和多选检查器使用同一批 Host 标签数据；多选检查器显示每个
    标签的确认、拒绝、未决定聚合状态，不以当前首张照片冒充批量状态。
18. WebSocket 与账号轮询按事件类型局部刷新；并发刷新排队合并，不重入、不丢失后到
    事件，也不重复重建未变化的缩略图。
19. 标签与标签组管理命令通过 Host 权威服务执行；同一操作 ID 重放不重复写入，标签侧栏、
    检查器和管理面板在成功后取得同一份最新投影。
20. 最近一次标签决定和最近一次审核决定分别可撤销一次；任一通道的新写入只替换本通道凭据。
    重复撤销返回同一结果，同通道更早的撤销凭据失效，Host 重启后不把仅存在于旧进程的撤销
    能力显示为可用。
21. 审核总览的标签、来源、照片/视频范围和统计值与 Mac 端投影一致；从总览进入队列、返回
    总览或后台刷新时不覆盖另一模式的摘要、选择和已载入窗口。标签卡按 Mac 权威标签组与本地
    顺序展示；组折叠、方向键/Home/End 与异步焦点恢复使用稳定 group ID，不另建浏览器分组真相。
22. 账号登录下只预取可视区附近缩略图；单击已显示缩略图后，检查器立即出现渐进预览，
    PhotoKit 大图后台完成后原位替换，且选图不改变图库滚动位置。
23. 视频媒体路由对完整 GET、HEAD、合法单段 Range 和越界 Range 分别返回正确的 200、
    200/206、206 和 416，MIME、长度及 `Content-Range` 与实际资源一致。
24. 文件夹与 PhotoKit 视频均按响应租约流式读取；客户端断开、读取失败和正常完成都释放
    文件描述符与来源访问租约，峰值内存不随视频文件大小线性增长。
25. 配对 Cookie 与账号白名单登录均可播放、暂停和定位视频；账号 Basic 不进入 URL、日志
    或持久存储。切换网格“适应/填充”不重载资产窗口或改变滚动位置。
26. 单张网页检查器的来源、相对位置、媒体、格式、尺寸、视频时长、文件大小、拍摄时间、
    修改时间和可用状态与 Mac 同源；“在 Mac 上打开”只委派既有只读打开器，不回传本机路径。
27. 网页训练工程的媒体/方法筛选、Run 排序、三槽发布状态和详情与 Mac `TrainingWorkspacePort`
    同源；刷新保留选中 Run，返回的 JSON 和 artifact 引用不泄漏本机绝对路径。
28. 网页新建训练任务的标签资格、样本门槛、来源、媒体隔离和并发约束由 Host 再校验；相同
    `operationID` 重试只启动一次。个人训练活动可在工作台原位显示，后台刷新不关闭配置面板
    或重置用户尚未提交的选择。
29. 训练 Run 可打开关联后台任务并只显示 Host 返回的暂停、继续、取消动作；个人训练取消落到
    对应 Rebuilder。失败/取消记录可重新配置，缺少历史标签 ID 时必须显式重选且不能直接提交。
30. 网页图库瘦身的分析记录、候选组与成员来自 Mac 权威投影；大结果分批展开可到达真实总量，
    账号轮询不重置当前分组或选择，预览继续走受保护媒体路由。只读验收不触发分析、回收或删除。
31. 网页图库瘦身设置与 Mac 共用活动来源、三种范围和相似阈值；全部来源保持 `nil` 语义，空选
    不可提交。相同操作 ID 的启动/设置/任务动作只执行一次；浏览器验收只到提交门，不启动真实
    分析、不删除现有记录，也不开放任何媒体回收动作。
32. 网页来源管理可发起连接文件夹、连接/恢复 Apple Photos、重新授权、重扫/同步、完整修复和
    删除来源；需要权限或破坏性确认的操作必须在 Mac 显示原生确认/选择器。网页显示等待、完成、
    取消或失败，不暴露路径、书签、TCC 绕过或 Host 安全设置。
33. 网页回收站按照片/视频、来源和文件名读取 Mac 未解决条目，响应不含原路径、隔离路径或
    Photos 标识。文件恢复、重新检查和永久删除必须先返回等待 Mac 的异步回执并在 Mac 原生
    窗口确认；Photos 只显示系统恢复说明，授权前失败意图只允许无文件 I/O 的安全撤销。
34. 网页批量回收只接受当前分析簇中的冻结资产快照，最多 5000 项；可恢复回收与立即释放空间
    都必须在 Mac 原生窗口再次确认。进度和逐项审计不含路径或 Photos 标识；部分失败不能把失败
    项从候选结果隐藏，成功/待恢复项在 Host 权威投影中保持隐藏。
35. 网页“完全相同项一键清理”的预览统计来自 Mac 运行时证明方案，浏览器只持有临时方案 ID。
    执行前方案必须重新生成并完全相等，随后仍需 Mac 原生确认；每组严格保留一项，完成报告来自
    删除后的独立核验。方案变化、过期、授权取消或部分失败均不得把未完成项目误报为已完成。
36. 图库瘦身分析记录必须保留 Host 的控制请求与阶段化进度，网页不得把“正在暂停/取消”显示为
    普通运行中；运行态必须锁定完全相同项一键清理。记录切换提供可达的前后与键盘导航，并在
    异步投影重载后恢复焦点。删除后核验报告的目标保留、实际读取、当前可用和确认清理统计必须
    来自 Host 的再次读取，不得由浏览器依据清理前计划推算。
37. 网页世界地图只使用 Host 目录聚合和 App bundle 本地渲染资源；视口事件不得形成重复刷新循环。
    点击照片塔后地点统计和预览来自同一选择查询，关闭预览保持地图相机和地点卡片；根页面不可被
    嵌入，地图只允许同源 iframe。网页不获得位置写入、路径或 Photos identifier。
38. 网页图库总览必须直接映射 Mac `GalleryOverviewSnapshot`，不在浏览器重算或缓存为第二真相；
    媒体、来源和标签下钻使用现有资产查询，刷新不访问原照片、不形成请求循环，390px 下不得横向
    溢出。
39. 网页应用存储面板只显示 Host 权威用量和脱敏位置状态；导出、外置位置与两类清理均由 Mac
    原生选择器或确认窗执行。响应不得包含绝对路径或书签；Photos 原图副本清理继续受图库瘦身
    活动门禁保护，网络重试不得重复执行。
40. 网页选区的“准备特征”复用 Mac `AppSelectedAssetEmbeddingCaching`，Host 复核媒体类型与
    content revision，异步进度可取消；“查找相似”冻结选区后直接复用图库瘦身种子分析。网页
    不接收向量、媒体路径或 Photos identifier，相同 operation ID 不重复执行。
41. 网页“抽取样本并生成建议”复用 Mac `AppPersonalSampleSuggesting` 与同一审核仓储。有选区时
    Host 按浏览器提交的网格顺序复核并截断到当前配置上限；无选区时空 `assetIDs` 明确表示由 Host
    从完整图库抽样。活动可查询、取消并按 operation ID 幂等恢复，网页刷新不得重复生成；结果只
    进入现有待审核队列，不把模型、向量、路径或 Photos identifier 返回浏览器。
42. 网页审核总览的按标签“个人模型 / 超级个人”全库生成必须复用 Mac
    `AppPersonalTagLibrarySuggesting`、Embedding Cache、每标签阈值和最大待审数。Host 冻结并
    复核活动来源，只枚举尚未对目标标签做决定的候选；任务进度可查询、取消并按 operation ID
    幂等恢复。完成结果进入同一审核队列，网页不得接收模型、向量、路径或 Photos identifier。
43. 网页审核总览的 Feature Print 生成/更新入口复用训练配置与 Host 启动命令；活动任务只显示
    Host 权威允许的暂停、继续、取消动作。审核卡片可按 job/tag 定位关联训练 Run，训练详情可返回
    同一标签审核；任务动作与后台刷新不得丢失当前媒体、标签或 Run 定位。
44. 训练失败恢复使用 Host 生成的结构化、脱敏上下文和安全失败指引。Feature Print 新运行冻结
    标签与来源 ID；旧运行只恢复账本能够证明的字段，缺少或已停用来源必须显式重选，禁止退化为
    全来源。训练记录使用 roving focus 的列表框语义，键盘切换和异步刷新都不得改变当前 Run、
    滚动位置或把焦点丢到页面根节点。
45. 个人模型多标签批次采用逐标签独立提交：单标签失败或跳过不阻止后续标签，也不回滚已发布
    结果；每个标签保留独立 Run 和产物，账本另存脱敏批次清单以支持恢复。App 启动只终结依赖旧
    进程的个人模型孤儿 Run，队列持久化的 Feature Print Run 不得被误判中断。网页可逐项展示
    Host 状态并只重新配置未完成标签，但不得自动重启训练；批次投影和恢复上下文不得包含路径、
    书签、向量或 Photos identifier。
46. 个人模型批次状态不能只存在于进程内，也不能在短时 UI 提示结束后消失。Host 在 App 自有
    RemoteHost 目录保留最近 50 个脱敏批次，采用原子写入、完整文件保护与 0600 权限；单标签
    `training_run` 和产物继续是模型结果权威，批次账本只补足逐标签编排事实。Host 重建保留终态，
    把旧运行态收束为 `hostRestartInterrupted`，不得自动重放。网页可长期显示、定位关联 Run 和
    重配未完成标签；辅助账本禁止保存资产 ID、路径、书签、向量、模型内容或原始媒体标识。
47. 训练 Run 的常用界面事实必须由 Host 提供结构化安全字段：可读标签名、批次 ID/位置和样本
    统计不得要求浏览器解析任意 JSON。历史标签允许读取 Mac 权威仓储中的归档名称；旧载荷缺少
    新字段时必须继续解码并降级为单项记录。网页的全部/批次/单项筛选只改变本地显示范围，并与
    方法筛选组合；完整 Run、job、batch 和 tag 标识只进入折叠技术详情。所有投影仍禁止返回路径、
    书签、原始文件名、向量、模型内容或 Photos identifier。
48. 模型槽详情必须由既有 slot 与 Run 投影连接得出，不新增可能与 Mac 仓储漂移的浏览器版本
    状态。跨训练、审核和任务面板的往返使用结构化 run/tag/job ID 重解析目标，不长期依赖可能被
    重绘替换的 DOM 引用；返回时若原工作区仍存在则禁止无理由重建。任务列表可包含独立操作按钮，
    因此使用 list/listitem 与 roving focus，而不是把嵌套按钮塞入 listbox option。所有返回路径都
    必须恢复原工作区、选中项、滚动位置与可见焦点，并继续服从 Host 返回的 availableActions。
49. 网页通用设置只投影并修改 Mac 当前持有的同一组 observable settings model：本地模型启用、
    空闲缩略图预热和工具栏显示方式不得另存浏览器副本。`PUT /v1/settings/general` 只接受带
    `operationID` 的可选字段补丁，Host 持久幂等；启用模型必须等待 Mac 激活结果，预热开关必须
    同步当前 workspace runtime。公网地址、Host 开关、配对设备和账号白名单仍属于访问边界，
    只能在 Mac 原生设置中修改。网页以 Mac 紧凑设置层级展示这些边界说明，并支持 Command-,、
    Escape、方向键及关闭后焦点恢复；来源、存储、训练/审核和任务弹层在异步重绘后也必须按稳定
    ID 恢复焦点，不能依赖已被替换的 DOM 节点。
50. 网页建议阈值必须直接投影 Mac `SuggestionThresholdPort` 的三轨默认值、活动标签覆盖和参考值；
    默认、覆盖、继承与采用参考值均带 operation ID 幂等写入。搜索只改变本地可见标签，不重算
    参考分数；输入提交、异步刷新、快速关闭再打开和 390px 窄屏都不得丢焦点、永久禁用或横向溢出。
51. 来源侧栏右键与 Shift-F10 必须按 Host 来源类型和状态显示与来源管理一致的安全动作；方向键、
    Home/End、Escape 和点击执行后焦点可追溯。写操作继续复用 Mac 原生确认与 operation ID 幂等，
    不暴露本机路径；来源/存储面板在加载中快速关闭再打开不得永久停留在禁用状态。
52. 图库个人模型快捷入口必须与 Mac 一样只带入已确认的标签筛选；有选区时默认限定选区，
    无选区时默认全库。两种个人模型必须复用同一训练设置与启动端点；Host 不可用的方法不得
    可提交，也不得静默降级为另一方法。菜单、设置页和命令面板的关闭焦点必须可追溯。
53. 单张与多选检查器按 Host 标签组显示并可折叠；标签主体支持左键确认、右键清除、X 拒绝和
    Delete 清除，三态按钮仍可达。多选必须显示权威聚合状态并提交完整冻结选区；折叠和异步写入
    后焦点按稳定 ID 恢复。远程协议没有组内顺序前不得伪造拖拽排序。
54. 单张详情必须从 Review 端口投影全部待审 AI 建议及 feature/standard/personal/AdamW 来源；旧
    Host 缺字段仍可解码。网页默认显示 5 条并可展开，“属于/不属于”复用既有原子决定，写入后
    重新读取权威详情；异步重绘不得把焦点或检查器滚动位置丢回页面顶部。
55. 普通网页预览遇到 iCloud-only 时必须返回稳定的可恢复状态，不能自动下载。只有用户对当前
    单图点击后才调用显式 cloud-preview POST，并复用 Mac 的 2048px 标准预览能力与缓存；失败可
    原位重试，成功回到普通预览路由。合成测试需覆盖 409、下载失败和重试成功，且不得访问真实图库。
56. 无来源且无标签时，网页显示与 Mac 同义的三个首次使用动作；添加常用标签通过 Host 安装同一
    九标签集合，重复 operation ID 或标签已存在均不重复写入。安装不得扫描、分析或修改任何照片；
    成功后侧栏、标签管理和命令面板同步，宽屏与 390px 均可达且焦点可追溯。
57. 来源与同组标签排序仅写浏览器非敏感界面偏好，不调用图库写接口；跨组标签移动调用 Host 既有
    幂等命令，失败恢复原分组和顺序。侧栏、单图、多选检查器与选择器显示同一顺序，刷新后保持；
    拖放与 Option-方向键均可用，搜索期间不允许在不完整标签列表中排序，390px 不横向溢出。
58. 标签侧栏分组折叠刷新后保持，搜索只临时展开命中组；分组标题显示数量并支持方向键导航。单图
    与多选检查器均可直接组内排序和跨组移动，复用同一偏好及 Host move/失败回滚，完成后焦点留在
    原操作表面；不得因重绘触发标签决定或把检查器滚回顶部。
59. 标签侧栏普通点击、Command/Ctrl 点击和 Command/Ctrl-Option 点击分别实现并集、交集和排除，
    查询参数与视觉状态一致。标签及非系统分组的右键/Shift-F10 菜单必须复用既有筛选、重命名、
    归档、分组重命名与删除命令；菜单全键盘可用，确认取消、成功或归档后焦点按稳定 ID 恢复。
60. 网页来源菜单与来源管理面板补齐 Mac 的“预热缩略图缓存”和“专门用于原比例的缓存”。Host
    通过只读资产分页枚举和既有派生缩略图缓存端口执行，不读取后回传原图、不建立浏览器缓存真相；
    原比例预热跳过已存在缓存。运行快照必须包含完成、总数、成功和失败计数，网页关闭管理面板后
    仍在顶部显示进度并允许重新打开或取消。取消为协作式取消，相同 operation ID 和重复取消不得
    启动第二项工作；来源失效、分页停滞和逐项失败都必须收束为可解释终态。
61. 网页来源菜单与来源管理面板按 Mac 来源类型补齐“请求照片写入权限…”和“更新回收权限…”。
    网页只提交来源 ID、动作和 operation ID；Photos 系统授权、文件夹选择器及安全作用域书签仍由
    Mac 原生界面完成，浏览器不得接收路径、书签或 Photos 标识。Host 必须先校验来源类型与可用
    状态，取消、拒绝、受限和成功均返回可解释终态，同一 operation ID 重放不得重复唤起系统界面。
62. 图库为空且没有搜索、标签、状态或格式条件时，网页必须按当前来源类型和状态显示与 Mac 相同的
    恢复语义：活动 Photos 可立即同步、旧 Photos 可连接当前图库、待授权 Photos 可重新授权，活动
    文件夹可立即重扫、失效文件夹可重新授权。动作仍经来源管理和 Mac 原生确认执行；网页不接收
    路径、书签或 Photos 标识。仅来源投影变化也必须重绘空页面，不得依赖资产列表同时变化。
63. 网页全屏预览复用 Mac 单图模式的连续导航语义。图库或审核到达已载入窗口末尾且 Host 仍有
    下一页时，“下一张”保持可用并先扩展当前窗口；图库单图每次移动同步底层主选中项、检查器和
    返回焦点，关闭后回到当前照片而非打开预览前的旧照片。快速连续方向键串行执行且不丢按键；
    返回按钮按上下文显示“返回网格 / 返回审核 / 返回分析 / 返回地图”，原始媒体仍不进入长期缓存。
64. 网页审核队列复用 Mac 图库的选择语法：普通点击设为单选，Command/Ctrl 切换，Shift 连续区间，
    Command/Ctrl-Shift 追加区间，空白框选和 Command/Ctrl-A 选择当前已载入窗口。多选时检查器仍以
    主选中项提供预览，但 P/X 必须把队列顺序冻结后的完整选区一次提交给既有批量决定端点；U 不写
    决定、不重排队列，只前进到下一未选项并收束为单选。刷新、分页和旧请求返回只能保留仍有效的
    选区、锚点和主选中项。普通标签批量确认、拒绝、清除与新增并应用继续采用 Mac 的“即时执行 +
    最近一步撤销”，不得额外弹出确认框；涉及不可逆删除或原生系统授权的既有确认边界不变。
65. 网页撤销能力必须与 Mac 一样区分“标签操作”和“审核操作”。Host 为两类决定保留独立的进程内
    快照和幂等撤销端点；标签写入不能让尚未使用的审核撤销失效，反之亦然。桌面全局工具栏显示
    标签撤销并在存在审核凭据时显示审核撤销；全屏审核标题栏必须原位提供审核撤销，不能要求先退出
    工作区。窄屏可收束为图标并在命令面板保留同名入口；Toast 只能调用产生该凭据的对应端点。
66. 普通图库视频卡必须显示播放标识和 Host 投影时长；鼠标悬停短暂延迟后使用受保护媒体路由静音
    循环播放，同时最多只有一个悬停播放器。离开、滚动、切换模式、打开单图、失焦或退出必须释放
    媒体元素；悬停不得触发选择、请求检查器详情、改变滚动位置或重建网格。账号模式仍只通过内存
    Service Worker 凭据桥授权；触控与减少动态效果环境不得自动播放。
67. 网页世界地图必须与 Mac 一样按来源显式提供旧照片位置回填，并展示来源状态、目录覆盖率、
    已定位/无坐标计数及 reconcile 进度。开始、重试和取消必须由 Host 执行并按 operation ID 幂等；
    打开地图、打开或关闭面板、轮询和网络重试均不得隐式开始或误取消任务。浏览器不得获得路径、
    Photos identifier 或原始 GPS 载荷，回填不得写回原照片。
68. 网页世界地图必须与 Mac 使用同一地点标签缓存、搜索与确认事务。打开“补全地点”只能读取本地
    缓存；只有用户提交搜索时才可发送当前地点描述，且不得附带照片、路径或资产标识。候选确认必须
    使用 Host 返回的 opaque place ID、保持 GPS 优先并按 operation ID 幂等；过期候选不得静默接受。
    搜索期间允许继续编辑，完成后原位显示结果来源、恢复输入焦点和滚动位置；进行中提示必须引用
    实际已提交查询。候选支持方向键、Home/End 与 Enter；晚到的缓存读取不得覆盖搜索或确认后的
    更新。390px 不得横向溢出。

## 停止位置

本决策仍停止于单用户、单 Mac、现有 Cloudflare Tunnel，不扩展为云端多主系统。下列
能力不属于 Web Companion 对齐范围：

- Mac 离线可用、云端数据副本或推送唤醒；
- 多 Host、多租户、Cloudflare Access 或应用层端到端加密；
- 在网页中直接绕过 macOS 授权面板、文件选择器或受保护数据确认；
- 在浏览器保存图库数据库、原始照片副本或长期账号密码；
- 原生 iOS 工程改造。

来源管理、Photos 授权、训练、缓存与瘦身不再被整体排除，而按上述三类边界分阶段接入；
不可逆删除只有在 Mac 端已有安全契约、网页二次确认和可审计结果后才可进入单独 ADR。
