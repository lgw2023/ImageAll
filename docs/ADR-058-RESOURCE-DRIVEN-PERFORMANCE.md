# ADR-058：图片与模型流水线由系统资源调度

- 状态：Accepted
- 日期：2026-08-11
- 范围：图库图片加载、个人模型图片预取、派生图片磁盘缓存
- 安全边界：不改变来源授权、缓存完整性、取消/去重、页面状态或受保护真实照片规则

## 背景

ADR-057 为阶段性回归安全冻结了界面缩略图 4、底层网格 16、预览 4 的固定并发值，并保留派生图片
20 GiB 总量配额。个人模型批处理还把图片预取固定为 2，运行时再硬截断到不超过 4。这些常量与机器的 CPU、
内存、存储和底层框架实际调度能力无关；高性能机器会被提前限速。派生缓存每次发布还会查询已发布总字节数，
即使磁盘空间充足也可能因达到固定配额而淘汰仍可复用的对象。

个人化建议与标准建议每个持久化批次又逐资产读取相同形状的目录处理上下文，形成 N+1 SQLite 往返。

## 决策

1. 生产工作区与 `LibraryAssetImageLoader` 不再构造固定并发闸门。不同键请求立即提交给 Swift executor、
   PhotoKit、ImageIO 和文件系统调度；相同键仍共享一个底层任务，离屏取消和全部等待者取消语义不变。
   小并发闸门只作为测试注入 seam 保留，不是生产配置或回退默认值。
2. 个人模型每个既有持久化批次内立即启动全部待加载图片，不再接受或截断固定预取并发参数。64 项持久化批次
   继续作为事务、租约、进度和取消检查点边界，不是资源并发上限；Core ML 与缓存发布原有串行完整性边界不变。
3. 派生图片缓存删除 20 GiB 已发布总量判断和发布前总量查询。缓存总量无应用层上限；仅当卷实时可用容量
   不能同时容纳新对象与 `max(5 GiB, 卷容量 5%)` 安全余量时，才在规范缓存根内按既有 LRU 回收可重建对象。
   容量事实不可用时继续 fail closed。512 MiB 云端下载预览隔离配额不属于本决策，保持不变。
4. 个性化后台按现有批次一次读取全部资产处理上下文，再以资产 ID 映射复用；资格、决策、目录截止时间、
   内容修订和检查点计算保持逐资产同值判断。
5. 相似度扫描用集合判断待分析资产与种子成员，并按捕获日桶的成员直接构造向量子集，避免对每个桶重复过滤
   全量向量字典；桶顺序、成员顺序、阈值、召回、完整链接和进度语义不变。

## 验收标准

1. 默认工作区和底层加载器可让超过原 4/16 上限的不同键合成请求同时进入底层服务；相同键仍只执行一次。
2. 个人模型批次的全部图片加载可同时进入来源闭包，输出顺序、失败占位和缓存结果不变。
3. 逻辑已发布字节超过 20 GiB、但卷资源仍满足安全余量时，不发生配额淘汰；低空间回收与写入失败合同继续通过。
4. 128 个资产的冻结处理上下文只执行一次读取，并在五次暖运行中位数上至少比逐资产读取快 20%。
5. 相似度聚类与待分析资产结果继续通过既有捕获日分桶、种子查询、阈值和进度回归。
6. 隔离构建和定向回归只使用临时数据库、临时缓存与合成图片，不访问 PhotoKit 或受保护真实照片。

## 后果

快速滚动或大批次会更积极地向系统提交工作，峰值资源占用可能高于旧固定值；这是选择“由机器资源决定吞吐”的
直接结果。请求去重、Swift 任务取消、系统调度、卷容量准入和安全余量仍提供自然背压与失败边界。若未来需要
用户可控的节能模式，应作为显式产品模式另立 ADR，不能静默恢复固定默认上限。
