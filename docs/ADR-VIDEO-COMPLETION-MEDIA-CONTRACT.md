# 视频补全决策：跨端媒体域与旧协议兼容

日期：2026-09-27。状态：实施中。范围：P1 第一切片。

生产领域已保存 `MediaKind`，但摘要与详情仅传资源格式 `mediaType`，网页以 MIME 前缀判断，导致 `public.mpeg-4`、`com.apple.quicktime-movie` 等真实 UTI 不能进入视频分支。

摘要与详情新增可选 `mediaKind`，Host 从领域事实明确投影 image / video；不修改 `mediaType` 的现有语义。可选字段允许新客户端解码旧 Host；旧客户端按既有 Codable / schema 忽略额外字段。

消费方优先使用显式媒体域。旧 Host 仅使用已知 UTI 白名单及 image/、video/ MIME 类型兼容推断；未知格式保持未知并显示不可用，不能默认当照片。协议未知的新媒体域不回退猜测。HTTP Content-Type 仍由媒体路由决定。

本切片不重写播放器或标签系统。协议兼容测试与 Web 消费分支证明这条契约，播放资源生命周期、Mac/iPhone 入口及持久整理闭环在后续 P1 切片验收。网页实现保留在专用工作区，主线集成单列，不因分支通过宣称目标完成。

## P1 Mac 共用播放器（2026-09-27）

图库、审核和瘦身大图使用同一个 `LibraryVideoViewingSession` 与 `AVPlayerView` 组件，复用 `LibraryVideoPlaybackProviding` 的本地只读资源租约，不另建来源数据库。系统控件负责播放／暂停、进度、音量和全屏；速度限定 0.5 / 1 / 1.5 / 2 倍。打开不自动播放，避免切换资产时突发原声；保留显式系统播放器入口。

前台播放器与静音悬停互斥。资产／内容修订切换、关闭、来源／媒体域切换与 App 失去焦点均清理当前 item 和租约；失焦后返回以新请求重新读取，播放仍由用户触发。异步准备使用请求身份检查，迟到的资源只释放，不接到新选择。旧视图拆卸仅可停止匹配的资产与修订。

本阶段仍采用既有 PhotoKit 本地 URL 路径，不触发 iCloud 下载；云端不可用单独提示。编辑后的非 URL AVAsset 支持与显式下载由 P2 明确。瘦身投影尚无修订字段，因此每次打开重新获取当前资源；后续完整字节去重必须补齐执行前的来源／内容修订复验，不能将此播放器视为去重证据。

## P1 iPhone 认证视频流（2026-09-27）

AVPlayer 不接收 Bearer URL、查询参数凭据或非公开的 AVURLAsset 请求头选项。`RemoteVideoPlayback` 通过内部 `imageall-video` scheme 的资源加载委托，复用 `RemoteLibraryClient` 的配对请求头、TLS pinning 与禁止重定向的 transport。单次读取上限 256 KiB，生产 URLSession transport 在读取过程中限制大小并取消未读响应；加载器串行处理分段请求，不保存整段原件或持久视频缓存。播放器前向缓冲提示 10 秒，此提示不代表系统解码器内存的严格配额。

能力通过新增可选 `videoRangeStreamingVersion=1` 字段声明，不增加会导致旧 Swift 客户端枚举解码失败的 capability 值。缺字段的旧 Host 明确显示升级提示。媒体路由在提供器具备修订事实时返回 `X-ImageAll-Content-Revision`，带 revision 的请求必须匹配；播放器拒绝没有修订头、修订变化、Range／长度／媒体类型不匹配的响应。旧无 revision 请求继续按既有路由服务。该目录修订保护不是完整文件摘要证据，来源文件同修订下外部改写的精确去重保护仍属 P4。

切换资产、退出预览、断开连接与进入后台时清空 AVPlayerItem 并取消加载请求。同一视频的标签／收藏刷新在媒体身份与修订不变时保持播放位置；不会因为更新整理事实自动从头加载。视频邻居不进入照片预览预取。云端原件不可用明确报错，不授权或触发下载。

## P2 文件夹视频内嵌时间与位置（2026-09-27）

P1 的 Web 资源集成与各端 UI 验收保留未完成状态；为缩短到最终可运行功能的路径，先并行推进不依赖这些事项的 P2 元数据纵切片（仍由同一代理顺序实施）。不据此跳过 P1 门禁。

- 复用 `FolderVideoMetadata` → `FolderMediaMetadata` → reconcile → `asset` / `asset_location`，不创建第二份位置事实。
- 时间优先 QuickTime `creationdate`，再读取标准 common creation date。只解析带明确 UTC 或偏移的 ISO 8601 字符串，保存 UTC 毫秒；无时区、缺失与畸形值保持 nil，不用文件时间或本机时区猜测。遵循 ADR-069。
- GPS 读取 QuickTime ISO 6709 十进制度格式，校验纬经度边界，允许可忽略的高度；度分秒和不明后缀明确不解析。本地来源仍登记现有 `embeddedGPS` provenance。缺 GPS 不影响视频可用性。
- 宽高继续使用视频轨 preferredTransform 后的尺寸；测试覆盖旋转 90 度。读取容器元数据不解码全片，不写来源媒体。
- 本切片覆盖新扫描及已有 reconcile 读取路径。历史有界回填、技术规格存储／展示、筛选、地图媒体范围与显式云端获取仍属 P2 后续必需工作；不能用本次提取通过代替整阶段完成。

### P2 历史文件夹视频策略版本（2026-09-27）

复核发现旧视频已有 `asset_location` 空结果且文件指纹未变，原复用条件只判断照片的位置行，导致升级后视频元数据读取器永远无法触达这类旧资产。增加 V053 `asset.video_metadata_version`（默认 0），不改历史 migration。当前策略版本 1 随分类观察与其数据库批次原子提交，识别但不可读的视频也记录已尝试版本，避免无变化的损坏文件每次重读。

下次现有来源扫描经过旧视频时，版本不足才重新读取容器；版本达标且指纹相同时复用观察，包括明确缺失的时间／位置，不因 nil 无限重读。沿用已有来源重新扫描入口、批次进度、检查点、取消和重试，不额外启动全库任务；版本升级本身不读取来源。元数据补读不改变内容修订号。稳定内容下仅填补尚无坐标／place_id 的位置记录，保留更丰富的现有位置。照片复用规则不变。

该机制覆盖已有扫描任务的历史视频补读；地图回填入口仍需扩大媒体范围和统计，技术信息字段仍是后续必需工作。本轮不将这些缺口计为通过。

### P2 视频技术信息（2026-09-27）

- V054 为 asset 增加可空技术信息 JSON，包含视频轨 FourCC 编码、标称帧率、轨道估算码率、音轨数量。采集读取容器轨信息，不解码整段内容。未知或非正有限值保持 nil；音轨计数零仅在容器已成功读取且确实无音轨时保存，不把未分析资产标记静音。
- 策略版本升至 2，继承 V053 的按需补读与批次事务。不改写 V053 或历史 migration；未变化且已是版本 2 的视频继续复用技术信息。媒体容器格式和文件字节大小沿用独立字段。
- Mac Inspector 展示已读取技术信息，标称帧率不承诺恒定帧率，估算码率不宣称精确文件平均码率。RemoteAssetDetail 新增可选 `videoTechnicalMetadata`，旧 Host 缺字段仍可解码；iPhone 信息面板展示编码、标称帧率与音轨计数。Web 消费方已在独立 worktree 同步 schema 与 Inspector，再以三文件补丁集成 main；生成资源仍留在 Web worktree。
- PhotoKit 尚未做该技术信息提取时显示未知／尚未读取，不凭封面或已有时长猜测。这是明确待补能力，并非整个 P2 完成；获取原件仍遵守显式授权边界。

### P2 原生视频筛选与数值排序（2026-09-27）

- 首版时长条件为少于 1 分钟、1 至 10 分钟（不含 10）、10 分钟及以上；方向基于已归一化的显示宽高，分横屏、竖屏和正方形。缺失尺寸／时长不猜测，选择相关条件时不命中。视频条件在 SQL 内显式限定 video，切回照片清空条件，避免污染照片计数。
- 新增时长和文件大小双向排序；未知值一律后置，值相同时资产 ID 同方向排序。使用独立数值游标 payload，继续 keyset 分页；不同排序之间拒绝复用游标。界面改变条件时重新加载首屏。
- 文件大小来自已登记 fingerprint，未记录大小的 PhotoKit 资源排在未知组；不为了排序下载或打开原件。大小查询使用文件指纹主键子查询，未新增冗余尺寸事实。当前未宣称大库性能验收，后续集成若发现可复现主路径排序延迟再优化索引路径。
- 先交付 Mac 原生入口与共享目录查询；Web／iPhone 条件、排序入口和 Host 能力声明仍需独立对齐，不通过旧 Host 的默认排序冒充支持。


### P2 远端视频查询与 iPhone 入口（2026-09-27）

- 共享请求新增可选 videoDuration / videoOrientation，四种数值排序与 Mac 目录查询一致。Host 用可选 `videoQueryVersion = 1` 声明支持，不新增旧客户端无法解码的 capability 枚举值。旧请求缺字段继续不限；新客户端不向旧 Host 发送这些条件。
- Host 对未知排序、时长或方向值返回 400，禁止静默回退为默认排序或忽略视频条件。共享客户端按标准 query 编码条件，未选择时不发送。
- iPhone 能力门控后开放时长、方向及数值排序；选择视频条件／时长排序自动限定视频，切离视频清空视频条件与时长排序。文件大小排序适用于照片和视频，未知值后置沿用目录契约。能力缺失而仍有残留新条件时明确报错，不进行未筛选查询。
- Web 查询入口仍需在独立工作区补齐。iPhone 模拟器构建和共享链路测试不代替真机 UI 验收。


### P2 Web 查询入口（2026-09-27）

- Web 识别 `videoQueryVersion=1` 才显示时长／方向与数值排序。新条件进入 URL、分页 query key 与选择缓存身份；改变条件重建首屏。选择视频条件自动限视频，切回照片清空条件和时长排序；文件大小排序仍适用于两种媒体。
- 收藏链接若携带新条件而 Host 未声明支持，查询明确失败且不发送资产请求，提供“重置视频条件与排序”恢复入口。能力加载完成前不冒险发送这些请求。
- 检查发现“分析当前筛选”与种子分析的跨页范围 DTO 尚未承载视频时长／方向。因此本轮在条件生效时明确阻止这两个跳转，防止未经选择的资产被分析；后续分析切片必须补齐范围传递，不能把本提示作为目标完成。当前已选资产的普通标签／收藏操作仍沿用精确 ID 范围。
- 只集成 Web 源码／测试补丁；生成资源留在独立 worktree，生产内置网页资源更新仍是 P1/P7 待验项。


### P2 地图媒体范围契约（2026-09-27）

地图聚合、点选列表、跳转图库必须携带相同的 photos / videos / all 范围。未带字段的历史查询仍解释为 photos，防止旧界面把视频计入“照片”数量。范围属于查询和缓存身份，缩小点选数量时保留；坐标、可用性、回收隐藏与视口裁剪规则不因视频放宽。

本切片先统一共享目录查询与可选范围的回填只读统计，明确不把后台支持计为 UI 或 Companion 完成。既有 photoCount / eligiblePhotoCount 等属性在显式 videos / all 查询中代表所选范围的资产数；新界面必须使用对应范围的数量单位，旧界面仍只发照片查询。后续须接媒体选择器、跨端协议、视频详情及回填统计，不能只改 SQL 后宣布地图已完整支持视频。


### P2 原生地图范围与预览（2026-09-27）

原生地图显式选择照片／视频／照片与视频，数量统一用“项影像”；切换范围清除旧聚合、选择与弹窗，防止旧结果短暂冒充新范围。点选资产带媒体域及内容修订；视频弹窗复用受控 LibraryVideoViewer，网格封面继续只读缩略图。地图跳转图库保留空间及媒体范围；混合地图以空媒体限制打开混合列表，用户再选择照片或视频时缩小同一空间范围。旧照片默认与测试保留。回填面板、远端范围传递和混合分析入口仍需后续对齐。


### P2 原生位置回填范围（2026-09-27）

原生回填面板读取照片与视频的来源统计，显式启动同一来源的既有扫描任务；打开面板不自动扫描，取消／重试仍沿用持久任务。新增带 mediaScope 的 service 方法；旧无参数方法与旧远端命令保留照片统计及旧启动条件，避免旧客户端误解混合数量。

文件夹视频的历史“无坐标”行若元数据策略版本过旧，不算已检查；已知坐标或当前策略已检查的缺失结果均算已检查，避免无 GPS 视频无限回填。该检查只读目录库，不读取原媒体；实际扫描仍通过既有只读分类与批次事务。PhotoKit 位置观察继续使用原授权路径，面板不请求云端原件。


### P2 远端地图媒体范围（2026-09-27）

可选能力字段 worldMapMediaScopeVersion=1 声明地图聚合／点选／图库范围支持 photos、videos、all；旧 capability 枚举不变。聚合 GET 使用 mediaScope，点选 query JSON 使用可选 mediaScope，图库 GET 使用 worldMapMediaScope 并必须同时带完整空间桶参数。缺字段仍为照片，未知值明确 400。地图点选资产新增可选 mediaKind，保持媒体域独立于文件名。

现有 photoCount 等 JSON 键保留以兼容旧客户端，新范围请求的值代表所选范围资产数，客户端需据能力版本使用影像／视频数量文案。新共享客户端将完整地图空间条件、视口边界及媒体范围编码到图库请求；此前 DTO 有该字段但客户端没有发送，现补齐。版本 1 仅涵盖上述地图查询，回填混合统计／命令和 Web 范围入口仍需后续单独接入。


### P2 Web 地图范围入口（2026-09-27）

Web 仅在 Host 声明 worldMapMediaScopeVersion=1 时开放照片／视频／混合范围。范围进入地图 URL、聚合查询缓存、点选查询和图库空间 URL；详情页携带相同空间上下文。带新范围的收藏链接遇到旧 Host 时明确失败并允许切回照片，能力确认前不发送可能扩大范围的请求。默认照片查询保留既有失败重试。

计数统一使用项影像，共享原生地图渲染器的键盘导航与提示文案同步；回填面板仍按既有照片协议工作，不以地图查询版本暗示混合回填已支持。主线仅集成源文件补丁，生成网页资源继续留在独立 Web worktree。


### P2 远端位置回填媒体范围（2026-09-27）

新增可选 worldMapBackfillMediaScopeVersion=1，独立于地图查询版本。统计 GET、启动／取消命令及返回 snapshot 支持可选 mediaScope；省略仍是照片语义。旧计数字段名保留，但值对应请求范围。启动条件复用生产 scoped service，任务本身仍是整个来源的扫描，取消也按来源生效。范围加入幂等身份；同 operationID 换范围返回 conflict，不能重放别的范围结果。

Web 面板跟随当前地图范围，缓存及变更响应按范围隔离；不支持新版本时视频／混合范围不请求统计或允许启动，显示恢复说明。打开面板只读状态，只有显式动作才提交命令。选定范围元数据统计与全来源任务进度分别呈现，不把全来源扫描数量冒充视频统计。生成资源留在独立工作区，实际来源扫描／云端下载没有作为本轮自动化验收。


### P2 本地播放资源技术信息（2026-09-27）

查看器在既有本地资源授权成功后，异步读取 AVAsset 的编码、标称帧率、轨道估算码率和音轨数。播放可用状态先发布；技术信息读取失败不阻止播放。显示正在读取、读取失败和字段未知，且不将没有音轨误称为音频内容分析完成。切换／关闭／旧请求返回时以同一播放请求身份隔离并清除信息。

此入口覆盖文件夹与本地 PhotoKit 已获取的播放资源，不请求新云端权限，不在目录枚举时打开原件，不写源媒体或猜测值。信息属于本次播放资源观察，暂不持久化到目录；PhotoKit 详情持久技术字段及跨端消费仍为后续缺口，不能以本入口代替完成所有 P2 技术元数据要求。


### P2 原生显式云端视频获取（2026-09-27）

本地视频加载报告 cloudOnly 后，查看器提供“从 iCloud 获取当前视频”，确认时签发单次前台 PhotosCloudDownloadGrant 并绑定资产／修订。普通打开、重载、切换及后台恢复均不携带 grant，仍禁止网络。确认提示流量、本机空间及系统缓存边界；不会批量下载。仅原生入口先接入，不把照片 cloud preview 协议当成远端视频获取。

PhotoKit 使用原件版本 requestAVAsset、显式允许网络并报告进度。下载返回必须为本地文件；provider 复核同一来源、定位符、媒体域、可用性及内容修订，拒绝失配。系统管理原件，本 App 不复制、删除或承诺清除 Photos 缓存；取消停止当前 PhotoKit 请求及等待，不能承诺回收已由系统取得的数据。

准备资源任务由查看器会话持有，取消／切换／关闭／进入后台会传递取消；迟到资源释放、进度按请求 ID 隔离且单调显示。确认面板也绑定原资产，不能跨选择误用许可。进入后台后恢复仅本地重试，云端再次获取需再次明确操作。自动化使用 fake PhotoKit 与合成视频，绝不为了验收调用真实 iCloud。

空间策略为单个前台请求，原件大小和 PhotoKit 缓存所在卷不通过私有 API 推测；由 Photos 管理落盘与可用空间，明确映射系统空间不足错误并停止本次获取，不承诺固定字节配额或自动清缓存。非 AVURLAsset（如编辑合成资源）明确拒绝并提供“照片”播放／导出文件路径，避免通用失败掩盖支持边界。


### P2 PhotoKit 播放观察的按需持久化（2026-09-27）

已获准的本地视频播放资源读取技术信息后，可按 assetID + contentRevision 条件写回当前可用 PhotoKit 视频行；来源必须 active，历史定位符、照片、旧修订均拒绝。仅更新技术 JSON 与目录记录时间，不修改内容修订、媒体日期、标签或源文件。技术信息写入失败不影响播放，当前播放信息仍可查看；不得据此声称写入成功。

原生当前 Inspector 在写入成功后重新查询，共享 Host 详情沿既有 DTO 投影读取持久字段。此路径不为获取元数据额外下载原件、不在枚举时打开视频，不自动补全全库。PhotoKit reconcile 判断内容变化并增加修订时清空旧技术 JSON；未变内容保留观察结果，下一次本地播放可重新填充。


### P2 远端视频失败原因与恢复（2026-09-27）

保留原有 HTTP 404 / notFound，错误 JSON 增加可选 mediaFailureReason，区分 cloudVideoOriginalRequired 与 unsupportedVideoRepresentation；旧错误缺字段继续可用，旧客户端可忽略附加字段。Host 仍只读取本地原视频，不接受远端隐式下载。客户端对云端原件明确引导到 Mac ImageAll 确认获取后重试，对编辑合成资源说明“照片”播放或导出文件路径。

### P2/P3 智能推流的跨媒体证据与排序（2026-09-27）

复核发现候选已混合，但排序硬编码检查 image 模型，已确认样本也跨域混计。排序现按候选所涉及的每个媒体域检查既有 tag_model／personal_suggestion_model 行，只有全部域均有模型才视为已覆盖；混合组的样本稀缺度取各候选域已确认样本数的最小值，避免大量照片样本掩盖视频零样本。其余标签组亲和度、候选数、时间及 ID 稳定排序保持原规则。模型存在只用于排序，不证明模型质量或可执行就绪，也不调用模型。
