# 视频完整原件字节证据

日期：2026-09-28。状态：已决定，分阶段实施；显式任务与文件夹精确组清理已接线并通过合成验证；Photos 原件资源与完整原生运行验收尚未完成。

## 问题与选择

视频代表帧摘要只能说明代表帧相同或相近，不能证明整个文件相同。保留现有 `asset_similarity_fingerprint` 的视觉含义，新增 V055 `asset_original_content_digest`；旧摘要和手机归档摘要不自动提升为当前图库原件证据。

完整文件扫描只由显式视频分析触发，不加入后台代表帧补全。首段实现文件夹原始文件 SHA-256，单任务顺序处理资产，单文件 256 KiB 缓冲，分块进度与取消检查。来源沿已授权文件夹根，逐层 no-follow 打开，不跟随链接，不修改来源。

摘要绑定资产修订、来源、相对路径、大小、目录 mtime、catalog resource ID，以及当前设备／inode／ctime 和句柄原始 mtime。目录 mtime 使用既有 Foundation 表示，句柄身份另保留原始纳秒值，避免两者精度差异误判。重用也必须重新打开当前 locator 并核对物理身份；ctime 防止写入后恢复 mtime 造成误用。读后核对打开句柄和重新打开的路径，再在同一数据库事务中复核媒体、修订、来源可用性和文件事实。失败的复核移除该修订旧证据，取消不发布本次摘要。

## 使用边界

完整摘要独立于视频解码能力、代表帧和视频时长。只有原件证据相同且字节数相同，才能形成完整文件相同分组；同封面、转封装或多帧相似不构成此证据。清理前仍必须执行既有身份、授权、收藏保护及回收／恢复复核，缓存本身不能授权删除。

PhotoKit 需要另行明确原始资源类型与版本，并通过禁止网络的原始资源通道读取；播放 URL 或 AVComposition 不自动视为原始文件。当前 migration 只接纳 folder-original-sha256-v1，不能向该字段写入 Photos 或视觉派生摘要。Photos 支持须通过后续 migration 扩展来源契约。

## 验证

使用临时数据库和自建目录，检查分块边界、SHA 对照、重复读取重用、视觉指纹不变，覆盖取消、原地改写、路径替换、数据库修订变化，以及恢复 mtime 后不误用旧摘要。后续接线必须补完整分组和明确保留／回收／恢复闭环，不能以摘要单元测试替代 P4 验收。


首段验证已通过：摘要与分组 6 项、migration 4 项。完整文件组从新表读取，不要求先有代表帧，并校验目录修订／路径／来源／文件事实；视觉分组不提升为原件证据。素材为合成字节文件与 stub 代表帧，证明摘要和分组语义，不证明真实容器解码或重封装运行。显式任务接线见下节；回收前完整证据复核和 PhotoKit 原件通道仍待完成。


## 显式任务接线与兼容（2026-09-28）

新建视频分析任务保存 originalVideoDigestPolicy，只有匹配当前策略的任务调用完整原件服务；旧任务缺少该字段时保持代表帧路径，未知策略明确拒绝。照片任务和后台 completeAsset 不新增完整视频读取。原生分析帮助与 Inspector 说明当前文件夹完整摘要、Photos 代表帧范围。

每个文件顺序处理，并复用现有租约心跳；分块检查暂停／取消，续期保留当前文件 ordinal，恢复时重新校验当前文件。字节进度持久到 checkpoint，在原生任务字幕展示；远端仍展示项目级进度，字节级呈现与完整范围文案需后续对齐。控制检查可能访问任务队列，不在摘要数据库写事务中调用，避免与心跳持锁写入形成锁循环；提交后再次检查控制请求，取消时移除本次证据。

完整摘要不依赖视频时长或代表帧解码。任务测试使用缺少时长的合成字节文件，暂停／恢复后仍得到完整字节相同组；取消不持久化当前摘要或任务完成结果。清理证据仍走原有只接受图片原件的门禁，未在此切片放开视频一键清理；必须先补清理前视频原件复核与回收恢复验证。


## 回收／恢复与快速删除的原件校验（2026-09-28）

视频资产存在独立原件证据时，回收、恢复和快速删除读取当前修订／来源／路径／文件事实匹配的摘要，显式标记为必须校验摘要。证据存在但已过期时不得退回只有 resource ID 的路径，应拒绝操作并要求重新核对。没有原件证据的既有手工视频整理保留原契约。

快速删除此前在 resource ID 存在时跳过 SHA 校验；带强校验标记时即使 resource ID 可用，也必须以固定 64 KiB 缓冲重新哈希文件。源文件在最终移动或删除前检查设备、inode、大小、mtime 和 ctime；恢复 mtime 不能掩盖 hash 后的写入。同卷移动与恢复也补最终句柄元数据复核；跨卷继续沿既有复制、目标摘要、源端重验与持久化路径。

11 项 fixture 测试通过，覆盖完整摘要→回收→恢复、过期修订、同长度写入后恢复 mtime、hash 后写入竞态、同卷与跨卷回归、恢复防篡改、快速删除及收藏策略。仍未放开视频一键精确组计划：还需将独立证据接入组成员／保留项的物理复核，并验证带收藏保护的整组保留／回收／恢复。

## 文件夹视频精确组清理（2026-09-28）

清理计划从独立原件表加载视频证据，不依赖代表帧是否成功；照片继续使用原有原件／视觉指纹契约。计划记录媒体类型和原件物理身份，同一组不得跨照片／视频域。视频只允许完整字节相同且大小相同的组进入自动清理；代表帧视觉匹配即使为 100% 也不允许。收藏保留规则复用既有策略。

执行前重新核对整个计划的当前修订、来源、定位、摘要和收藏，并在取得交互 I/O 优先权后再次复核。视频保留项和待清理项均使用已有只读来源授权打开真实 locator，以设备／inode／ctime／mtime／大小、目录指纹及当前原件表检查缓存证据仍属于该文件；复核不重新发布摘要，也不要求保留项具备写权限。实际移动／删除仍以固定块重新计算待处理文件 SHA-256。

整组预检失败时不修改任何成员。批次中每个视频副本开始处理前，再检查该项及全部保留项；保留项消失、替换、修订变化或待处理项新设收藏时停止相关剩余副本。已完成的回收继续遵循既有可恢复记录，快速删除保持用户已确认的不可恢复语义，不宣称多文件文件系统操作原子。外部程序可在检查后继续改写文件，不能把这些复核宣称为对其他进程的排他锁。

## PhotoKit 本地原始资源（2026-09-28）

Apple 将 [`PHAssetResourceType.video`](https://developer.apple.com/documentation/photos/phassetresourcetype/video) 定义为原始视频数据，而 [`fullSizeVideo`](https://developer.apple.com/documentation/photos/phassetresourcetype/fullsizevideo) 可为编辑版本。本实现只选择唯一 `.video`；不退回播放 URL、AVComposition、`.fullSizeVideo` 或 Live Photo 的 `.pairedVideo`。资源列表、资产修改／创建时间、时长和尺寸构成资源描述摘要；读取完成后重新获取资产并复核。编辑状态单独记录，原件相同不得宣称编辑效果相同。

使用 `PHAssetResourceManager.requestData` 逐回调哈希，应用不累积完整视频、不写原件缓存；回调块大小由系统控制，不能宣称 PhotoKit 总内存有固定上界。请求显式 `isNetworkAccessAllowed = false`，网络必需错误转换为云端不可用；[Apple 的选项说明](https://developer.apple.com/documentation/photos/phassetresourcerequestoptions/isnetworkaccessallowed)确认该设置禁止请求下载云端资源。顺序任务每 100 ms 检查暂停／取消并取消 PhotoKit 请求；连续 300 秒无数据进展视为不可用。未有公开稳定的资源字节修订号，因此每次显式扫描的第一轮重新读取，不以元数据缓存跳过原件哈希；同一任务后续仅用于补代表帧的轮次不重复读取完整 Photos 视频。

追加 V056 独立 Photos 原件表，V055 和历史摘要均不改写、不自动提升。记录当前资产修订、来源、Photos localIdentifier、资源描述、编辑状态、字节数、SHA、核验时间，以及云端／不可用／不支持／变化的跳过状态。取消清除本次修订证据；源修订改变不发布旧读结果。分组将两类完整原件摘要按 SHA 与大小比较，仍只限视频域。

新视频任务使用 `video-original-sha256-v2`，旧 `folder-original-sha256-v1` 仍只读取文件夹原件，无策略的历史任务仍走代表帧。分析结果持久保存 Photos 云端跳过、不可核验及编辑原件数量，并在 Mac 状态说明中展示。Photos 资源没有公开可靠总字节数时，进度显示已读取字节而非伪造百分比。

Photos 视频精确组当前只提供原件比较结果，尚不进入自动清理计划；需下一切片完成资源与保留项执行前重读、编辑资产保护和系统删除／恢复验证。该未完成项仍属于 P4，不能以文件夹门禁替代最终 Photos 支持。真实 Photos／iCloud 操作保持 NOT_RUN；自动验证只调用注入的合成资源 reader 与纯策略／流式哈希状态，不创建或读取用户 Photos 资产。

## Photos 精确组清理与编辑保护（2026-09-28）

Photos 的完整原件证据接入同一精确组计划，绑定当前修订、来源、localIdentifier、SHA、字节数、资源描述和编辑状态。收藏保护与编辑保护分别记录；凡已编辑的 Photos 视频均保留，若组内只有保护项则整组跳过，不以共同原件替代不同编辑效果。没有保护项时沿用大小／日期／稳定顺序选保留项。此规则只影响精确自动清理，不改变用户明确选择的普通手工整理语义。

授权门禁先于昂贵资源读取。取得交互 I/O 优先权后复核所有组成员，Photos 视频必须再次通过禁网络 reader 完整读取原始资源，并比较摘要、大小、资源描述和编辑状态；读取前后再查数据库计划事实。处理文件夹副本前复核相关保留项；Photos 待删项统一排队，系统批次开始前再次核验本批次及其保留项，防止前面的文件夹操作期间保留资源或收藏发生变化。Photos pending intent 写入也校验快照修订、媒体域和 localIdentifier。

Photos 仍通过已有系统确认进入“最近删除”，不将“快速清理”改造成 Photos 永久删除。Photos 恢复必须由用户在 Apple Photos 完成，ImageAll 观察到资产重新可用后才将回收记录标记已恢复。跨来源多文件操作不具有全局原子性；某个文件已回收而后续 Photos 复核失败时，保留已完成记录，文件仍可恢复，尚未通过核验的 Photos 项不提交系统删除。

## Mac 逐项比较与合成运行证据（2026-09-28）

清理确认页以逐项核对优先于汇总图：每项展示文件名、来源、原件来源类型、大小、时长、媒体日期、去留及保护／排序依据。缺失元数据明确标记未记录；收藏和编辑保护分开显示。文件名、来源名称与时长进入当前计划证据，执行时仍要求与预览一致。统计图折叠保留，避免挤占去留信息。

“查看”退出确认页并定位该组、选中该项、打开已有媒体预览；查看后重新生成清理计划，不持有过期的可执行预览。SwiftUI 确认页及逐项表通过直接 XCTest 的 NSHostingView 渲染并人工检查 PNG，测试不启动生产 composition root。合法 MP4 增加空 `free` 容器块的对照仍能解码，时长与首帧像素一致，但完整 SHA 不同且不进入字节相同组。

P4 的规定合成工程验收已覆盖原件来源隔离、取消／修订、原件与代表帧分组边界、比较数据、收藏／编辑保护及回收恢复语义。真实 Photos／iCloud 和日常 Xcode 点击验收不因此变成已验证；全 App 合成操作复核及最终版本回归统一在 P7 收口，接下来按原计划实施 P5 多帧能力。
