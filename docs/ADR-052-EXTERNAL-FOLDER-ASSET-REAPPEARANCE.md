# ADR-052：外部文件重新出现时建立新资产身份

> 状态：已决定并实施（2026-08-04，项目所有者对话批准）
> 相关：`ADR-044-LIBRARY-SLIMMING-AND-RECYCLE.md`、`LOCAL-TEST-DATA-SAFETY.md`

## 背景

文件夹来源可能在 ImageAll 之外被备份恢复、磁盘间迁移或修复。完成可恢复回收后，原相对路径应当
为空；如果之后的完整来源对账又在该路径观察到常规媒体文件，这个文件不是正在回收的旧资产，不能
继续被旧回收记录隐藏。

此前对账会保留所有 `availability = recycled` 的 current locator。外部工具把新文件放回同一路径时，
它因此仍显示为已回收，也无法进入正常的扫描、派生图预热和待处理队列。

## 决策

1. 当旧资产为 `recycled`，且最新回收记录已经处于稳定的 `recycled` 或 `purged` 状态时，对账观察到
   同一路径文件即把旧 locator 归档为 `historical`，并创建全新的 current Asset。
2. 旧回收记录继续指向旧历史 Asset；不自动恢复、不自动清空 quarantine，也不把旧标签、分析结果或
   内容 revision 继承给新 Asset。
3. `pending`、`restoring`、`purging` 等文件系统与数据库尚在收敛的状态继续保留旧身份，避免把一次
   回收/恢复事务误判成外部新文件。
4. 缺少稳定回收记录的孤立 `recycled` 状态继续保守保留，不凭不完整事实创建新身份。
5. 针对一次已知外部迁移，可在 App 退出且目录库完成可恢复备份后，把迁移清单命中的旧 current
   locator 归档，并为相关来源增加 dirty epoch、入队一次完整对账。此操作只修改 App 自有目录库，
   不读取或写入来源照片内容。

## 后果

- 外部恢复到原路径的内容会像新接入来源中的资产一样重新分类、建立指纹、生成派生图并进入待处理
  状态。
- 回收站历史和新内容身份分离；尝试恢复旧回收副本时仍由既有目标冲突保护 fail closed。
- 旧历史 Asset 及其可追溯事实不会静默删除；后续 App 自有维护可按现行缓存和历史事实策略收敛。

## 验收

- 合成数据库证明完成回收后的同路径 observation 产生“旧 historical + 新 current available”两个身份；
- `pending` / `restoring` / 孤立 recycled 等既有崩溃恢复语义保持不变；
- 自动化不访问受保护真实照片，运行库处理前后只报告聚合数量。
