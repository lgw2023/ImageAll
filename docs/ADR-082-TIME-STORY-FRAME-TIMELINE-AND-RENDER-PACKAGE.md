# ADR-082：时光故事统一帧时间线与 StoryRenderPackage 导出

- 状态：Accepted
- 日期：2026-09-18
- 关联：ADR-081、OpenMontage `StoryRenderPackage v0.1`

## 背景与问题

第一阶段项目持久化的是 `durationSeconds`，预览和原生视频各自按秒计算，默认淡入重叠为
0.45 秒。OpenMontage 的交换契约以 30 fps 整数帧为唯一时间单位。若预览、原生导出和故事包
分别量化，镜头边界、转场及总时长会产生漂移。第一阶段前景还会从完整展示继续放大到
101.5%，使横图或竖图的边缘在镜头末端被裁掉。

## 决策一：一个规范化帧时间线

`TimeStoryTimeline.normalize(project:)` 是三个消费端唯一的时间语义来源：

- 帧率固定为 30 fps；v1 镜头的秒数只在此处执行一次
  `round(durationSeconds * 30, toNearestOrAwayFromZero)`；
- 项目标题卡为 90 帧，每个章节标题卡为 60 帧；它们和照片镜头处在同一条时间线上；
- 首段从第 0 帧开始。后续段的转场长度为
  `min(14, 前段帧数 - 1, 当前段帧数 - 1, 90)`，起始帧为
  `前段起始帧 + 前段帧数 - 当前转场帧数`；
- 14 帧是原 0.45 秒在 30 fps 下按同一规则量化的结果；
- 总帧数是所有段 `startFrame + durationFrames` 的最大值；
- 非有限、非正数或量化后不足一帧的时长拒绝渲染；章节与项目镜头顺序不一致也拒绝；
- 过短镜头不会产生等于或超过任一相邻段长度的转场，至少各保留一帧非重叠内容。

现有 v1 项目仍按原结构读取和保存。规范化是只读派生，不把量化值或标题卡回写到用户项目。
因此旧项目的照片时长最多发生半帧量化差异；相对第一阶段成片，总时长还会明确增加 90 帧
项目标题卡和每章 60 帧章节标题卡，并把 0.45 秒重叠统一为 14 帧。照片选择、章节顺序和镜头
顺序不因接口适配而改变。

## 决策二：标题、字幕和完整展示

- 项目标题只呈现在开场项目标题卡；
- 章节标题呈现在各章开始处的章节标题卡；
- 镜头字幕只呈现在对应照片镜头的下方安全区；
- 用户编辑后的三个字段进入统一时间线，因此预览、原生视频与故事包采用相同文本和位置规则；
- 正式照片前景始终是 `contain`。轻微运动从完整尺寸的 98.5% 到 100%，不越过完整展示尺寸；
  可运动、模糊和压暗的背景仍允许 `cover`。

横图、竖图、方图和超宽图合成夹具在四边使用不同颜色标记。自动化检查照片镜头的开始、中间
与结束代表帧，确保四边标记在整个前景运动范围内保留。

## 决策三：固定 StoryRenderPackage v0.1

ImageAll 导出器固定使用：

- Schema 文件：`schemas/integrations/story_render_package_v0_1.schema.json`
- OpenMontage 提交：`30d412449354efce1ec002539e471b7c067e11c7`
- 文件 SHA-256：`884a6fed3eb4d8cf3b37c450b8a9a4e2d21782220532a66d21dccdf8fe696841`

OpenMontage 当前 `IMAGEALL_HANDOFF.md` 记录的 `ffdbd2…` 与上述提交中的实际文件哈希不一致。
ImageAll 以提交内实际 Schema 文件及其可复算哈希为准，并在跨项目交接中显式记录这一差异；
本轮不修改 OpenMontage 仓库，也不扩展 v0.1 字段。

导出器直接接收 `TimeStoryProject`，通过已有授权媒体读取接口取得镜头引用的正式预览素材，
按方向归一化为 JPEG。它不复制候选清单或整个图库，也不在包中写 Photos identifier、源路径、
精确 GPS、bookmark 或其他图库身份。包内路径是相对路径，项目、章节、镜头和素材 ID 是不可逆
散列生成的不透明 ID。

素材读取前后分别运行内容版本校验；配乐在复制前、复制后和源文件复查时比较 SHA-256。
任何缺失、版本变化、取消或校验失败都只删除本次暂存目录。完整写入并通过内部一致性和哈希
校验后，才以同目录替换方式发布，已有有效包不被失败任务损坏。

`projectRevision` 是规范化素材、文本、时间线、画布与制作参数序列化后的内容哈希，不包含导出
时间。相同内容和画幅重复导出得到相同 revision；横竖画幅因画布属于渲染内容而 revision 不同，
但素材、章节、字幕、镜头顺序和所有帧边界必须一致。

## 决策四：交付和运行边界

工作台提供“导出故事包”入口，用户选择横屏或竖屏及保存位置，并可查看进度、取消和结果。
面向用户只说明它是供外部制作工具使用的素材与制作方案，不暴露 Schema 或实现语言。

本轮保留原生 MP4 导出，不在 App 内打包 Python、Node、Chromium 或 OpenMontage，也不加入
一键外部渲染。原生渲染器仍只输出横屏；竖屏只用于故事包交换。只有 OpenMontage 对实际交付
包给出验证报告后，才可宣称跨项目联调完成。

## 可重复交付入口

测试 `TimeStoryFeatureTests/testGeneratePhase2DeliverablesWhenRequested` 在设置以下环境变量时，
使用实际导出器和原生渲染器生成交付，目标目录必须是不存在的新目录：

```text
IMAGEALL_STORY_PHASE2_DELIVERY_ROOT
IMAGEALL_STORY_PHASE2_SCHEMA_PATH
IMAGEALL_STORY_PHASE2_IMAGEALL_COMMIT
```

它生成短包、精确 1800 帧的横屏与竖屏完整包、只替换一张照片并修改一条字幕的变更包、
60 秒原生 MP4、Schema 副本、交接清单及全文件 SHA-256。所有媒体都是代码生成的合成素材；
生成过程不读取真实照片或触发 iCloud 下载，也不会在导出后修改 `story.json`。
