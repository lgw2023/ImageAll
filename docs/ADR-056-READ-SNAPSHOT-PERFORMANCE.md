# ADR-056：目录统计与审核总览采用批量只读快照

- 状态：Accepted
- 日期：2026-08-11
- 范围：图库总览、待审核建议状态刷新
- 安全边界：仅查询 ImageAll SQLite 目录；不扫描来源、不访问 PhotoKit、不读取原照片

## 背景

图库总览原先在同一个 GRDB `read` 闭包中执行九条独立聚合语句。每条语句都重新声明并遍历相同的
`overview_asset` 目录集合。待审核建议刷新则分别读取待审核总数、标签总览、两个全库任务；标签总览又为
每个标签分别读取样本数、四类建议数、任务、模型和标准标签状态。标签增多后，刷新成本随标签数产生明显
的查询放大，并在结果未变化时仍重复发布多个 `@Published` 属性。

## 决策

1. 图库总览改为一条 SQL。基础目录集合显式物化一次，各统计分支通过 CTE 聚合后以带类型的结果段合并；
   Swift 映射继续产生原有 `GalleryOverviewSnapshot`，不新增持久缓存或 migration。
2. 待审核建议新增 `PersonalizationReviewStateSnapshot`。生产服务在一个 `DatabasePool.read` 快照内批量读取
   所有活跃标签的样本计数、来源过滤后的四类建议计数、模型/标准标签状态、标签任务以及两个全库任务。
3. 待审核总数由同一快照内各活跃标签的四类待审核数求和。该口径与原 `UNION ALL` 总数查询一致，仍允许
   同一资产在不同标签或不同建议来源中分别计数。
4. `LibraryWorkspaceModel` 继续在后台读取快照，但只有新值与当前值不同时才写入对应 `@Published` 属性。
   队列重载、选择、排序、分页、焦点和视口逻辑不变。
5. 冻结现有并发和算法：缩略图 UI gate 为 4、底层网格为 16、预览为 4；个人建议图片预取为 2、推理为
   1。第一阶段不改变模型、预处理、阈值、Top-K、缓存格式、20 GiB 配额或 iCloud 策略。

## 验收标准

1. 合成目录的图库总览在照片/视频、精确摘要、来源、标签、年份、无日期、可用状态和收藏上与既有结果完全
   相同，十万资产精确性回归继续通过。
2. 批量审核快照与旧的四个独立投影完全相等，并保留来源过滤和媒体类型语义。
3. 标签规模增长时，审核快照保持固定 8 条查询；五次热运行中位数相对旧逐标签读取至少改善 20%。
4. 连续两次读取相同审核快照时，第二次不触发工作区对象发布，也不重载活动队列。
5. 自动化验证只使用临时 SQLite 与假实现；不得启动生产 App 宿主或访问受保护真实图库。

## 后果与停止点

本阶段降低重复 SQL 扫描、数据库队列往返和无效 SwiftUI 重算，但不引入陈旧缓存。若五次热运行的中位数
未达到热点至少 20% 的改善，回退额外复杂度。完成本 ADR 的定向验证与本地提交后暂停，后续图片缓存、
相似度后台处理和 Web Companion 增量渲染按批准计划分别审阅。
