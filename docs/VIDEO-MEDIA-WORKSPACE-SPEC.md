# ImageAll 视频媒体工作区实施规格

> 状态：Approved（产品形态已批准，实施待开始）
> 日期：2026-07-29
> 依据：ADR-046
> 安全：自动化测试不得读取 `/Volumes/HDD2/Photos Library.photoslibrary` 或 `/Volumes/HDD2`
> 顶层四位年份文件夹。

## 1. 产品目标

在不改变 App 外层入口的前提下，让视频拥有与照片同构的图库、标签、Review、训练、AI 建议和图库瘦身
能力。视频在网格和全部图像 AI 流程中由一张稳定的代表缩略图表示；视频页和照片页数据严格隔离。

## 2. 页面契约

### 2.1 统一媒体页签

以下工作区内容区顶部增加同一视觉规格的大页签：

```text
┌──────────────────────────────────────────────────────────────┐
│  照片  12,480    │    视频  386                              │
├──────────────────────────────────────────────────────────────┤
│  当前工作区原有内容；结构与动作随媒体域复用                   │
└──────────────────────────────────────────────────────────────┘
```

| 外层入口 / 工作区 | 照片页 | 视频页 |
|---|---|---|
| 全部 / 无标签 / 来源 / 标签 | 现有照片网格、筛选、批量标签 | 视频代表缩略图网格、同一筛选与批量标签 |
| 待审核建议 | 现有照片建议与 Review | 仅视频建议，交互和 origin 徽章相同 |
| 训练工程 | 现有照片 Run、槽位和新建任务 | 仅视频 Run、独立三槽位和同一新建流程 |
| 图库瘦身 | 现有照片分析、回收站 | 视频哈希相同 / 代表图相似分析与同一回收流程 |

行为规则：

1. 从侧栏进入任一工作区，页签初始化为“照片”。
2. 在当前工作区切换来源、标签、筛选、Run 或详情，保留当前媒体页。
3. 切换照片 / 视频时：
   - 取消尚未发布的搜索防抖结果；
   - 清空资产多选、主选和 Inspector 资产；
   - 重新按媒体域查询计数与内容；
   - 不取消已经启动的后台任务，任务仍归属于其创建时媒体域。
4. 大页签是页面主导航，不放进更多菜单或仅用一个小图标表达。

### 2.2 视频卡片与预览

- 卡片主体使用代表缩略图；
- 左下角固定播放图标，右下角固定 `mm:ss` / `h:mm:ss` 时长；
- 缩略图缺失时显示视频占位图、失败原因和“重试生成缩略图”，仍允许人工打标签；
- 双击或按既有单图预览快捷键进入视频预览；预览使用系统播放器控件；
- 文件夹视频播放会话全程持有 security-scoped 访问，关闭预览后释放；
- 视频 Inspector 显示：时长、尺寸、编码 / UTI、来源、日期、标签和 AI 建议。

## 3. 领域与数据库契约

### 3.1 基础类型

```swift
enum MediaKind: String, Codable, Sendable, CaseIterable {
    case image
    case video
}
```

UI 可以把 `image` 显示为“照片”，但数据库和应用层不得同时出现 `photo` / `image` 两种领域值。

### 3.2 migration v026

在新 migration 中演进，不改写 v001-v025：

| 表 | 变化 |
|---|---|
| `asset` | 新增 `media_kind NOT NULL DEFAULT 'image'`；新增可空 `duration_ms`；视频要求 `duration_ms > 0`，图片要求为空 |
| `training_run` | 新增 `media_kind NOT NULL DEFAULT 'image'`；查询索引包含 `media_kind, method, created_at_ms` |
| 个人模型槽 / 标签槽 | 唯一身份从 `method` 扩展为 `media_kind + method` |
| 建议阈值 / 模型身份 | 需要训练数据分布的记录按 `media_kind` 分槽；全局默认值可共享 |
| 相似分析任务 / 来源索引 | 任务快照和索引身份加入 `media_kind`，禁止照片 / 视频同桶 |

迁移回填：

- v026 以前仍在库中的资产全部回填 `image`；
- 不尝试伪造此前已被清除的视频或标签；
- migration 必须在合成数据库副本验证，不使用真实 Photos 库。

### 3.3 查询不变量

- 所有用户可见资产查询都必须有显式 `mediaKind`；
- 所有创建 Job / Run 的调用必须把当前媒体域复制进不可变 payload / snapshot；
- 后台任务不得在执行中读取“当前页签”决定范围；
- 标签字典跨媒体共享，标签计数与建议计数按当前媒体域聚合；
- 远端 DTO 至少增加 `mediaKind`、`durationMs`，旧客户端未知视频时 fail closed。

## 4. 视频代表缩略图 Module

### 4.1 Interface

调用方只需提供资产身份、内容修订和目标表示，得到本地缩略图或结构化不可用原因。调用方不需要知道
文件夹授权、PhotoKit、AVFoundation、iCloud 或缓存发布细节。

### 4.2 两个 Adapter

- 文件夹 Adapter：在授权租约内读取 AVAsset，用 AVAssetImageGenerator 生成图像；
- PhotoKit Adapter：只通过 PhotoKit 获取本地可用的视频代表图；默认禁止网络下载。

### 4.3 `videoPoster.v1` 取帧规则

文件夹视频使用确定性时间点：

1. 首选视频时长的 10%；
2. 不短于 1 秒、不晚于 30 秒；
3. 若该时间点不在有效时长内，退回时长中点；
4. 纠正视频方向后生成缩略图。

缓存身份至少包含：

```text
asset_id + content_revision + videoPoster.v1 + representation_size
```

Feature Print / embedding / prediction 的 provenance 必须记录 `videoPoster.v1`。以后更换取帧策略会自然使
旧特征失效并可重建，不覆盖历史训练 Run 的事实。

## 5. 标签、AI、训练和 Review

### 5.1 人工标签

- 视频与照片使用同一标签与标签组；
- 接受 / 拒绝、撤销、批量打标、无标签筛选完全复用现有行为；
- 资产被删除 / 缺失时继续保留现有目录历史语义，不额外删除人工标签事实。

### 5.2 AI 输入

首版每个视频只产生一份 `videoPoster.v1` 视觉表示，并复用：

- Vision Feature Print；
- DINO / embedding；
- 标准标签建议；
- Feature KNN；
- 个人质心模型；
- 个人 AdamW 模型；
- 代表图相似度。

以下内容明确不在首版：动作识别、跨帧聚合、镜头切分、字幕 OCR、语音识别、音频分类。

### 5.3 训练工程

- 顶部照片 / 视频页签位于现有训练工程标题区下方、槽位条上方；
- 每个媒体域独立显示 Feature KNN、个人质心、个人 AdamW 三个 published 槽；
- 新建视频训练任务只允许选择视频资产 / 视频标签样本统计；
- `training_run.media_kind` 是不可变事实，Run 详情显示“输入：视频代表缩略图（videoPoster.v1）”；
- 同一方法的照片与视频 artifact 目录 / DB 槽不得互顶；
- 视频页刷新、方法筛选与 Run 详情不得显示照片 Run。

### 5.4 Review

- Review Overview、标签队列、Inspector 和计数均按当前媒体域查询；
- 同一视频可出现多 origin 建议，沿用现有全并行规则；
- 人工决定会清除该视频 + 标签的各 origin pending 建议，不影响照片资产；
- 视频建议卡片必须显示播放标识与时长。

## 6. 图库瘦身

| 能力 | 视频首版语义 |
|---|---|
| 相同 | 完整文件 SHA-256 相同 |
| 相似 | `videoPoster.v1` 的 Feature Print / embedding 相似 |
| 种子检索 | 只在视频域查询，来源索引只加载视频桶 |
| 回收 / 恢复 | 复用当前文件夹授权与 PhotoKit 公开语义 |
| 永久清理 | 复用现有保护；不得新增对 Photos 系统回收站的永久删除 |

页面文案使用“相似视频（按代表缩略图）”。视频时长、码率或完整时间轴相似不在首版判定中。

## 7. 导入、同步与空闲预热

- 文件夹支持系统可识别的视频 UTI；首批显式覆盖 MOV、MP4、M4V；
- PhotoKit 枚举 `.image` 与 `.video`，Live Photo 首版仍作为一个照片资产，不拆成视频；
- 移除启动时清除视频资产 / 标签的行为；
- 文件变化或 PhotoKit change token 更新导致 `content_revision` 递增时，代表图、特征、预测和相似索引
  按现有失效机制重建；
- 空闲预热对视频只生成代表缩略图；Feature Print / embedding 继续服从当前预热策略和用户设置；
- iCloud-only 视频不因预热、训练或 AI 隐式下载。

## 8. 推荐纵向切片

### S1：基础媒体域 + 文件夹视频闭环

`v026` → MOV / MP4 / M4V 入库 → 代表缩略图 → 视频页网格 → 人工标签 → 系统播放器预览 →
重启后保持。

验收：一个合成文件夹 fixture 完成上述闭环，照片现有查询回归通过。

### S2：统一页签与查询隔离

在图库、Review、训练工程、图库瘦身接入同一媒体页签和媒体域查询；先允许后三个视频页显示真实空态，
不得显示照片数据。

验收：进入默认照片；切视频后四个工作区均无照片泄漏；选择与异步查询竞态有测试。

### S3：视频 AI + 训练 + Review 闭环

代表图 Feature Print / embedding → 三种方法独立视频槽 → 视频建议 → Review 决定 → Run 历史。

验收：合成视频代表图至少完成一条训练 / 建议 / 审核主路径；照片模型槽不变化。

### S4：图库瘦身与 PhotoKit 视频

视频相同 / 代表图相似分析、回收语义；PhotoKit 假 Adapter 覆盖视频枚举、缩略图、播放与云端不可用。

验收：零真实 Photos 访问；视频索引不与照片同桶；云端默认不下载。

### S5：Remote / Companion 投影

先传代表缩略图、媒体域和时长；完整视频串流另立安全与传输规格。

## 9. 完成定义

- 四个现有工作区均有一致的大照片 / 视频页签，进入默认照片；
- 文件夹与 PhotoKit 视频都能被索引，不再被启动清理；
- 视频可显示代表图、时长、播放标识并用系统播放器预览；
- 人工标签、三轨 AI、训练 Run、Review、相同 / 相似分析在视频域可用；
- 照片 / 视频模型、建议、Run、选择、计数、任务和相似索引无交叉污染；
- 视频 AI 的“仅代表缩略图”限制在训练详情、相似分析和帮助文案中可见；
- migration、主路径、必要失败路径和照片回归通过；
- 自动化证据明确为合成 fixture / fake Adapter，零访问受保护真实数据。
