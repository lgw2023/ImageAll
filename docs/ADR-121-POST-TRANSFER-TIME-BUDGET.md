# ADR-121：后处理时间不得超过传输时间

状态：已实施并通过合成预算与日常Xcode部署验收，2026-10-26。用户明确允许大幅调整流程。

## 硬门槛

同一合成批次、同一目标卷，T_transfer 从首个资源上传开始至持久交接ACK；T_post 从交接完成至校验、入库、发布与暂存清理全部完成。要求 T_post <= T_transfer。不计生成fixture时间，不插入延时或降低传输吞吐来达标，不把工作延后到计时外。手机仍在交接ACK后可拔线。

## 设计修订

旧路径7轮全读：接收1、复制目标1、入库末尾1、发布1、收尾目标2/接收1。
新连续路径保留接收副本全量SHA与目标副本全量SHA各1轮。目标校验后的同一操作中，入库、发布及收尾只复核清单/事实、对象版本、数据库引用和独占租约，不重读相同原件。全量校验结果仅在内存传递、不能持久反序列化或由接收声明伪造；显式旧入口/维护审计继续全读。重启失去凭据时重新执行实际内容校验。

此决定替代ADR-120及更早ADR要求每个事务层重复实际全读的部分。完整性契约是：源和最终副本确实全量SHA通过，后续同一调用链以身份/版本连续性绑定提交；不声称版本检查能检测校验后未引起文件版本变化的静默介质故障。显式独立审计仍完整读取。所有可观察的内容修改、旧凭据、对象替换和事务中断必须拒绝或回滚。

用户发起的Mac导入用userInitiated执行优先级、串行逐批推进；不增加原件并发或内存阈值。先用同一方法测量实际传输与后处理，再评估是否还需更大流程调整。

## 验收

先失败测试：凭据复用0资源读取；同大小损坏/恢复旧内容/对象替换/回调中断拒绝；集成证明数据库无部分可见、发布后清理失败不损伤图库。
4 GiB单资源和包含多项目/整理信息的合成批次计时。性能不满足硬门槛就不宣称完成。真实媒体不重传，既有3,721项保护。

## 额外发现

包含整理信息的20项测试先失败：实测原件读取4轮而非2轮。原因是reconcileFacts对已随归档验证、完全相同的事实文件仍做前后媒体全读。
仅在持有同操作全量凭据、事实URL就是已验证最终归档中的当前文件且摘要相同时复用；新事实版本保持原审计路径。事务前后仍验证对象身份，故障回调后的变化会回滚。
单资源4 GiB首测传输46.836秒、后处理10.913秒，比值0.233；该结果尚不替代多项目和实际HDD目标卷的验收。

HDD2/APFS机械盘独立目录已验收：855项/4.05 GiB，传输141.506秒，后处理78.668秒，比值0.556。源SHA35.953秒、目标SHA35.307秒；发布1.850秒、收尾4.122秒。全部完成后冷重启0.239秒、0媒体读取。
正常新批次实际读取2遍；已复制最终归档但数据库提交中断的恢复允许在完整SHA后复用同一目标对象，避免把同一最终归档误作两份文件各读一次。恢复及新任务使用用户发起的执行优先级，旧独立维护入口默认继续完整审计。
