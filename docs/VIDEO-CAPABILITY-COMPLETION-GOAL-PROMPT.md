## 2. 你的任务与最终结果

你是本项目的视频能力补全实施代理，负责产品取舍、必要 ADR、实现、测试、构建和本地交付。

最终结果应让用户完成以下操作：

1. 接入文件夹或 PhotoKit 视频，正确看到媒体类型、时长、方向、拍摄时间及可用位置。
2. 在 ImageAll 内观看视频、拖动进度、调整声音，同时打标签、收藏、审核和切换资产。
3. 按来源、标签、时间、地点、时长、大小和常用视频规格找到视频。
4. 对视频生成可解释的智能建议，并在原生端与支持该操作的 Companion 中审核，形成持久人工事实。
5. 分清完整文件相同、代表帧相似和多帧内容相似，安全地比较和处理重复候选。
6. 用有限多帧分析覆盖视频内容，查看建议来自哪些时间点。
7. 将照片与原始视频片段共同用于故事，调整片段范围、顺序与原声，导出经过校验的成片。
8. 明确知道一个操作当前能否完成、缺少什么资源、如何恢复或重试；不能只有按钮而没有业务闭环。

优先完成从用户动作到可见结果的最小纵向切片。不得先进行全仓库媒体抽象改造、播放器框架重写或大规模命名清理。

## 6. 架构与产品决策原则

### 6.1 复用已有领域

- 沿用 `MediaKind.image / .video`，共享标签字典与人工决定事实，不创建平行标签数据库。
- `mediaKind` 表示业务媒体域；UTI 表示资源格式；MIME 表示 HTTP 内容类型，三者不能混用。
- 训练 Run、模型槽、预测、分析任务与来源相似索引继续隔离媒体域。
- 进入工作区、切换媒体与选择清理行为沿用现行规格；确有必要变更时用 ADR 说明。
- 可共享的播放器、媒体资源租约与状态组件应收敛到小模块，避免继续把全部逻辑塞入大型 Workspace 文件；不借机重构无关模块。

### 6.2 封面、分析帧与片段分开

- 展示封面供用户浏览；分析表示用于特征／模型／相似判断；两者分别拥有版本与缓存身份。
- 修改展示封面不应悄悄使 AI 结果、历史训练样本或重复结论失效。
- 分析帧身份至少包含资产、内容修订、策略版本、时间点与表示参数。
- 多帧缓存必须有大小预算、重建策略和并发限制，不能按视频长度无限生成。
- 资产标签表示整段视频的归属；时间点证据与片段标签是不同事实。首版允许时间点证据，不强制新增独立片段标签体系。

### 6.3 缺失信息与降级

- 区分未知、尚未分析、不支持、来源离线、授权失效、云端原件不可用和处理失败。
- 没有拍摄时间／坐标／音轨时保持缺失，不猜测为某个日期、地点或静音事实。
- 显式说明是否只分析代表帧／多帧，不能用“已理解视频”掩盖范围。
- 旧缓存与旧模型按明确策略继续使用或失效；不悄悄重建全库，不覆写历史 Run 的输入事实。

### 6.4 决策留痕

以下选择必须在实现前或同一切片的 ADR 中记录：时间与时区来源、地图混合显示规则、云端视频获取策略、多帧采样与聚合、完整字节去重证据、故事片段与音轨规则、协议兼容策略。

常规低风险实现可用合理默认值直接推进。只有影响已有事实语义、来源写入、外部传输、付费或不可逆操作的选择，才作为需要用户明确决策的门槛。

**退出标准**：状态文件与首个切片的输入、输出、验收清楚；没有尚未解决的安全冲突。P0 结束后立刻开始 P1，不等待对计划的常规确认。

### P1：统一媒体契约与完整观看／整理闭环

**用户结果**：在主要整理界面中观看视频并立即完成标签、收藏与审核；远端不再把 UTI 当 MIME 推断视频。

实施：

1. 在主资产摘要／详情以及实际缺失的相关 DTO 中传递显式媒体域；同步 Swift、Web schema、fixture 和协议兼容处理。
2. 旧客户端与旧 Host 缺字段时按已知 UTI／受控兼容规则处理，无法识别时显示不可用；不把所有未知媒体默认为照片。
3. Mac 增加可复用视频查看器：播放／暂停、拖动进度、音量、倍速、全屏；保留外部系统播放器入口。
4. 接入图库大图、审核大图和瘦身详情，保留标签／收藏／审核动作以及前后切换。
5. 与悬停播放器协调资源；快速切换、关闭、失焦、来源切换和任务取消不留下旧画面、声音、解码器或授权租约。
6. Web 修复媒体分支并接通现有媒体路由，验证 Range、寻址和错误状态，不用 mock 成功冒充 Host 联调成功。
7. iPhone Companion 接入与其认证方式兼容的视频播放；复用受控媒体访问，不把 Bearer 凭据暴露到日志或任意 URL 参数。
8. 统一视频时长、播放标识、可访问性名称和照片专用文案，修改仅限实际视频路径。

**最小验收**：

- 合成视频入库 → 打开 → 播放／拖动 → 打标签或审核 → 切下一条 → 重启后人工事实保留。
- 真实生产 DTO 形状的合成 MP4／MOV UTI 能走视频展示分支；照片分支回归通过。
- 快速切换与不可播放输入各覆盖必要失败路径，确认资源释放与清晰错误。
- 各端分别保存所测层级证据；尚未接通真实 Host 的端明确标记。

### P2：元数据、筛选、地图与云端可用性

**用户结果**：视频进入准确的时间／地点整理体系，能按常用条件查找，资源不可用时有明确下一步。

实施：

1. 文件夹视频提取可用的内嵌拍摄时间与 GPS，记录来源和时区策略；保持媒体时间与文件时间独立。
2. 采集可获得的容器／编码、帧率、字节大小、音轨存在性；动态帧率、未知码率等允许缺失或明确标注。
3. Inspector 展示上述信息；技术信息缺失不阻断浏览、打标和现有播放。
4. 增加时长范围、分辨率或方向等常用筛选，以及时长／文件大小排序；首版选择能由可靠元数据支持的少量条件。
5. 历史回填通过有界任务、checkpoint、取消与重试实现；仅当策略版本或缺失字段需要时读源，不每次扫描全量解码。
6. 地图查询、回填统计、聚合、选择与详情接入视频；提供清晰的照片／视频／混合范围及数量语义。
7. 智能推流使用可用视频时间／位置证据，明确同事件跨媒体候选的规则与人工确认边界。
8. 本地可播放与云端原件不可用分开建模。保持悬停、浏览、预热和 AI 默认不下载原视频。
9. 设计并实现用户主动获取云端视频的产品入口：先沿现有授权框架明确动作、临时或持久存储语义、进度、取消、空间限制和清理归属；以 fake Adapter 验证，不执行真实下载。
10. 播放只支持返回 URL 的现有路径时，评估经 Photos 编辑后返回其他 AVAsset 的情况，选择可解释的支持或拒绝策略，不无条件强制转换并报通用失败。

**最小验收**：

- 已知时间／坐标／旋转的视频 → 入库或回填 → 信息正确 → 时间筛选／地图定位正确。
- 缺失字段与时区跨日样本有明确结果；不回退伪造拍摄时间。
- 筛选与排序分页稳定，媒体切换没有照片／视频计数污染。
- 合成回填可取消并继续；fake 云端视频不会隐式下载，主动获取可取消且状态可恢复。

### P3：标签、AI、训练、审核与跨端能力对齐

**用户结果**：现有视频代表帧智能链路在实际入口可用，原生端和 Companion 对可发起操作的解释一致。

实施：

1. 逐条核对人工标签、清除、拒绝、批量操作、收藏、撤销、搜索与状态刷新；复用已有逻辑，修复实际缺口。
2. 确认标准建议、Feature KNN、个人质心、AdamW 的视频模型槽、输入、任务 payload、Run 与发布身份完整隔离。
3. 去除远端命令服务中已经具备视频底层支持却仍硬编码照片的限制；不只是删除 guard，要跟踪下游样本／缓存／模型选择。
4. 能力声明、按钮可用性与服务端校验来自一致的规则。模型缺失与功能未支持分开说明。
5. 串起视频样本选择 → 训练或模型选择 → 建议 → Review → 人工事实 → 撤销与重新读取。
6. 智能推流的媒体范围、模型成熟度判断、候选播放和批量确认一致；不把“忽略”写成负样本。
7. 跨端共享事实沿现有操作 ID、版本与幂等机制更新，不自行创建另一套同步账本。

**最小验收**：

- 一条视频样本到建议再到审核的完整合成链路，证明照片模型槽和照片人工事实不变。
- 一条远端发起命令到持久结果再读取的链路，覆盖幂等重放与媒体域校验。
- 一个缺模型或资源不可用的失败路径，不生成虚假成功任务。
- 多种训练方法按实际改动范围选择必要回归，不为每种组合重复全套昂贵训练。

### P4：完整视频精确去重与安全比较

**用户结果**：可靠识别完整文件相同的视频，并与视觉相似结果清楚区分。

实施：

1. 用新 ADR 记录从“仅代表帧分析”扩展到显式完整字节分析的产品变化。
2. 将完整文件摘要与代表帧摘要分开存储或明确区分 provenance，不覆盖原视觉指纹的含义。
3. 先实现本地文件夹的显式完整字节扫描：分块读取、受控并发、进度、取消、重用与内容修订复核，禁止一次把大文件全部读入内存。
4. PhotoKit 路径必须说明参与比较的是何种原始资源／版本。播放 URL 可能不是所声明原件时，不能直接标记为原件字节相同。
5. 对可证明取得原始字节的本地 PhotoKit 资源实现分析；云端不可用时跳过并说明，需要显式获取才能继续，不在分析中偷偷下载。
6. 结果至少区分“完整文件相同”和“代表帧相似”，展示大小、时长、来源、收藏保护与保留候选依据。
7. 接入现有用户确认、授权、回收／恢复语义，执行前再次复核身份与修订；代表帧相似不能成为自动清理依据。
8. 手机迁移归档摘要可作为该资源完整性证据，但只有完成资源身份关联和来源复核后，才可参与主图库的同类判断。

**最小验收**：

- 相同字节副本进入精确组；同封面不同视频不进入精确组；改写容器的非同字节视频不误称字节相同。
- 扫描中内容改变或取消不发布错误完成结果。
- 合成重复组比较 → 明确保留／回收 → 恢复闭环；收藏保护与媒体身份复核生效。
- 所有删除／移动测试仅在当前测试创建的 fixture 根内执行。

### P5：多帧分析、可解释建议与内容相似候选

**用户结果**：分析覆盖整段视频的有限时间点，用户能看到命中依据，不再只依赖封面。

实施：

1. 新建版本化采样策略，用有上限的确定性时间点覆盖前中后段；短视频去重时间点，必要时绕过明显无效帧。
2. 首版不要求完整镜头切分或视频大模型；明确帧数／解码／缓存预算，并依据合成测量调整默认值。
3. 显示封面与分析帧分别管理。保留 `videoPoster.v1` 旧结果的可读性和来源，不将其冒充新多帧结果。
4. 先复用现有图像特征／模型，实现帧级结果到资产级建议的明确聚合规则；保留命中时间点和证据。
5. 推理、训练输入与模型身份一致；采用视频向量或多帧样本时显式版本化，历史 Run 不改写，未经验证不互用旧新模型。
6. 在详情／审核中查看代表分析帧，并点击时间点跳转播放。
7. 用多帧表示生成“内容相似候选”，可加时长等约束；首版不承诺识别所有重编码、变速、裁剪或片段重叠。
8. 新旧策略有明确切换与重建入口，不因升级自动扫描全库。

**最小验收**：

- 构造“前段无目标、后段出现目标”和“封面相似、内容不同”的小型合成对照组。
- 记录单帧与多帧的结果差异、解码帧数、耗时、缓存量及证据时间点；只对该对照组下结论，不伪称真实库准确率提升。
- 命中时间点可播放定位；取消／重跑复用缓存；内容修订与策略升级不会误用旧特征。
- 内容相似候选不进入精确去重自动清理路径。

### P6：照片／视频混合故事的可编辑闭环

**用户结果**：将照片和原始视频片段组合成故事，保留视频运动与可控原声，导出可验证成片。

实施：

1. 故事候选支持照片与视频，候选数量、时长估算、来源可用性和缺失信息明确。
2. 视频镜头具有稳定资产／内容身份、入点、出点与音轨策略；照片镜头沿用已有展示时长与运动规则。
3. 在故事工作区预览视频、设置片段范围、调整顺序；校验零长度、越界、来源变化及不可播放状态。
4. 先实现用户明确选择片段的确定性制作路径，再让自动选材使用已验证的片段能力；不要求先完成复杂镜头评分。
5. 渲染包显式区分静态图与视频片段，冻结使用的资源／版本／范围，按现有任务授权和安全目录规则准备素材。
6. 图像和视频方向、画幅、帧率／时间基准按明确规则归一；音轨最小支持保留原声、静音及与配乐组合的受控音量，不引入完整专业混音器。
7. OpenMontage 协议、Schema、集成清单与生成契约同步升级，保留旧照片故事的可读取性和已完成任务恢复。
8. 视频素材不能在 UI 看似被支持、导出时却仅使用一张代表图；不支持的输入必须在制作前说明。
9. 完成记录、重试、历史成片、未知任务状态和模型授权继续遵守现有可靠性契约。

**最小验收**：

- 至少包含一张照片和一段带已知运动／合成声音的视频，完成选材 → 设入出点 → 调序 → 渲染 → 重开成片。
- 验证输出存在、非空、可解码、时长合理，能观察视频运动并核对声音策略；截图或文件存在不算成片验收。
- 损坏或修订变化的输入被拒绝；旧照片故事回归通过。
- 仅使用合成素材与本地模型 fixture；涉及发布包时另走 OpenMontage 发布门禁。

### P7：集成、运行证据与工程交付收口

**用户结果**：获得能在当前 Xcode 项目继续使用和验收的完整实现，以及各端真实支持范围的准确说明。

实施：

1. 检查 P1–P6 的功能是否存在真实入口、是否调用实际服务、是否产生持久结果；清理占位按钮与假成功状态。
2. 完成获授权的主项目集成，不夹带网页长期分支或手机／OpenMontage 并行任务的无关改动。
3. 对最终集成版本执行与改动匹配的构建、定向测试和合成运行检查，证据绑定相同版本。
4. 检查照片原有浏览、预览、标签、审核、模型槽、地图和故事的受影响主路径。
5. 验证大视频操作采用流式或有界处理，取消、缓存配额和后台状态可恢复；先解决可复现的主路径资源问题，不铺开无限性能矩阵。
6. 核对 Web 与 iPhone 的协议和能力声明；没有支持的端或来源写清限制，不显示可操作却无法完成的入口。
7. 更新视频规格、相关 ADR 和完成矩阵；真实图库、实体设备、iCloud 下载、付费模型及发布安装证据单列。
8. 提供最短人工验收路线：从 Xcode 打开哪个项目、使用哪些已授权或合成数据、点击哪些入口、预期看到什么。

**退出标准**：符合第 9 节的工程完成定义；没有未集成的必需功能、失败的必需测试或未披露的核心占位实现。

## 8. 测试与证据约定

### 8.1 小型可重建素材集

优先复用现有 fixture，再按实际需求补充：

- 横屏、竖屏或带旋转信息的视频。
- 带已知拍摄时间／坐标的视频，以及缺失这些字段的视频。
- 短视频、有声／无声、前黑后亮或分段变化的视频。
- 相同字节副本、同封面不同内容、非同字节但相近内容的视频。
- 损坏／截断输入、fake 云端资源及取消中的请求。

保持素材小、生成步骤可复现，不为长视频验证提交巨大二进制。长时长、大字节压力优先用受控生成或测试替身，并明确其证明范围。

### 8.2 每个切片的证据

- 一个用户主路径测试或合成运行证据。
- 必要失败路径，重点覆盖取消、媒体身份／修订、来源不可用、事务与资源生命周期。
- 受影响的照片回归及协议兼容回归。
- 所改目标的构建检查、`git diff --check`，网页按实际 package scripts 做类型／测试／构建。
- 记录命令、退出码、结果摘要、日志／产物位置和版本身份，不只写“测试通过”。

测试执行前核实宿主与数据路径，直接 XCTest bundle 不等于可以忽略其依赖初始化行为。不得为获得测试结果而临时连接真实图库。

### 8.3 证据等级

| 等级 | 可证明什么 | 不能代替什么 |
|---|---|---|
| 静态检查 | 分支、契约、数据流与调用路径存在 | 运行成功、兼容性、质量 |
| 单元／合成集成 | 指定 fixture 的行为正确 | 真实图库、云端和实体设备体验 |
| 合成 UI 运行 | 指定隔离配置下用户动作闭环 | 日常配置与真实资料验收 |
| 明确授权的真实 smoke | 本次授权范围内的运行结果 | 全库可靠性、无限性能或后续写入许可 |
| 发布验收 | 被验收包与门禁结果 | 未执行的真实模型与媒体质量验证 |

## 9. 目标完成定义与交付格式

### 9.1 工程目标可以完成的条件

必须全部满足：

- P0–P7 的必需实现已交付；阶段重排有记录，核心范围没有被静默删去。
- 所需主项目集成已经完成。分支提交、补丁或前端 fixture 完成不能替代实际集成。
- Mac 视频查看／整理、时间地点整理、现有 AI 建议审核链路、精确去重、多帧证据和混合故事均有相应合成闭环证据。
- 最终代码版本的必要构建与测试通过；无失败项被改写为“技术债”以绕过完成标准。
- 旧照片路径没有已知的阻断性回归，数据与安全不变量保留。
- 所有核心入口真实可用，或在预先定义的不支持情形下明确拒绝；不能以“所有视频暂不可用”满足失败状态要求。
- 已有可恢复的本地提交或经说明保留的改动清单，未污染他人改动，没有 push 或历史改写。
- 完成矩阵、证据、人工验收路线、剩余限制与待授权事项准确。

工程目标的完成不宣称真实图库、真机或发布验收通过。这些不是本提示词自动授权的动作，必须在交付中保留 `NOT_RUN` 或实际结果。

### 9.2 不能标记完成的情况

- 仅完成盘点、ADR、接口、DTO、UI 或局部测试。
- 只有代表帧，却声称完整视频理解或完整视频重复检测已完成。
- 核心跨端变化还留在工作分支，主项目集成未完成。
- 关键实现依赖真实外部服务，但只有假数据演示、没有可运行的本地或明确受支持路径。
- 预算即将耗尽、执行时间过长或需要压缩上下文。
- 等待授权导致核心集成无法完成。此时继续其他工作，最后如实保留目标未完成状态，不把待办换成完成。

### 9.3 每阶段向用户报告

用简短中文说明：

1. 用户现在能做什么。
2. 实际修改和本地提交范围。
3. 通过了哪些必要验证，证据属于哪一层。
4. 尚未实现、未验证或需要输入的具体事项。
5. 下一步正在推进的切片。

最终交付再附能力矩阵、构建／测试／合成运行证据、人工验收步骤和未完成的真实验收列表。目标工具返回的状态如实报告；用户设有显式预算时按工具规则报告实际使用量。

## 10. 后续扩展：本次目标之外

以下内容纳入路线图讨论，但不自动纳入 P0–P7 的完成门槛。用户以后明确纳入时，再扩展目标与验收标准。

| 扩展 | 可带来的能力 | 启动前应明确 |
|---|---|---|
| 字幕 OCR 与语音转写 | 按对白／画面文字检索，点击结果定位时间 | 本地／外部模型、语言、隐私、成本、时间戳质量与纠错 |
| 声音事件与动作识别 | 查找掌声、讲话、奔跑等内容 | 任务边界、模型许可、评估样本和误报处理 |
| 镜头切分与精彩片段评分 | 自动推荐故事片段 | 与 P5 采样证据的区别、质量基线及人工覆盖 |
| 重编码／裁剪／变速副本与片段重叠 | 更复杂的视频重复候选 | 候选召回、时间对齐与人工确认，不自动升级为字节相同 |
| 转码、压缩与代理文件 | 更流畅的浏览和存储管理 | 输出位置、画质／HDR／音轨保留、原件绝不原地覆盖 |
| 手动封面、播放进度记忆、逐帧与截帧 | 更细的查看与取材体验 | 展示缓存与分析身份分离，截图产物身份和存储位置 |
| Live Photo 动态资源管理 | 静态与配对视频联合使用 | 复合资产身份、归档完整性与用户可见语义 |
| 手机归档与主图库统一身份 | 跨来源统一筛选、标签与去重 | 依赖 ADR-102 当前进度，不重复建立同步和迁移账本 |

不能为追求“全面”把所有后续扩展一次性塞入实现。先完成本目标明确的端到端能力，再根据用户实际使用决定下一轮。
