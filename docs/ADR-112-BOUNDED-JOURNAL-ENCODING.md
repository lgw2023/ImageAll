# ADR-112：有界资源编码缓存，保留原子会话快照

日期：2026-10-21。状态：已实施，接收端合成门与真实 USB 对照完成；USB 吞吐中位提升约 5.4%，未达 25% 目标。范围：USB 接收端 P2 第一切片。

## 依据与取舍

同 SSD1 的 2,889 项合成日志每块约 2.20 MB，JSON 编码约 17.65 ms、原子替换约 3.68 ms。
当前成本主要来自重复编码。先保留 formatVersion=1 的 session.json、整份原子替换和现有恢复器，
仅复用未变化资源的已编码 JSON 片段。暂不引入增量落盘日志、重放、压缩或新迁移格式。
这是对“增量日志优先”的最小化重排：先按资源增量编码，后续再凭实测决定是否改变落盘格式。

## 决议

- 每个 store 只缓存最近一个任务；上限 8 MiB 编码字节、8,192 个资源条目。超限回退完整 JSONEncoder。
- 每条缓存以路径、已有 ledgerDigest 和 StorageObject 为有效性条件。账本摘要绑定块列表和资源回执；
  所有修改仍经过现有 bindStorageObject。任务元数据每次重新编码，任务身份不能跨缓存复用。
- JSON 键和值均由 JSONEncoder 产生，只拼接固定 JSON 结构；保持可选字段和现有解码语义。
- 数据块同步、日志原子替换成功后才提交缓存；失败不得污染后续同进程重试，也不得提前 ACK。
- 冷进程没有编码缓存，仍按 ADR-111 验证对象/凭据和必要的旧日志实际字节；编码缓存不能证明完整性。
- 块 SHA、资源冻结、最终封存全量 SHA、数据库/发布验证、内存保护和真实数据边界不变。
- 当前仍每块替换完整日志，不声称已减少落盘字节或具备新的掉电持久性保证。

## 验收门

公开 store 接口验证多资源、回执、跨任务和冷重载；在日志替换失败后同进程重试，再冷恢复，
检查已提交偏移与回执。沿用同大小损坏、旧凭据、对象替换、尾部修复和封存回归。
同编译条件、SSD1、三轮交替、每组 8 个 4 MiB 非稀疏块做前后对照；只报告实际测到的接收端改善。
真实 USB 吞吐与日常 Xcode 部署独立验收，不能由本地函数计时替代。缓存上限和回退需独立合成验证。


## 2026-10-21 验证结果

112 项协议测试通过，包含日志替换失败、同进程不同后缀重试、跨任务缓存切换和严格冷恢复。
8,193 项与超过 8 MiB 的编码输入分别触发条目/字节回退，实际块、资源回执及严格冷恢复均通过。
HTTP 集成通过中断后 4 MiB 偏移续传、重复恢复零新增上传、同大小损坏拒绝和最终发布状态。

同一天、同 SSD1、同 Xcode Debug 编译条件的前后基线，大任务单块总耗时中位数
37.211 → 24.259 ms（减少 34.8%），提交部分 31.093 → 17.748 ms（减少 42.9%）；
小任务总耗时 14.941 → 15.205 ms。日志仍约 2.20 MB，无写入字节减少声明。
三轮、每组 8 个 4 MiB 块，完整 SHA 和新 actor 冷恢复偏移通过；所有合成进程保留 512 MiB 保护。
此结果不替代真实 USB 吞吐 A/B，也不是新的 4 GiB 冷恢复计时。

证据：`/Volumes/SSD1/.codex-builds/USB-P2-JournalEncoding-20261021/Evidence/REPORT.md`。


## 实机对照方法

真实 USB 对照使用同一 Host 二进制；仅隔离 XCTest 经 internal 诊断方法关闭编码缓存，
走原完整 JSONEncoder 路径。该入口不作为 public API、生产设置或环境开关。
64 MiB 非稀疏合成资源预提交32 MiB，2,888个已有资源，续传32 MiB；三轮交错运行。
手机记录逐块ACK、上传开始/结束、首次有效接收进度、封存及发布；必须区分上传窗口、
首ACK之后的持续传输与全流程时间。4 GiB/剩余8 MiB冷恢复仍作为独立门，不能用小夹具代替。


## 2026-10-22 真实 USB 对照

同 iPhone、SSD1、Debug Host 二进制，三轮交替开关缓存。每组 2,889 项，64 MiB
非稀疏大资源从 32 MiB 续传，8 个 4 MiB 块。32 MiB 上传窗口中位数
1.562408 → 1.481903 秒，吞吐 20.481 → 21.594 MiB/s（+5.43%）；首个 ACK
之后的 28 MiB 连续传输为 21.219 → 23.137 MiB/s（+9.04%）。未达到 25% 目标，
不得用先前接收端函数计时的 34.8% 替代 USB 收益。

从恢复开始到封存完成中位数 4.154 → 4.517 秒，未显示全流程稳定改善；此小样本
不能据此单独归因为编码缓存导致回退。六组均完成同任务恢复、验证/发布、手机可浏览
状态及冷启动重复恢复零上传。一组手机轮询跳过短暂的待入库阶段，仍观察到验证、
发布和可浏览；其余五组观察到全部四阶段。另一次上传前连接中断独立保留失败证据，
新 run/Host 身份替换后完成该对照组；根因尚未定位，不声明零失败或已修复断连。

仅本轮隔离驱动在连接后等待 3 秒稳定窗口（首个基线未加此等待），位于恢复计时
之前；没有改变生产重试或恢复逻辑。所有完成组的 Host/手机均未触发 512 MiB 保护。

决策：保留本切片的有界编码缓存，不为追求 25% 数字直接引入新的日志落盘格式。
下一步先分解完整校验、导入及发布的重复读取成本，再评审 P3 的最小改动；必须保留
实际字节完整性、对象身份绑定与数据库原子发布。当前不声明 P2 所有优化目标已完成。

证据：`/Volumes/SSD1/.codex-builds/USB-P2-USBCompare-20261021/Evidence/performance-20261022.json`。
