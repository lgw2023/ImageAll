# ADR-047：正方形缩略图为主，原比例缓存仅手动生成

> 状态：已决定并实施（2026-07-30，项目所有者对话批准）
> 相关：ADR-041、ADR-046、`docs/LOCAL-TEST-DATA-SAFETY.md`

## 背景

图库顶部已有“正方形 / 原比例”显示切换。若“原比例”在切换时临时读取 2048px 预览或原文件，
大型来源会产生明显迟滞，也会把一次纯显示操作变成不可预期的批量解码。照片与视频现已共用图库入口，
因此不能只为静态照片定义缓存规则。

同时需要明确显示缓存与模型输入的边界。当前 Feature Print、DINO / embedding、建议和相似聚类并不读取
512px 网格缓存：它们从各自的原始图像 / PhotoKit 分析输入或视频代表图加载器取数据，再在算法内部执行
1024px、518px、256→224 等独立预处理。因此新增原比例显示缓存不会改变模型结果。

## 决策

### TH-P1：正方形仍是唯一主网格缓存

- 自动网格加载、空闲预热和现有来源缩略图预热继续使用 `gridRegular`（512×512，居中填充裁切）。
- 工具栏默认“正方形”；切回正方形时所有照片和视频都走主缓存。
- 原比例显示缓存不作为 Feature Print、embedding、模型预测、训练或相似聚类的输入。

### TH-P2：原比例缓存是独立的手动辅助层

- 新增 `gridOriginal`：最长边不超过 512px，保持照片或视频代表图的宽高比，不放大较小源图。
- 只允许用户在左侧来源的右键菜单点击 **“专门用于原比例的缓存”** 后生成。
- 预热遍历该来源的照片和视频，沿用可取消进度、逐项失败统计和持久缓存配额。
- 2048px 预览可以在用户已经发起本次手动预热后作为渲染输入，但仅打开预览、下载云端预览或点击
  比例切换按钮都不得自动创建 `gridOriginal`。

### TH-P3：切换比例只查缓存，未命中保持正方形

- “原比例”模式先执行 cache-only 查询，不打开文件、不请求 PhotoKit、不下载 iCloud 内容，也不生成图。
- 命中 `gridOriginal` 才显示原比例；未命中、缓存损坏或读取失败均回退到 512×512 主缩略图。
- 预热完成或取消且已有成功项时刷新可见图库、待审核和图库瘦身卡片，使成功项无需再次切换即可生效。

### TH-P4：照片与视频采用相同契约

- 文件夹照片从原图生成 `gridOriginal`；文件夹视频从稳定代表帧生成。
- Apple Photos 的照片和视频都通过本地 PhotoKit 512px `aspectFit` 请求生成；默认禁止网络访问。
- iCloud-only 项若没有本地可用输入则计为失败，不因原比例预热隐式下载原内容。
- 缓存键继续绑定 `asset_id + content_revision + representation_version + variant`，源内容变化后旧缓存不再命中。

## 数据与缓存后果

- migration `v029_add_original_aspect_thumbnail_cache` 扩展派生图表的 variant 约束，并原样迁移既有行。
- `gridOriginal` 计入通用派生图缓存用量和 LRU 清理，不计入“已下载云端预览”的独立额度。
- “清除预览缓存”和现有维护流程会连同其他派生图一起清除它；不新增第二套目录或清理机制。
- 不对既有图库执行自动重建。升级后所有资产仍先显示正方形，用户按来源决定是否占用额外空间。

## 验收摘要

- 未手动预热时，点击“原比例”不触发 2048px 预览、原文件、PhotoKit 或网络请求，卡片保持正方形。
- 手动预热后，照片与视频均可显示最长边 512px 的原比例缓存，重启后仍可复用。
- 已下载的 2048px 云端预览本身不能让“原比例”模式生效；主网格仍得到正方形缓存。
- 模型与相似聚类输入、结果和缓存身份不因显示模式或 `gridOriginal` 改变。
- 合成 fixture 覆盖文件夹、假 PhotoKit、照片和视频；自动测试不得访问受保护真实图库。
