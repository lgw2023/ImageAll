# ADR-068：待审建议按门槛全部保留并流式写入

- 状态：已接受
- 日期：2026-09-02

## 背景

待审核建议此前共用一个“每标签上限”，默认只保留 Top 500。这个数量既出现在 Mac 与 Web
界面，也被特征近邻、个人模型和超级个人模型的生成路径读取。它会让高于用户所设门槛的结果
静默消失，而且“门槛”和“数量上限”同时存在时，用户很难判断审核队列为何不完整。

直接把上限替换成 `Int.max` 也不安全。App 内个人模型原先会在任务检查点中累计全局 Top-N，
直到扫描完成才一次写入。如果保留该算法，无上限队列会让检查点随图库规模增长，增加编码、
数据库提交和恢复成本。

审核网格仍需在队列扩大后保持交互稳定。现有的 100 条键集分页、审核后原位移除、选择与滚动
位置保持属于既有契约，不能因取消生成上限而退化。

## 决策

1. “最低分数门槛”是建议进入审核队列的唯一产品边界。生产生成路径保留门槛以上的全部结果，
   不再提供可配置的每标签数量上限。
2. 100 条审核分页、64 条个人模型持久化批次等仍是技术批大小，不是产品数量上限。
3. 特征近邻生成不再执行生产侧 Top-N 裁剪；保留可注入的可选裁剪只用于验证旧的排序契约。
4. App 内个人模型在每个 64 条扫描批次后，把命中结果与紧凑检查点放在同一个租约保护事务中
   提交。第一批先替换该标签/轨道的旧结果，后续批次追加；检查点不累计命中数组。
5. 已经入队的旧版有界任务继续按其载荷完成，避免改变运行中任务语义；新任务使用无限策略。
6. 审核页继续按 100 条键集分页。每页收藏状态一次批量读取；可见单元格使用可比较的展示快照，
   收藏、选择、缓存或布局未变化时，不因工作区其他状态发布而重算整批缩略图。
7. Mac 建议总览改成“生成中心 + 分组工作区”的视觉层级，明确显示“门槛以上全部保留”；Web
   同步移除数量控件。远程协议暂时保留可空旧字段以兼容解码，但 Host 不再接受写入上限。Mac
   审核总览没有照片选区，自动收起此时不可操作的标签检查器，把宽度交还给分组建议；进入某个标签的
   审核队列后再自动展开检查器，返回总览时重新收起，离开审核工作区则恢复进入前的检查器显隐状态。

## 取舍

- 队列、扫描耗时和数据库行数可能高于 Top 500；用户通过来源范围和各轨道门槛控制召回范围。
- 分页限制内存与首屏读取成本，流式批次限制任务检查点大小，并让长扫描的结果逐步持久化。
- 流式任务首批提交后可留下部分结果；任务失败或暂停时，已提交批次可继续审核和恢复，不需要
  重跑已确认的游标之前部分。
- 单元格仍会在自身选择、收藏、缓存版本、缩略图比例或恢复代次改变时刷新，这是必要刷新。

## 验证标准

- 超过 500 个合格候选时，特征近邻生产路径保留全部候选。
- App 内个人模型跨多个持久化批次时，所有命中均写入且检查点 `topHits` 为空。
- 审核首屏收藏状态按页一次读取，不再由每个缩略图各自创建读取任务。
- 既有有界 Top-N 回归仍通过，证明旧载荷与排序兼容。
- Mac 构建、相关模型测试和 Web 构建/审查回归通过。

自动化验证只使用合成数据库与临时缓存，不读取受保护的真实照片资料。
