# ADR-054：超级个人模型全库建议采用有界流水线与持久检查点

> 状态：已决定并实施（2026-08-07，项目所有者要求按顺序落实五项性能优化）
> 相关：`LOCAL-MODEL-MODULE-SPEC.md`、`ADR-044-LIBRARY-SLIMMING-AND-RECYCLE.md`、
> `LOCAL-TEST-DATA-SAFETY.md`

## 背景

“待审核建议”中的超级个人模型可以按一个标签扫描全部来源。旧路径先在主界面解析全部候选，再逐张加载
预览、生成 DINOv2 embedding 并打分。全库达到数万张时，图片读取、2048 像素预览落盘、缓存容量扫描和
逐项进度发布串在同一条长链上；退出 App 后也无法从可靠检查点继续。

已有个人线性头依赖当前 DINOv2 预处理的精确数值语义。性能改造不能静默替换裁剪、缩放、颜色或归一化
规则，也不能通过自动化读取受保护的真实照片来证明效果。

## 决策

1. 全库超级个人模型建议复用 `personalization.personalLibrarySuggestions` 持久任务。入队时冻结目录截止时间、
   来源集合、模型能力、阈值和每标签上限；界面留在建议总览显示任务进度，不提前打开尚无结果的审核队列。
2. App 本地运行时每批处理 64 个候选。图片数据最多 2 路并发预取，Core ML embedding 和个人头打分保持
   单路顺序执行，避免 HDD 随机读取完全串行，也避免多路推理争抢内存带宽。
3. 文件来源在冷路径继续使用既有 2048 预览渲染规则，但中间预览只在内存中存在，不写入通用派生图缓存。
   随后把编码器实际消费的 224×224 RGB 图以无损 PNG 写入独立、版本化、512 MiB 有界缓存。缓存地址包含
   catalog、asset、content revision、预处理 revision 和流水线 revision；命中时可跳过来源读取与缩放。
4. 既有 embedding 缓存继续以完整模型身份寻址。embedding 与 224 输入缓存都只在首次建立容量状态时枚举
   自有对象，之后用增量字节账本和摊销 O(1) 的最旧对象队列维护容量；不触碰其他缓存文件。macOS `/var`
   与 `/private/var` 路径统一规范化，避免把同一对象重复计数或误删刚发布对象。
5. 旧预览入口与 224 缓存入口必须产生逐元素完全相同的 embedding。缓存写入失败时，显式缓存填充不能把
   仅在内存中生成的结果报告为已持久化；个人头和既有 embedding 不需要重训。
6. 直接运行时的进度回调最多每 32 张或 200 ms 发布一次，并始终发布最终值；持久任务按 64 张事务提交，
   UI runner 最多每 300 ms 刷新一次，避免逐张触发主线程视图重算。
7. 每个持久批次原子保存 checked、skipped、above-threshold、游标和全局 Top-N 候选。暂停、取消、失败或
   App 退出后从最近已提交批次继续；最终建议替换与任务完成在同一数据库事务中发布，不能出现任务显示
   完成但建议尚未落库的窗口。

## 后果

- 首次文件来源扫描不再为模型预测额外持久化 2048 像素预览；复扫优先命中 embedding，embedding 被清理或
  模型切换时仍可复用兼容的 224 输入。
- 内存和 I/O 并发都有明确上限；吞吐提升不依赖无界任务组，也不会把 Core ML 推理改成多路并行。
- 任务拥有可审计的冻结范围和恢复点；用户可沿用现有暂停、继续和取消动作。
- 本决策不新增 migration，不读取或修改真实照片。自动化验证只使用合成目录、合成图片和 PhotoKit 假实现。

## 验收

- 4 张合成图片证明同时存在 2 路读取，且结果按单路模型执行全部产出；
- 旧入口与缓存输入入口的 384 个 embedding 元素完全相等；
- embedding 被移除后，命中 224 输入缓存可重新生成 embedding 且不再次调用图片加载；
- 130 个候选按 64、64、2 三批完成，只发布全局 Top-N；
- 第二批事务注入失败后，检查点保留首批 64 个进度，重试从该游标继续并正确完成；
- 派生图、缓存安全、Photos 图片加载与既有持久建议回归全部通过。
