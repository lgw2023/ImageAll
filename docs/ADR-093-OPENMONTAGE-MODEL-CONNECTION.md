# ADR-093 — 统一的 OpenAI 兼容模型连接

状态：已实施，2026-09-22。

## 问题

ADR-092 把底层环境变量表直接暴露给用户，但照片视觉工具仍固定 DashScope 地址和模型，模型表单只是元数据。填写参数不等于实际调用采用参数，用户还需理解 key_env，违反统一配置的预期。

## 决定

主设置改为接口地址、API Key、模型名。接受 Base URL 或完整 Chat Completions 地址；高级项包括温度、token 参数及上限、超时、响应格式、SDK Organization/Project、extra_body JSON。自动重试保持 0，避免自动重复上传/计费。其他专用图像、语音等服务独立保留在高级区，其协议不强行套用聊天模型。

凭据仍进设备钥匙串；统一模型凭据不再依赖其他工具服务开关。非敏感连接参数冻结在每次执行器启动的配置快照。旧设置的 connection 缺省可正常解码；没有连接时本地制作照常使用，视觉模型调用明确失败，不回退固定供应商。百炼按钮只是可编辑示例，不构成调用默认值或发起网络请求。

通过可复现源码覆盖层接通 private_photo_vision 和其工具包装，使用内置 OpenAI SDK，禁止重定向、自动重试与缺失配置回退。旧任务的 key_env 字段仅兼容解析，不再选择 shell 凭据。运行时按 App 统一凭据调用。照片范围/显式外发确认、源哈希、响应 schema 校验不变。SDK 的返回模型可能是服务端版本名，审计同时记录请求模型和返回模型；离线历史结果按自身记录验证，不依赖现在的设置。

这不是新增自动创作编排循环；统一连接接通现有照片视觉分析，固定模板仍不调用模型。未实施任意额外认证协议、Responses API、流式生成或自动图片外发。

## 验收

使用本机 loopback 假服务和两张 8×8 合成图片，证明配置地址、模型、温度、token 参数、extra_body 与凭据实际到达 SDK 请求；旧 key_env 不影响统一凭据；无授权/无配置不请求；HTTP 500 不重试；凭据不写入任务审计。Swift 验证 URL 规范化、旧配置兼容及附加字段防覆盖。完成构建后更新日常 App 并验证设置 UI。

2026-09-22 验收完成：loopback SDK/照片工具测试与 Swift 配置测试通过，Debug build-for-testing 和最终 build 通过。完整 App 包签名核验通过，保留旧 App 后更新日常版本。UI 完成模型连接保存、重新读取、合成 Key 清除，旧模型名、温度 0.7、96000 token 上限保留；百炼示例地址已保存，真实 Key 未读取或调用。现有执行器未强制重启，配置在下次启动时生效。
