# Mac 视频能力最短人工验收路线

适用项目：`/Volumes/SSD1/ImageAll/ImageAll.xcodeproj`，scheme `ImageAll`，目标 `My Mac`。日常从当前 Xcode 项目构建运行，不替换已安装 App。本页给出操作路线，不代表这些界面已全程验收；已通过证据见[完成矩阵](VIDEO-CAPABILITY-COMPLETION-MATRIX.md)。网页和 iPhone 不在本次范围。

## 1. 准备合成素材

在项目根运行（需要本机 FFmpeg 与 ffprobe）：

```sh
python3 scripts/create_video_acceptance_fixtures.py --output /Volumes/SSD1/.codex-builds/video-completion-20260927/manual-acceptance-inputs
```

脚本只接受不存在的新目录；重复运行请改成新的目录名。不会覆盖旧素材或结果。当前机器已生成上述目录，五个媒体文件均通过 ffprobe 与 FFmpeg 全片解码，目录中的 `fixture-manifest.json` 记录 SHA、媒体信息和预期值。该 manifest 是输入说明，不是 App 验收报告。

| 文件 | 预期 |
|---|---|
| `01-audio-time-gps.mp4` | 横屏、3秒、30fps、1条低音量合成音轨；内嵌时间2024-06-15 08:30 UTC、坐标35N/139E |
| `02-exact-copy.mp4` | 与01完整字节相同，唯一应与01形成精确组的副本 |
| `03-same-stream-different-container.mov` | 同一音视频流重封装为MOV，完整字节不同，不能称为精确相同 |
| `04-portrait-silent.mp4` | 竖屏、2秒、无音轨、不同内容；没有人为填充拍摄时间或GPS |
| `05-photo.jpg` | 橙色合成照片，用于照片分支和混合故事 |

只连接该合成目录。不要连接、选择、扫描或清理受保护的HDD2真实媒体；本路线不授权真实Photos/iCloud读取或下载。已有日常来源不得用来代替合成素材。后续自动化仍使用独立fixture和直接XCTest，不启动生产Photos宿主。

## 2. Xcode与观看整理

1. 在Xcode打开上述工程，选择ImageAll/My Mac，构建运行。当前工作区含并行未提交改动，运行记录应同时保存HEAD和改动清单；不能称为纯提交版本。
2. 使用“连接文件夹…”（空库入口可能显示“连接照片文件夹…”），仅选择合成目录。索引后选择“视频”媒体页，预期4个视频；照片页预期1张。筛选前先清除已有标签/状态筛选。
3. 打开01视频，播放/暂停、拖动进度、选择1.5×、调低音量/静音、进入/退出全屏。“视频信息”应显示30fps和1条音轨；04应显示无音轨。系统播放器入口需单独实际点击并核对打开的是选中素材。
4. 为01添加一个专用验收标签并收藏，切到下一视频再返回。关闭再从Xcode运行，核对人工标签与收藏保留、照片事实未被修改。记录具体标签名和资产，不只记“成功”。
5. 播放时快速切换、关闭大图、切换来源。离开App再返回应停止旧声音并保持暂停；记录实际焦点动作和结果。通知集成测试通过不代替这一步。

## 3. 时间、筛选与地图

1. 在01详情核对拍摄时间与GPS：原始UTC为08:30，北京时区显示应为16:30；以界面声明的时区为准。04缺失信息不应变成拍摄时间或伪坐标。
2. 使用“视频时长”“画面方向”筛选，验证2秒竖屏与3秒横屏分开；使用“视频时长：长到短”和“文件大小：大到小”确认数值排序。回到照片页不残留视频计数。
3. 在地图选择合成来源，按需显式更新位置。视频范围能定位35N/139E，选择资产后详情可播放；照片/视频/混合范围数量各自一致。缺GPS的视频不应产生伪地图点。
4. 云端不可用、主动获取、取消、授权失效仅看已有fake测试证据；本路线不操作真实Photos，也不为凑验收下载真实视频。

## 4. 多帧、建议与精确去重

1. 在当前视频大图的“多帧分析”菜单点击“分析当前视频（复用有效帧）”。应显示最多5帧及时间点；点击时间点定位实际视频。再次执行应复用有效结果，取消后可重试。
2. 已分析多个视频后点击“比较已分析视频的内容候选”。候选只是内容相似提示，不能直接作为字节相同或自动删除依据。短小测试图案不保证模型一定召回候选，空结果不是精确去重结果。
3. 视频模型可用时，在视频域选择样本、训练或选择模型、生成建议，在审核大图播放并确认/拒绝/撤销，再重新读取人工事实。缺模型时应有明确说明，不产生假成功；照片模型槽及照片人工事实保持原状。此路线不调用付费模型。
4. 在瘦身入口对合成来源显式执行完整视频字节分析。仅01/02应形成精确组；03虽同流也不应进入该组。比较窗口核对时长、大小、来源、收藏保护和保留依据，视频能播放并前后切换。
5. 回收/恢复仅适用于本脚本新建的合成文件，并须先明确授权该具体fixture操作。此页本身不执行回收；没有该授权时只验只读比较，将回收/恢复标为未运行。已有自动化fixture回收恢复证据可独立引用。

## 5. 混合故事与成片

1. 从合成标签入口“创建时光故事…”或故事工作区创建项目，加入05照片与01视频。
2. 选择视频镜头，点击“预览与编辑视频片段”，填写入点0.2秒、出点0.8秒、原声25%，点击“使用片段”。零长度/越界应禁止提交。将视频移到照片之前，保存并重新打开故事，确认范围、音量和顺序保留。
3. 选择“导出横屏 MP4（16:9）…”并保存到合成目录之外的新输出路径；使用“播放上次导出的 MP4”重开。应看到运动的视频片段而非静态封面，方向正确、原声受控、照片仍正常显示。未录制实际操作时不能把模型测试当这条UI路线已通过。
4. OpenMontage混合任务有独立的合成真实执行器证据。日常Xcode运行不要求打包发布；如要发布或手工替换，另按[发布门禁](OPENMONTAGE-RELEASE.md)执行。不要直接修改Runtime种子或触发真实模型调用。
