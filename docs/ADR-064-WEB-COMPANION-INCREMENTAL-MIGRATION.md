# ADR-064：Web Companion 绞杀式迁移、默认切换与旧版退出

> 状态：已决定
>
> 日期：2026-08-31
> 相关：`ADR-063-WEB-COMPANION-REACT-ARCHITECTURE.md`、
> `web-companion-refactor/FEATURE-PARITY-MATRIX.md`

## 背景

旧 Web Companion 虽为超大静态单体，但已承载广泛的图库、审核、训练、瘦身、地图、来源、存储、
会话、键盘、触控、焦点和浏览历史语义。仓库中的 `WEB-COMPANION-PARITY-SPEC.md` 已累积 381 条
行为契约。一次性替换会把“代码可编译”错误等同于“产品能力已替代”。

项目要求尽快形成可运行纵向闭环，同时禁止提前删除旧实现、降低安全策略或访问受保护真实照片。

## 决策

### 1. 采用绞杀式并行入口

迁移期间（默认切换前）：

- `/`、`/index.html`、`/app.js`、`/app.css` 继续提供旧版；
- `/web-v2/` 提供新版；
- 两者使用同一 Host API、同一认证、同一数据真相；
- 不在浏览器复制数据库或业务状态机；
- 新版未实现的工作流提供明确“在旧版打开”入口，并保留可恢复的图库上下文；
- 旧版不反向依赖新版组件。

### 2. 纵向切片顺序

每个切片必须包含真实 API、加载/空/错/权限、桌面/窄屏、键盘、自动化和截图：

1. 连接、账号/配对、会话恢复、断线重连；
2. 来源选择与图库虚拟化浏览；
3. 搜索、筛选、排序和 URL/历史恢复；
4. 单选、多选、检查器和批量上下文操作；
5. 灯箱、图片缩放平移、视频和相邻预取；
6. 收藏、标签、标签建议和撤销；
7. 审阅总览、队列、P/X/U、历史和恢复；
8. 训练、运行记录和异常恢复；
9. 图库瘦身、相似聚类、回收站和删除确认；
10. 图库总览、世界地图、来源/存储维护、设置和导出。

若某条更短的闭环能显著降低风险，可调整同一阶段内的次序；必须先更新本 ADR 或实时计划，不能
静默改变产品语义。

### 3. 每个切片的完成定义

只有同时满足以下条件，矩阵状态才可从 `foundation`/`in-progress` 改为
`parity-proven`：

- UI 不是静态占位，已调用真实 Host endpoint；
- 权限和能力门禁来自 Host；
- 成功、空、加载、失败、离线和重试都有可感知状态；
- 主要鼠标、键盘和触控操作可用；
- 前进/后退/刷新不会丢失该切片声明的上下文；
- 单元/组件/API 契约/E2E 中适用层级通过；
- 1440×960、1024×768、390×844 视觉证据齐全；
- 没有访问真实 PhotoKit 或 `/Volumes/HDD2`；
- 局部验证的报告明确边界，不宣称整个重构完成。

### 4. 新旧上下文桥

迁移入口只传递非敏感、可验证的上下文：route、media kind、source/tag IDs、query、sort、filter 和
可选 asset ID。桥接参数必须经过白名单解析，不能包含 token、密码、绝对路径、书签或任意 JSON。

已选择的多个 asset ID、精确滚动像素和表单草稿默认不跨实现传递；新版对应切片完成后，由统一路由
与工作区状态负责内部恢复。旧版入口必须明确说明未迁移的临时状态范围。

### 5. 构建产物和提交

每个稳定阶段：

1. 先提交源代码、测试和文档；
2. 用锁定依赖生成 `WebCompanionV2` 产物；
3. 运行 manifest/bundle hash 校验；
4. 只暂存本阶段相关文件；
5. 使用 Conventional Commit 本地提交；
6. 不 push、不 amend、不 squash、不修改持久 Git 配置。

构建产物必须可由脚本确定性重建。生成目录中的未知文件会使 Swift 资源契约失败，而不是被静默提供。

### 6. 默认入口切换门

只有以下条件全部通过，`/` 才切换到新版：

- 功能矩阵无未解释的 P0/P1 关键缺口；
- 主要日常工作流端到端可用；
- 新版三档视口、键盘、VoiceOver/WCAG、大图库性能通过；
- Swift 清单、MIME、路径、CSP、Cookie、Origin、Range 和打包契约通过；
- Service Worker 升级不会留下旧缓存陷阱；
- `build-for-testing` 通过；
- 已记录前后对比截图、遗留债务和回滚命令；
- 本地 Git 有切换前恢复节点。

切换后 `/legacy/` 保留至少一个稳定发布周期，并提供清晰但不抢占主界面的回滚入口。由于旧版
不解析新版 URL 查询状态，而且必需工作流已经迁完，返回旧版故意从旧版默认工作区开始；不传递
token、密码、绝对路径、选择或表单草稿，也不伪装成无损上下文桥。

### 6.1 2026-08-31 实施状态

- 根入口 `/` 与 `/index.html` 以 `302` 跳转到 `/web-v2/gallery`；新版成为默认入口。
- `/legacy/` 与 `/legacy/index.html` 继续交付冻结的旧版，供一个稳定发布周期内人工回退。
- 根 `/service-worker.js` 始终交付已审计的 V2 worker，避免访问旧版时把默认应用降级到旧
  Service Worker；旧版静态资源仍保留在 App bundle。
- 默认切换是独立提交 `66284a2a`，未涉及数据库 migration、PhotoKit/GRDB 语义或用户数据。
- 当前不删除旧版：人工 VoiceOver 听读与真实 App/真实 MapLibre 的授权验收仍需由项目所有者在
  发布环境完成。该限制不扩大自动化权限，自动化仍不得访问 HDD2 受保护数据。

### 7. 旧版删除门

删除旧实现前必须证明：

- 生产入口、文档和测试不再引用旧路由；
- 无旧 DOM selector 或静态资源契约仍被使用；
- Swift 不再映射旧资源；
- 根 Service Worker 不再引用旧版本缓存或脚本；
- 旧版保留期没有无法由新版完成的关键任务；
- Git 中存在可构建、可恢复的切换前提交。

删除是单独阶段和单独提交，不与默认切换混在同一提交。

## 备选方案

### 页面级 iframe 混合

能快速嵌入旧页面，但会产生双焦点、双历史、双 Service Worker/滚动上下文和更差的可访问性。拒绝。

### 组件级把新 React 挂进旧 DOM

适合很小的孤立控件，但现有全局状态和 DOM 协调会让所有权更模糊，且无法形成清晰路由、查询和
设计系统边界。只允许作为一次性诊断，不作为迁移架构。

### 一次性 feature flag 切换

没有逐工作流回滚和验证粒度。拒绝。

## 取舍

- 并行入口短期增加 bundle 和维护成本；换取持续可运行和精确回滚。
- 上下文桥有意不传全部临时状态；换取不泄露敏感数据和不把旧状态模型固化进新架构。
- 旧版保留期占用资源；换取发现长尾能力缺口的时间。

## 迁移影响

新增 `/web-v2/` Host 入口、功能矩阵状态、跨实现入口和发布门。GRDB、PhotoKit、远程协议及现有写入
语义不因本 ADR 改变。

## 回滚

- 预览期：停止暴露 `/web-v2/`，旧版不受影响；
- 默认切换期：本地执行 `git revert 66284a2a` 并重新构建；根入口和根 Service Worker 都恢复到
  切换前版本，不动数据库 migration；
- 旧版保留期：直接使用 `/legacy/`；
- 删除后：恢复切换前 Git 节点并重新构建 App。

任何回滚都不得回滚数据库 migration、删除用户数据或绕过 Host 权限。

## 验证

每个阶段更新 `web-companion-refactor/FEATURE-PARITY-MATRIX.md`、实时计划、适用测试报告和截图。
最终门以 `web-companion-refactor/ACCEPTANCE-GATES.md` 为准。
