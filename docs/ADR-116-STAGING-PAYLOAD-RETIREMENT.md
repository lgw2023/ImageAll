# ADR-116：暂存载荷的显式受控收尾

日期：2026-10-26。状态：Mac 显式收尾实现、失败/中断门、目录库与日常 Xcode 入口验收通过。范围：P4 第一纵切片，Mac 接收暂存。

接收 actor 之外存在 HTTP 临时文件写入与入库读取，因此 actor 串行化本身不是清理租约。
接收器整个生命周期及接收包入库期间持有根目录共享 flock；收尾使用非阻塞排他 flock，
有活跃参与者就拒绝。租约跨进程，进程退出由内核释放，不靠过期时间猜测无人使用。

第一版只处理新版本创建且登记 ownershipVersion 的任务。历史暂存不自动补登记。
操作显式发起，先完整核验最终归档与数据库资源覆盖、发布和来源引用，核对暂存清单、
事实和资源登记；不接受传输 100% 或孤立发布行作为许可。

为缩小删除面的复杂度，第一版释放精确登记的 resources 载荷，保留零字节占位文件、
清单、事实、session 和持久收尾记录。通过 no-follow 目录/文件句柄核对身份、单链接和
版本后 ftruncate + fsync，不递归删除或按路径重新打开写入。释放字节是逻辑字节；
APFS 共享块意味着它不等于实际可用空间增加。

收尾意图先于载荷变更持久化；一旦存在意图，接收器拒绝修复、重传和发现该暂存包，
完成状态继续来自数据库发布凭据。失败或进程中断保留记录；重入必须再次完整审计
最终副本，接受同一已登记对象的原尺寸或已清零尺寸，不接纳替换对象或新增文件。权限恢复等版本变化必须重新读取完整载荷并匹配 SHA，不能仅凭身份/尺寸重新接纳。
清理错误独立于发布状态，不回滚已发布图库。最终原件与必要完成记录不属于清理对象。

此阶段不做后台自动收尾、手机载荷回收、历史目录扫描或通用存储管理。它们在 Mac
失败门通过后另行接入。合作进程遵循租约；不声称阻止同用户恶意进程任意篡改最终图库。

验收：活跃接收/读取、未发布、引用不全、同大小损坏、路径/对象替换、硬链接拒绝；
释放中断后同任务重入且发布来源不变；成功后普通重启仍不全读原件，最终完整复验通过。


## 证据与范围

RED/GREEN 包括目录替换、未登记事实、等字节目标替换和权限恢复。独立进程在一个
资源释放后 SIGSTOP，再由外部 SIGKILL；另一进程成功完成余下资源，重复释放为零。
中断期间另一进程无法取得租约，SIGKILL 后内核正常释放。此证据针对进程中断，不
宣称突然断电的持久顺序保证。意图写入不完整时拒绝重入、保留现场，不猜测恢复。

Mac 目录库集成先要求发布和真实资源/来源绑定；清理权限失败保留可浏览来源，重试
完成后原件与 Mac 收藏不变。没有数据库 schema 变更，没有修改最终全量验证或冷恢复
门。普通已完成重启仍读取紧凑发布凭据。

首版根目录租约有意保守：需停止该接收目录的整个服务，不能在同根其他任务活跃时
并行释放。自动收尾与手机临时载荷回收另作后续切片。逻辑字节释放不等于物理空间收益。
