## 统一任务与恢复模型

主状态建议为：准备 → 传输 → 验证/发布 → 可浏览；暂停、可恢复失败、需要用户决定为独立状态。内部细分阶段保留，但用户只处理一个任务。

- taskID、来源安装身份/epoch、选择集合摘要、Mac 目的身份与存储位置绑定。资源版本和整理信息版本分别冻结，整理快照更新不创建新传输任务。
- 持久化用户意图：继续上传、仅发布已接收子集、暂停。重启恢复意图，但“暂停”不能自动变成继续；新设备或身份变化必须进入明确的恢复决策。
- 接收端 durable offset 是续传依据，ACK 在对应数据及日志提交之后发出。持久化历史回执不等于当前完整性证明；恢复要验证收据绑定、存储根身份及对应对象，发现异常只降级受影响资源。
- 未完成资源按提交偏移续传，重放同一块幂等；冲突偏移、不同摘要、旧会话请求拒绝。低频持久化事实增量与大资源传输分离。
- 所有暂停记录实际触发点、原因码、阶段、最后提交偏移、连接世代与时间。未知原因明确为未知，不能从 CancellationError 推断 USB 拔线。
- iOS 保持用户主动开始任务期间的前台体验；进入后台先提交断点，解释何时可继续，不承诺系统不允许的无限后台执行。不得靠保持镜像、修改系统网络或自动反复拉起 App 保活。

## 有界数据通路与可解释速度

先测量，再改瓶颈。用统一 taskID 关联手机 PhotoKit 准备、手机文件读、USB 发/收、ACK、接收写盘、journal 提交和最终验证；记录每阶段字节、活跃时间、排队时间与错误，不收集照片名称/内容。

1. 对当前“HTTP incoming 临时文件 → 提交到 package”的双写路径做原型：优先固定窗口流式接收，增量摘要，写入最终归属的未发布对象。断流时未提交尾部不可成为 ACK 数据；进程被杀后恢复到最后 durable offset。
2. 将逐块整体重写 journal 改成有版本的追加记录或 SQLite 事务账本，采用有界批量提交与定期压缩；格式升级可回滚，旧断点可读。不能为了速度提前 ACK。
3. 从单传输流、有界缓冲开始，测量小文件往返开销后才引入小文件批量请求或有限流水线。传输、校验、缩略图分别排队，共享字节预算，避免相互争用使“传完”更慢。
4. 事件通道每连接世代最多一条，旧世代确定关闭；迟到事件不能更新新任务。重连有上限与退避，控制请求不排在大文件数据后无限等待。
5. UI 同时显示当前阶段、阶段进度、本轮新增字节、待处理项；只有上传阶段显示网络速率。缓存命中、跳过字节不算新增吞吐，验证读盘速度不叫传输速度。

## 验证、入库、发布与存储所有权

目标是**一份受管理的最终媒体对象集合**。来源只引用它；多相簿/集合用关系表示，不复制文件。4,169 资源包含一项媒体的不同资源，不能因主网格只有 2,866 个入口就删掉其余资源。

- 接收期间增量校验并记录资源摘要；最终发布必须证明所发布的实际持久化字节与清单一致。计划把完整最终读取集中成一次验证流，生成有版本的验证凭据供封存/入库/来源发布消费；不能简单删掉 verify 调用。
- 凭据绑定任务、清单摘要、资源摘要与大小、事实快照、存储对象身份、验证器版本。不能仅凭 size/mtime 认为文件未变；受管理不等于防篡改，换卷、变化或不可信状态必须重新验证。
- 同卷优先原子改名提升接收对象；跨卷采用流式复制+摘要并验证目标，然后提升。文件系统与 SQLite 无法假装成一个原子事务：持久化 prepared/published/catalogCommitted 中间状态，启动可幂等协调孤儿与待提交对象。
- 来源发布仅在资源和事实均符合门禁后原子可见；重放、冷启动保持 source/asset 身份，不覆盖 Mac 后续编辑。
- 常规启动读取紧凑发布凭据，不遍历 75GB；用户主动“完整复验”另作可取消、可续跑任务，失败不能破坏已发布数据。
- 事实快照中的来源相簿/层级/空相簿/顺序、红心、标签与集合分别有计数及逐项摘要。零项必须明确，不能把“尚未读取”写作 0。以后双向编辑需要单独冲突策略，本轮导入不暗中启用回写手机。

## 文件清理作为产品能力

建立 artifact registry：每个文件注明 owner taskID、类别、创建版本、是否有活跃读写者、引用关系、清理前置条件和清理结果。类别至少为最终原件、事实/完成凭据、可恢复 staging、可重建预览、诊断、合成测试、构建产物。

- 最终原件和必要凭据长期保留；预览缓存归 App 正常 LRU/容量管理，避免导入完成即全部清空导致再次解码。
- staging 只有在最终目标验证、入库/发布凭据、来源引用和资源覆盖检查都通过、无活跃续传租约后才可回收。清理失败只记录，不回滚已完成入库。
- 部分完成保留未交付项的身份和原因记录；后续重试针对差集，新事实版本不重传已确认且未变化资源。错误新建批次须有废弃/回收流程，不能仅按目录名删除。
- 手机任务最终收尾只在收到目标完整核验的专用完成回执后释放残余导出载荷，保留任务和完成记录，不改 PhotoKit 原件或选片。现有逐资源校验后的有界缓存窗口释放继续保留；该机制与整项任务最终收尾的区别见 ADR-117。
- 文件删除使用规范路径、no-follow/句柄检查、同对象确认和精确允许清单，拒绝父目录与符号链接绕过。当前真实 HDD2 清理仍受 LOCAL-TEST-DATA-SAFETY 的具体授权要求约束。
- 开发任务每轮使用一个唯一工作目录；成功保存小型报告、版本指纹及再现脚本后清理构建和合成数据。失败现场也有明确容量/保留期，禁止无边界产生新目录。

2026-10-20实测补充：原批次暂存经具体授权及两份逐资源核验后已删除。其逻辑体积约75.25GB，但APFS卷立即可用空间只增加8.30MiB，具体共享块/快照归属未测。后续存储指标必须区分逻辑字节、分配块统计和实际可用空间变化，不能把两条路径并存直接描述为占用了两倍独占物理空间。清理权限和结果见[单次清理记录](USB-IMPORT-CLEANUP-20261020.md)。
