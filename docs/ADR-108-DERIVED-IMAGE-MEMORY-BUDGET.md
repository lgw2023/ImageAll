# ADR-108：原件派生图的临时内存预算

- 状态：Accepted（已实现、合成验证通过；实机网格和 RAW 预览通过，其余 UI 验收见 ADR-107）
- 日期：2026-10-19
- 范围：本地文件来源（含已入库 iPhone 来源）的冷缓存图片解码及视频封面生成
- 替代：ADR-058 关于昂贵派生图生成无资源准入的部分；不改 UI 请求提交、缓存命中、PhotoKit 或模型批次契约

## 事实与影响

真实 iPhone 来源首次点击后，独立 1 GiB 保护在物理内存 1,152,256,352 字节终止 Mac App。
入库及整理信息只读对账仍通过。先前冷启动验收没有覆盖真实网格生成，不能算浏览验收通过。

受控 48MP / 45MiB 合成 JPEG 实验把问题拆成读取与解码：旧 `readAllBytes` 从空 Data 分块扩容，
连续串行读取约十次即超过 512MiB 测试保护；不经过 ImageIO 仍复现，外围 autoreleasepool 不能消除。
按已打开句柄的 fstat 大小 reserveCapacity 后，32 次同形读取约 48MiB 物理峰值。
完整单路渲染约 80MiB，但 12 路同时读大图仍超过测试预算。因此需要同时修复扩容和并发叠加。
这证明当前平台上的持续分配驻留问题，不将其无证据命名为底层 Foundation 引用泄漏。

## 决策

1. 安全读取先依据同一只读 no-follow 文件描述符预留容量，仍读取到 EOF；前后指纹、路径替换检测及错误合同不变。
2. 缓存未命中的原件生成共享 256MiB **估算工作集**预算。图片按两倍压缩字节加 32MiB 计费；
   RAW 独占预算；视频按 128MiB 计费，不能以整段视频文件大小计费。超过预算的单项独占执行。
   此预算是准入估计，不是对 ImageIO/AVFoundation 实际内存的硬保证；独立进程保护仍保留。
3. 等待者按 FIFO 取得预算，取消等待及时移除；取消、异常和成功都归还预算。昂贵同步工作离开 actor
   隔离执行，并在归还预算前释放 autoreleased 临时对象。缓存命中和同键合并不占解码预算。
4. 保持图片尺寸、方向、像素与编码验证、来源只读授权、原件完整性、发布原子性和整理编辑保留合同。
5. 不用真实照片做压力或故障注入。先以独立 512MiB 保护运行合成大图串行/突发、冷暖缓存、取消及失败测试，
   再在 1GiB 保护下通过当前 Xcode 工程验收真实来源；保护触发不得自动循环重启。

## 实机补充：RAW 预览必须避免完整传感器解码

21:30 受控实机复验仍触发1GiB保护。Xcode暂停帧确认是85,551,616字节的富士RAW，
在生成512像素网格图的aspectFill/颜色转换阶段；独占预算不能阻止单个RAW解码峰值。
`ThumbnailMaxPixelSize`只限制输出尺寸，`CreateThumbnailFromImageAlways`仍要求从完整图生成。

浏览专用路径优先使用现有LibRaw桥的unpack_thumb（不调用unpack/dcraw_process），
将内嵌JPEG作为缩略图来源；JPEG没有方向字段时只从原容器转移方向元数据。
ImageIO对大RAW容器只能提取已有缩略图；没有内嵌预览时返回原有解码失败占位，不自动展开完整sensor图，
不改变原件、资产身份或归档完成状态。小于等于2048×2048的普通TIFF容器保留既有兼容路径。
浏览调用显式选择此策略；现有感知哈希消费者的解码契约保持不变。

前述JPEG压力验证没有覆盖RAW单项工作集，因此不作为真实RAW浏览通过的证据。

最终有效的 40MP 合成 DNG 经真实 LibRaw 提取预览；旧渲染器单项触发 512MiB 测试保护，
新渲染器完成 384 次，物理峰值约 94MiB。当前 Xcode 运行版已实际显示照片网格、RAW 单图和
视频网格；本轮约 26 分钟时物理峰值约 673MiB、当前约 433MiB，1GiB 独立保护未触发。
这是本轮浏览观察，不是所有媒体格式及长时间使用的内存上限保证。完整 AX 读取连续超时，
视频播放进度与相簿展开没有完成证据；保留验收缺口，不重复重启 App。
