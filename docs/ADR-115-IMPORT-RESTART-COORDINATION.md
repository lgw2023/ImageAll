# ADR-115：以持久发布记录协调导入重启

日期：2026-10-26。状态：实现、本地中断门、日常Xcode与真实USB双端重启验收通过。范围：P3 恢复收口。

## 核对结果

`migration_import` 的 prepared 记录先于归档复制，catalogCommitted 与条目同事务提交；
原生来源、资产投影和 `phone_library_publication` 同事务提交。发布记录已经是日常
任务状态的持久完成凭据，绑定迁移、清单、事实版本、项目数和来源。旧的
`migration_completion_receipt` 用于独立备份恢复验证，不应把其双副本审计强加到日常启动。

现行启动协调仅枚举 catalogCommitted，遗漏归档已改名落盘但仍为 prepared 的窗口。
此时重试原始导入可恢复，但启动发现不了，且不应依赖已消失的接收暂存。

整理事实也存在文件已发布、数据库版本未提交的窗口；原启动发布审计会拒绝不一致，
却没有接续事实事务。新增进程中断测试已复现。

## 最小决定

启动候选枚举包含 prepared；仅按既有数据库记录定位准确目标，不扫描目录寻找批次。
对未完成目标重新完整验证清单和实际字节，绑定原迁移、来源、目标路径与计数，再复用
原入库事务完成条目写入，最后执行原生发布完整审计和事务。不存在可用目标时保留
prepared 并提示需要恢复传输，不凭空创建或覆盖归档。损坏或身份冲突保留现场并拒绝。
单批次错误不能阻止其他待恢复批次被发现与处理。

已入库但未发布且无本次内存凭据时，先比较归档事实文件与数据库版本；不一致时
通过现有完整校验的事实协调事务恢复，再执行发布全量审计。匹配时只读小型事实
元数据。显式旧内存凭据仍拒绝，不因协调而悄悄认作有效。

已完成的普通启动、重复发布和任务状态查询继续只核对数据库发布凭据，不读取原件，
不重新应用手机事实或覆盖 Mac 编辑。这是过去已完成发布的记录，不表示启动重新
检测了磁盘静默损坏；主动完整复验继续读取实际字节。内存校验结果不跨进程持久化。
有效完成记录还必须对应 catalogCommitted 状态；未完成任务不得凭孤立发布行呈现可浏览。

不改 schema、既有 migration、最终全量 SHA、内存阈值或真实数据，不加入自动清理。
文件系统与 SQLite 仍为可恢复的分阶段提交，不声明跨存储原子事务或断电 fsync 保证。

## 门禁

先 RED 证明 prepared 目标被遗漏，再验证归档改名后、入库事务中、入库提交后、发布
事务中与提交后回应前的进程中断：未发布前零原生可见资产，恢复后只有一份身份。
已完成任务在新进程无接收暂存时状态可浏览、诊断原件读取为零、Mac 编辑不变。
损坏、错误身份、提交前换对象拒绝，失败批次不阻塞其他批次。最后独立真实 USB
完成后重启 Host/手机，验证同任务可浏览、零新增上传及无全量读取。
