# ADR-062：缩略图自动恢复与缓存会话生命周期

- 状态：Accepted
- 日期：2026-08-29
- 范围：派生图片缓存句柄、图库瘦身到期清理、Mac 照片网格缩略图恢复
- 关联：ADR-058 图片与模型流水线由系统资源调度
- 安全边界：不改变来源授权、来源只读保护、PhotoKit 写入边界、缓存路径校验或分页状态

## 背景

一次到期回收清理处理了 827 个条目。`AppOwnedAssetPixelCachePurger` 为每个资产打开派生缓存的
`v1`、`staging` 和 `objects` 三个锚定目录句柄，却没有关闭会话，运行进程因此保留 2,481 个目录句柄。
已在内存中的缩略图仍可显示，后续缓存读取和生成逐步失败；网格单元耗尽局部重试后停在占位符，只能通过
滚出再滚回或重启 App 重新触发。

局部重试不能解决系统性故障。每个可见单元原有最多八次内部重试，外层还会再次请求；大量不同资产同时失败
时会放大 I/O 压力，而且没有一个共享的“后端已恢复”信号。

## 决策

1. `DerivedImageAnchoredCacheSession` 以引用对象拥有三个目录句柄。`closeHandles()` 必须幂等，`deinit`
   作为遗漏显式关闭时的最后防线；成功打开、实际关闭、当前活动数和活动高水位保留轻量进程内诊断计数。
2. 所有正常调用仍在最小作用域显式关闭会话。自动析构是防御措施，不替代清晰的 `defer` 所有权。
3. 一次 `purgeExpired` 及其 Photos 回收收敛、异常中断恢复和文件回收清理共享一个短生命周期缓存会话。
   单条显式清理仍可独立创建会话；批次会话建立失败时退回逐项失败隔离，不能在进入回收状态机前让整批失败。
4. 不恢复 ADR-058 已移除的生产固定并发上限。正常缩略图继续由 Swift、PhotoKit、ImageIO 和文件系统按
   资源调度；本决策只在系统性失败时合并恢复请求。
5. Mac 网格在两秒窗口内观察到至少三个不同资产的瞬时加载失败后，进入共享恢复状态。只运行一个探针循环，
   从 250 毫秒指数退避到最多 5 秒；其余单元停止各自扩大重试。单个资产失败不会触发全局恢复。
6. 探针成功后递增统一恢复 generation。仍可见单元的 SwiftUI task identity 随 generation 改变并自动重载，
   不要求用户滚动、清缓存或重启。来源导航和删除导致加载 epoch 改变时取消旧恢复循环。
7. 恢复期间在网格顶部显示非阻塞的“正在恢复缩略图…”状态。失败单元、选择、分页、排序、滚动位置和缓存
   内容不被重置；恢复提示不拦截鼠标或键盘操作。共享恢复开始、成功和无可用探针时写入不含资产标识的
   `ThumbnailRecovery` 统一日志。

## 验收标准

1. 使用临时目录和合成资产批量清理 12 个以上条目，清理前后进程文件描述符回到基线，缓存会话打开和关闭
   各一次，活动会话数不增长。
2. 调用者丢弃 20 个未显式关闭的成功缓存会话后，文件描述符数不增长；显式关闭后的析构不重复关闭句柄。
3. 缓存对象路径校验失败并抛错时，已打开的缓存会话仍然关闭；某资产没有衍生缓存条目时，即使衍生缓存
   布局不可用，也不阻断其独立的 Photos 原图缓存清理。
4. 六个不同资产同时失败时只建立一个恢复循环；恢复成功只发布一次 generation，局部单资产重试契约不变。
5. 恢复 generation 是缩略图单元可见状态的一部分，变化后会重新执行当前可见单元的加载 task。
6. `build-for-testing`、派生缓存、回收服务、工作区模型和缩略图呈现定向回归通过。自动化只使用临时数据库、
   临时缓存和合成媒体，不启动 production App，不读取受保护真实照片。

## 后果与边界

缓存会话从值类型变为自动托管引用类型，复制会话不再复制所有权；所有副本共享同一组句柄，关闭操作全局幂等。
恢复探针可能在外置盘长期离线时持续低频运行并保持提示，这是为了在介质重新出现时自动恢复。来源事实已被目录
协调更新为不可用、授权受限或资产不合格时，仍按既有明确错误终止，不进入系统性恢复。

本决策不自动清空缓存、不重扫来源、不修改照片，也不承诺真实图库的固定延迟或吞吐。真实数据运行验收仍需单独
只读授权；本切片的自动化证据只证明隔离状态机、句柄平衡和恢复触发行为。
