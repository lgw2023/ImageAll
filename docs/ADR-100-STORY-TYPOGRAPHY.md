# ADR-100 · 时光故事系统字体与制作约束

日期：2026-09-23。状态：实施。

## 决策

右侧「创作」增加故事级文字样式；使用可搜索、带中文样例的字体下拉面板，不另开制作弹窗。字体列表从 NSFontManager 读取本机已安装字体。标题/章节和字幕共享字体、常规/粗体，可分别调整标题 24–120 px、字幕 16–80 px。字号以画幅短边 1080 px 为参考；预览随画布缩放。

项目存储可选 typography，兼容旧项目解码，默认苹方、标题 64、字幕 36、常规。修改进入既有撤销与项目指纹机制；创作/提交期间沿用编辑锁。自动导演与 Atelier 请求中的创作意图包含文字样式约束；可编辑方案不拥有该字段，应用方案保持 ImageAll 的设置。自由场景 Agent 收到的是明确约束，其自由代码输出仍需审片。

原生 AVFoundation 渲染使用 NSFont；故事包 template 携带 fontFamily/titleFontSize/captionFontSize/fontWeight；固定 PhotoStory 与诗句模板显式消费它们。扩展包 schema 和 edit-decisions schema 一起更新，由 typography_patch.py 对固定版本运行时幂等应用；包 schema 摘要同步更新。runtime 内容摘要确保下次启动使用新组件。

本切片针对本机已安装字体。字体名称作为 CSS 字符串引用；缺失字形允许系统回退。不会上传、复制字体文件或联网下载字体。跨机器未安装相同字体时不保证排版相同；字体文件打包和逐字形覆盖检查不在本切片。

## 2026-09-23 执行器就绪校验修复

发现扩展 schema 的 SHA-256 已与 Swift 导出端一致，但 Python readiness 仍按上游旧 lock 校验，导致后台进程存活却显示依赖未就绪。打包补丁同步写入经审核的固定扩展摘要及长度/行数，并将原上游 lock 完整保留为来源记录。补丁拒绝未知 schema 或未知 lock，不取消摘要校验、不将任意当前文件自动视为可信。运行时内容摘要随 lock 变化，沿用现有完成当前任务后退出的版本升级流程。

回归覆盖 Swift/schema/lock 摘要一致、重复打补丁幂等、schema 被修改时拒绝同步。

修复验收：Python 回归通过，Debug build 通过，签名启动组件通过 nonce 启动契约完成旧执行器平滑退出和新执行器启动；实际 daily-tasks 就绪报告的 8 个检查全部通过，心跳 PID 对应新 payload 内容版本。未提交新的真实素材制作或远程模型请求。就绪证据保存在 `/Volumes/SSD1/ImageAll-artifacts/openmontage-schema-repair-20260923/readiness.json`。

## 2026-09-23 等比例文字预览

移除右侧固定 `字号 × 0.4` 的独立文字样例。预览先在当前制作画幅（1920×1080 / 1080×1920）排版，再统一缩放整张画布，字体、字幕面板、边距及位置共用缩放因子。画幅选择与制作面板共用状态。提供片头标题/照片字幕两个视图，使用当前项目标题、所选镜头字幕与已加载缩略图；无文字时回退示例，不额外读取原照片。

标准本地制作预览沿用 PhotoStory 的 7% 短边安全边距、居中标题、底部居中字幕面板及对应内边距；字体和字号实时更新。提供放大窗口辅助判断小字号、长字幕和竖屏排版。制作锁定期间仍能切换预览与放大查看，只禁用字体/字号/画幅修改。该视图用于标准排版的尺寸和位置判断，不宣称与 Chromium 字形栅格、动画或自由创作代码逐像素一致；其他固化模板位置也以成片为准。

本轮验证：最终 Debug 构建通过；从生产源码抽取同一预览组件，在独立合成文字窗口检查横屏字幕、竖屏字幕换行、片头居中、90→92 px 即时更新和放大窗口，未加载真实照片。日常 App 更新前通过保存入口保存当前 19 镜头故事，核对保存时间和原字体设置后重启新版本。

## 2026-09-23 字形柔边字幕

按用户要求，标准照片字幕取消整块深色底板、圆角、容器阴影及背景模糊，改为零偏移深灰色字形柔边。PhotoStory 使用 1080 短边基准的 1.5 px / 4 px 双层 text-shadow；SwiftUI 字幕预览采用同色同尺度阴影，原生 CoreText 制作使用 3 px 字形阴影。保留原字体、字号、字幕内容、安全边距及内边距，不增加新的用户设置，也不修改 Schema。已生成视频保持不变，新的制作使用该外观。

字幕外观验收：使用当前故事已冻结的派生素材重新制作，输出 1920×1080 / 30 fps / 24.166667 秒，媒体校验和全片解码通过。抽帧检查明亮舞台与夜景均无字幕底板，文字带局部深灰柔边。新版视频与抽帧位于 `/Volumes/SSD1/ImageAll-artifacts/caption-shadow-20260923/`；未调用模型、未读取或修改原照片。

日常 App 已备份后以完整新 bundle 替换，Debug 构建和 strict/deep 签名验证通过；运行二进制与字幕渲染组件和构建产物一致。构建脚本使用随附 Python 3.12，避免系统 Python 缺少 tarfile 安全解包参数。

## 默认方案与模板固化

2026-09-23 用户确认将上述视觉方案设为默认并固化到对应模板。命名为“深灰柔边字幕”，版本 1，参数保存在 `scripts/openmontage/caption-style-defaults.json`，由构建补丁读取。标准照片故事默认使用该方案；“短文案淡出”模板共用 PhotoStory 渲染器，其照片字幕继承同一方案，包括该模板的个人变体。无单独开关，重新启动、创建故事或重新套用这些模板不会恢复旧底板。

App 预览和原生制作已采用同一视觉决策；字体、字号、字重、文字、位置与安全边距仍沿用各项目设置。该默认只约束字幕外观，不把草莓音乐节的文案、照片或字体固化为所有项目默认。照片内手写诗句采用其已有独立模板；本次不改变它的布局。历史成片是冻结文件，保持原样。

## 2026-09-24 字体菜单顺序

字体菜单优先显示当前故事已明确选择的字体、最近在菜单中选择的字体、已保存故事里明确使用的字体，然后显示这次安装的字体、原有常用字体及其余本机字体。每组只出现一次，缺失或无法由 CoreText 加载的字体不展示；最近选择保留最多 12 款并跨启动保存。搜索沿用中文显示名和字体内部家族名。每次打开菜单重新扫描用户字体库，将新安装字体注册到当前进程，避免 App 已运行时仍显示旧清单。字体文件仍只从本机读取，不复制进项目或成片包。
