# 用 Mac 与 iPhone ImageAll 一起导入照片和信息

## 授权怎么做

不需要向 Codex 提供 Apple 密码或授权码。权限在设备和 ImageAll 中完成：

1. 有线连接时，解锁 iPhone；若系统询问，选择“信任此电脑”。这让 Mac 识别设备，不代替照片权限或 App 配对。
2. iPhone 打开 ImageAll →“此 iPhone”→“选择照片访问权限”。只导入几张媒体可使用有限权限；要读取来源相簿名称、层级和成员关系，需要完整照片访问权限。拒绝或有限权限可通过页面上的权限设置按钮更改。
3. Mac ImageAll → 菜单“设置”（⌘,）→“设备与导入”。启用手机连接服务，选择“照片接收目录”，确认每批容量上限足够。
4. **USB 有线方式：** 手机“待分享”或“Mac 图库”点击“开启 USB 有线连接”；Mac 刷新 USB、选中有线设备、点击“通过 USB 连接手机 App”。在手机核实 Mac 名称和证书指纹后点击“确认通过 USB 连接此 Mac”。首次通过同一线缆完成安全配对，无需扫码；已保存配对必须匹配 Host ID 和证书，不能静默替换为另一台 Mac。
5. 显示“USB 有线已连接”后传输数据仅经过手机本地端口、USB 和 Mac 本地端口，无需互联网、Wi-Fi 或个人热点。保持手机 App 前台。USB 模式会记住；拔线、App 后台或 Mac 退出时暂停，不自动改走无线网络。
6. 若要用网络，手机显式点击“改用网络连接”，然后按 Mac 的安全配对入口扫码或恢复已有配对。网络方式需要可用网络；归档请求禁止蜂窝回退。

### 提示旧配对身份不同

手机保存的 Mac ID 或证书指纹与当前请求不同，连接会暂停。手机会显示差异原因以及新旧 Mac ID、完整证书指纹；请与 Mac“设备与导入”的身份信息核对。确实要连接当前 Mac 时，点击“重新配对此 Mac…”，再确认“清除旧配对并连接”。同一 USB 请求继续完成新配对，无需跳转页面或扫码。

此操作只清除手机上的旧连接凭据，保留“待分享”选择、本地照片及整理信息。Mac 上旧设备记录可另行移除。请求超时或通道改变时，旧确认不能继续清除配对，需在 Mac 重新连接。不要在身份无法核实时重新配对。

手机会显示确认截止时间，窗口按 Mac 配对令牌剩余有效期计算，最长 5 分钟。临时失焦保留 USB；真正进入后台或锁屏时暂停。若提示请求失效，手机重新等待 USB、Mac 断开旧请求后重新连接；过期的确认不能沿用。更新本次等待期修复后，Mac 也需从当前 Xcode 项目重新运行新构建。

2026-10-09 已修复表单内“重新配对”和“拒绝”按钮同时被一次点击触发的问题。按钮现在独立响应；打开或取消重新配对弹窗不会拒绝 USB。此修复需更新手机 App，不能仅靠在 Mac 重启或反复重连生效。

## 选择和导入

照片接收位置必须与 ImageAll 已保存的来源目录分离：不能是来源本身、其子目录或包含来源的父目录；停用来源也计入。来源授权失效时需要先修复授权，不能跳过检查。Photos Library 包不能作为接收位置。独立普通目录不因卷名或年份命名而被拒绝；设置失败会弹窗说明原因。

- 在 iPhone “此 iPhone”里将需要导入的照片/视频加入“待分享”。这就是明确的导入范围；未选择媒体不会自动加入。
- “待分享”中需要包含空相簿和文件夹目录时，手动开启“保存可访问用户相册目录（含空相册）”。此选项要求完整照片权限；未选成员仍不传输。
- 点击“导入所选照片与信息到 Mac”。App 先同步目录和事实，再传输同批原件及快照。有冲突或后续变化页时，请先用同步入口处理后再重试；不会忽略冲突传原件。
- 传输中显示当前通道、Mac 已确认的原件字节和平均速率。速率是本次传输确认量除以本次准备/传输耗时，不是 USB 接口理论带宽；重试略过已有字节，不把这些字节算成新传输速度。
- Mac 刷新“iPhone 照片与信息导入”，看到已校验批次后点击“导入照片与信息”。查看所选批次的来源相簿目录、资源和标签/集合数量；点“在 App 中预览”核对照片及红心。
- Mac“导入离线照片包…”用于手机另行导出的完整离线包；不能选择空接收目录来发起 USB 传输。没有已接收批次时，先在手机点击导入按钮，接收完成后再刷新 Mac。入库时显示处理中指示，失败会弹窗说明原因。
- 手机原件保留。需要以后更新整理信息时使用既有同步/同批整理信息快照入口；不因导入自动写回或删除手机 Photos。

## 信息含义与范围

来源 Photos 红心、ImageAll 收藏目标、ImageAll 标签/集合分别保留。相簿包含 PhotoKit 可访问的用户相簿与文件夹；不包括其他 App 私有标记或智能相簿规则。有限权限下来源相簿覆盖不可用，不能把显示为 0 当作手机没有相簿。

“分享目录已接收”不代表原件已导入。“Mac 已校验接收”不代表 App 已完成入库。普通导入后的查看和断开手机使用，与进一步的迁移完成回执/独立备份验收分开；后者在高级入口中保留。

## 中断时

USB 中断后保持原选择范围和配对身份，手机重新等待 USB，Mac 重新发起连接并在手机确认，再重试导入。已经落盘且校验的字节保留；每个分片检查当前通道会话，不能在传输途中换通道后继续旧任务。用户显式选择网络后可以重新发起同批导入，但原任务先停止。

更改 Photos 权限、选择范围或来源资源时，旧批次可能拒绝继续，需重新准备。资源只读取本机可用版本，默认不从 iCloud 下载补齐。容量不足或连接中断不等于成功；按页面提示解决后重试。

## 开发构建边界

USB 实现见 ADR-104。Mac 保持 App Sandbox，仅对系统 usbmuxd 的单个 Unix socket 增加连接例外；未授予文件读写例外。该配置已在本机签名沙盒探针中验证，正式分发仍需另行检查平台与商店要求。

### USB 速度与暂停（2026-10-09）

手机传输进度显示当前阶段、已确认原件、传输均速和总耗时。传输均速包含接收端确认等待，不包含提交目录、准备原件与 Mac 复验阶段；不能用它判断线材标称速度。新版使用最多 1 MiB 分块，并缓存资源之间的完整可见性检查；权限或 Photos 变化仍会使检查失效并停止不再获准的范围。

点击手机“暂停逐资源传输”或拔线后，保留原范围、相簿选项、Mac 配对和接收目录；恢复连接后点击同一导入操作继续已落盘批次。客户端升级兼容旧 64 KiB 进度。Mac 接收完成后的本地“导入照片与信息”属于校验/复制/入库阶段，目前不支持中途暂停；拔线只暂停手机传输。

### 准备或恢复时出现请求超时

新版会明确显示当前是在核对上次目录回执、提交目录、同步红心/标签/集合、准备原件、传输、Mac 复验或封存。准备阶段的本轮“已确认原件 0 KB”不代表旧批次没有文件；只有收到最终复验及封存回执才能显示整个批次完成。Mac 更新/重启后的首次续传会复验之前落盘的数据，机械盘上可能需要较长等待。

保持手机 App 在前台和原 USB 连接，使用原选片范围及相册选项重试。无需删除接收目录，也不要把隐藏接收批次当作已完成的离线包。整理信息处理允许等待 3 分钟，旧批次恢复及单原件复验允许 10 分钟，整批封存允许 30 分钟；普通界面请求仍为 15 秒。需要暂停时使用手机暂停按钮，保留已落盘进度。

USB 连接使用独立 I/O 心跳保活；手机准备照片或相册耗时较长时不会因 UI 主线程忙而误断开。8 秒期限只检查一次心跳响应，不限制整批照片上传的总时长。若确实拔线或退出手机 App，连接仍会暂停，按钮因未连接而禁用；重新从 Mac 发起连接并在手机确认身份后恢复可操作状态。

2026-10-09 已修复续传窗口因沙盒绝对路径写法不同而误报“来源照片或视频已变化”的问题。更新手机 App 后保留原选片范围、相册选项和接收目录，重新连接 USB 后重试。准备阶段会显示“核对续传目录与原件”；这时尚未确认新的传输字节，显示 0 KB 不代表已完成。无需清空接收目录或重新生成离线包。若明确提示待恢复缓存无法对应当前所选原件，请核对选片范围和版本，旧进度仍保留。

同日追加修复：原件读取与写入完成回调的线程隔离错误会导致手机 App 闪退。更新手机 App 后重新连接 USB，保留原范围重试即可；不用撤销照片权限或清除旧批次。修复已通过实际待恢复单原件的只读哈希检查，整批完成仍以 Mac 接收封存和入库结果为准。

### 长批次自动恢复（2026-10-09，待真机整批验收）

新版会自动重试短暂请求失败并刷新到期登录凭据；整个批次没有固定总时长上限。活动导入期间保持屏幕唤醒，切换 ImageAll 内的页面可以继续；主动锁屏、进入后台或拔线仍会暂停并保留进度。持续错误会显示原因，可恢复原连接后继续。

新版已确认资源会留下完成记录，重试先核对 Mac 的对应原件，跳过手机重复导出。旧批次在首次生成这些记录前仍可能需要较长准备时间。若部分原件不在手机本地，先完成其他可读取资源，末尾显示待处理数量；整批完整前不会显示接收完成，也不会静默下载云端原件。
