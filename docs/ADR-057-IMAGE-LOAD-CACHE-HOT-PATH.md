# ADR-057：图片加载先合并请求并批量读取缓存快照

- 状态：Superseded by ADR-058
- 日期：2026-08-11
- 范围：图库缩略图、派生图片缓存命中路径
- 安全边界：自动化验证仅使用临时目录与合成媒体；不访问 PhotoKit 或受保护真实照片

## 背景

同一资产的 SwiftUI 单元在快速重挂载时，重复请求会先分别占用界面和底层 I/O 并发许可，之后才在底层共享
实际解码。重复请求因此可能阻塞其他资产。派生图片的缓存命中又分别查询资产存在性、目录上下文和缓存条目；
较小变体在未命中时还逐个查询可复用的较大变体。工作区内存缩略图缓存用数组维护 3,000 项顺序，每次写入
都执行线性删除，容量满后还从数组头部移动元素，滚动越过缓存容量时会在主线程产生额外 CPU 工作。

## 决策

1. 工作区与 `LibraryAssetImageLoader` 都在取得现有并发许可之前合并相同资产、变体和加载代次的请求。每个
   等待者可独立取消；只要仍有等待者，共享任务继续执行，全部等待者取消时才取消底层工作。请求代次确保旧
   任务延迟收尾时不会清理同键的新请求，因此不提高并发上限，也不把离屏任务变成后台常驻工作。
2. 派生图片热命中通过一条精简 SQL 读取当前目录键和目标变体条目。只有目标未命中时，第二条 SQL 才批量
   读取来源/指纹事实及当前内容修订的全部变体；生成资格和较大变体复用来自这个冷路径快照，发布前的目录
   事实重验证继续保留。
3. 每次磁盘缓存命中仍读取受锚定对象、校验字节数、SHA-256、格式和像素尺寸，并更新数据库 LRU 时间；不引入
   绕过完整性验证的内存命中层。
4. 工作区 3,000 项内存缓存改用带代次的顺序记录和游标淘汰。相同字节不刷新顺序或版本，不同字节仍移动到
   最新位置；被淘汰资产的字节和版本同时移除。顺序记录按阈值压缩，使 CPU 为摊销 O(1)，内存仍有上界。
5. 冻结既有契约：界面缩略图并发 4、底层网格 16、预览 4；缓存格式、20 GiB 配额、512 MiB 下载预览配额、
   iCloud 显式下载策略、页面/选择/排序/焦点/视口均不变。

第 5 项仅描述本阶段当时的停止边界；固定图片加载并发值与 20 GiB 派生缓存总量配额已由 ADR-058 后续取代。

## 验收标准

1. 三个并发的相同工作区缩略图请求只调用一次服务；重复底层网格等待者不占用本可供不同资产使用的许可。
2. 派生图片热缓存命中只执行一条 `SELECT/WITH`，结果与旧的存在性、上下文和条目投影完全一致。
3. 缓存快照读取及内存淘汰结构各自以五次暖运行中位数比较旧路径，至少改善 20%。
4. 既有取消、并发上限、缓存损坏重建、较大变体复用、PhotoKit 本地/云端及工作区软刷新回归继续通过。
5. 隔离 `build-for-testing` 成功；测试不启动 production App 宿主，不读取受保护数据。

## 后果与停止点

本阶段减少重复许可占用、SQLite 队列往返和主线程数组移动，不以放宽完整性或提高并发换取速度。若任一五次
暖运行中位数未达到 20% 门槛，则回退对应复杂化。阶段二完成定向验证与本地提交后停止；相似度后台计算与
Web Companion 增量渲染留在后续已批准阶段。
