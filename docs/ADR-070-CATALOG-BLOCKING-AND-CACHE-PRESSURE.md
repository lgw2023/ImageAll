# ADR-070：目录阻塞隔离与缓存压力合并

- 状态：Accepted
- 日期：2026-09-07
- 范围：图库目录查询、缩略图缓存读取、低空间派生图片回收、图库空状态呈现
- 关联：ADR-058 图片与模型流水线由系统资源调度、ADR-062 缩略图自动恢复与缓存会话生命周期
- 安全边界：不改变来源授权、真实照片只读保护、缓存规范路径校验、分页排序、选择、滚动或请求去重

## 背景

低空间会让多个缩略图生成请求同时进入派生缓存回收。旧实现从 Swift 异步任务直接调用同步 GRDB 读取；
读取池繁忙时，同步等待会占住 Swift 协作线程，而归还连接的异步任务也需要这些线程继续执行，最终可能形成
线程饥饿。与此同时，每删除一个缓存对象都会重新读取并排序全部 LRU 记录，约十二万条记录时会放大数据库
争用。图库导航还会先清空旧列表，却继续以内容状态渲染，因此尚未返回的查询会被误报为“没有照片”。

## 决策

1. `CatalogBlockingExecutor` 成为遗留同步目录接口的统一 seam。工作区模型和照片缩略图加载器通过异步接口
   提交同步调用，由专用且有并发上限的 `OperationQueue` 执行；等待 GRDB 读取连接不再占用 Swift 协作线程。现有同步目录接口可逐步
   迁移到原生异步 GRDB，调用方无需再次选择调度方式。
2. 派生图片模块中的异步热路径通过同一 seam 执行同步数据库读写与缓存命中校验。缓存维护互斥改为续体与
   条件通知，不再用 `Thread.sleep` 或定时轮询等待。
3. 同一缓存实例在任意时刻只运行一个容量回收任务。并发请求共享正在执行的回收；回收完成后，各请求按自己
   的待写入大小重新检查实时卷容量。
4. LRU 候选按 128 条一批查询并依次回收。每批耗尽且空间仍不足时才读取下一批；不再为每个被删除对象读取、
   排序全部缓存记录。下载预览的独立 512 MiB 配额采用相同批量候选读取，配额值保持不变。
5. 进入普通图库、来源、文件夹、红心、无标签或照片世界结果时，立即把列表状态设为加载中。只有请求成功且
   确认为空时才呈现空结果；当前请求失败时继续呈现目录失败状态，过期请求仍由既有请求 ID 丢弃。
6. 不增加 GRDB 连接数，也不恢复固定图片请求并发上限。前者只掩盖等待模型，后者违反 ADR-058。

## 验收标准

1. 工作区同步目录调用不再使用 `Task.detached` 作为阻塞隔离手段；派生缓存异步热路径不直接等待同步 GRDB
   连接。
2. 两个并发容量回收请求只执行一个活动回收闭包，等待者在活动回收结束后继续判断自己的容量条件。
3. LRU 候选接口可返回有序、受限批次；低空间、删除失败、空间事实不可用及内存回退契约继续通过。
4. 清空旧图库行的同步导航状态为加载中，查询完成后转为内容或失败，不显示临时空图库。
5. 派生缓存定向测试、工作区模型定向测试与隔离 Debug 构建通过。自动化仅使用临时数据库、临时缓存和合成
   媒体，不启动生产 App，不访问 PhotoKit 或受保护真实照片。

## 后果

同步目录实现仍然存在，但其阻塞行为集中在一个深模块内，调用方获得异步接口与统一调度。专用队列在数据库
拥塞时限制同时运行的阻塞工作项；GRDB 读取池继续控制实际数据库并发。缓存回收从逐对象全表扫描变为单任务批次扫描，减少
重复工作，同时保留实时空间事实、对象安全删除和写入前准入检查。
