# ADR-065：Web Companion 采用独立的“私人影像档案馆”视觉身份

- 状态：Accepted
- 日期：2026-09-01
- 范围：`WebCompanionApp` 与打包到 Mac App 的 `WebCompanionV2` 静态资源

## 背景

Web Companion 的功能对齐目标是：关键任务、状态语义、Mac Host 权威、安全边界与跨设备连续性
保持一致。它不要求复制 Mac App 的窗口、侧栏、面板密度或系统控件外观。

上一版 React 界面虽然完成了功能迁移，但把“三列信息关系”误解成了桌面 App 的视觉复刻，结果更像
通用管理后台，照片没有成为主角。网站端需要利用更宽的展示面、触控与浏览器全屏能力，形成自己的
产品气质。

## 参考研究

本次只提取成熟产品的交互规律，不复制任何单一产品的品牌或界面：

- [Glass Web](https://glass.photo/platform/web)：边到边照片流、全屏与像素级查看、键盘浏览；
- [mymind](https://mymind.com/) 与 [Cosmos](https://help.cosmos.so/en/articles/11846092-intro-to-cosmos)：
  私密视觉收藏、弱化文件管理负担、以内容流组织记忆；
- [Picflow](https://picflow.com/) 与
  [Frame.io](https://blog.frame.io/2026/01/08/new-in-frame-io-interactive-zips-access-requests-and-a-faster-way-to-get-around/)：
  将收藏、审批、标注、上一个/下一个等动作放到媒体上下文中；
- [Adobe Lightroom](https://helpx.adobe.com/in/lightroom-cc/using/organize-photos.html)：无边框网格、方形网格、
  详情/全屏层级与键盘导航。

## 决策

Web Companion 采用 **ImageAll Atelier / 私人影像档案馆** 作为独立视觉方向：

1. 全局导航使用深墨色框架，工作区使用暖象牙纸色，图库和灯箱使用纯黑接触印样台；
2. 标题采用编辑部式衬线字体，功能文字使用本机无衬线字体，编号与状态使用等宽字体；不请求外部字体；
3. 烧橙色只承担选择、活动状态和关键提示，不作为大面积装饰；
4. 图库卡片改为紧密的 4:3 接触印样，元数据覆盖在照片下缘；完整比例仍在灯箱中以 `contain` 呈现；
5. 桌面保留“导航—内容—检视器”的信息语义，但三列拥有明显不同的材质和层级；移动端折叠为内容优先的
   双列影像流，并保留筛选、分析和框选入口；
6. 灯箱使用接近全屏的黑色观看区和独立纸色元数据栏，操作靠近当前媒体；
7. 所有表面保持不透明；不使用渐变、玻璃模糊、发光边框或装饰性循环动画。

图库、概览、审核、地图、训练、瘦身、来源、存储、标签、活动、设置和认证入口共享同一套颜色、字体、
间距、按钮与状态语言，而不是只给图库换皮。

## 不变契约

- Mac Host 继续是列表、修改、任务和设置的唯一权威，网页不伪造成功；
- 路由、URL 筛选、选择语义、快捷键、右键菜单、撤销、灯箱返回上下文与分页契约不变；
- 10k 图库继续使用虚拟化；PWA 仍只缓存公开壳层，不缓存私有媒体或会话数据；
- 深色模式、高对比模式、放大文字、减少动态效果和 390px 触控布局继续受自动化约束；
- 自动化只使用合成 Host 与合成媒体，不读取、遍历或写入受保护真实图库。

## 取舍

- 编辑感字体依赖系统字体，不同平台字形会略有差异，但换取离线可用和零外部跟踪；
- 接触印样采用 4:3 裁切以提高浏览密度，精确构图判断必须进入无裁切灯箱；
- 高密度排版比通用后台更有个性，因此通过强制颜色、键盘与放大文字测试保留可访问兜底。

## 验证

- Playwright：80 项中 76 项通过、4 项按浏览器项目配置跳过；
- 10k 合成图库：首卡可交互 969 ms，DOM 630，卡片 28，选择反馈 p95 17.3 ms，灯箱 p95
  95.6 ms，长任务 0，滚动锚点偏差 0 px；
