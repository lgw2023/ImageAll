# ADR-065：Web Companion 采用独立的 Helios 视觉身份

- 状态：Accepted（2026-09-01 项目所有者反馈后第二次修订）
- 日期：2026-09-01
- 范围：`WebCompanionApp` 与打包到 Mac App 的 `WebCompanionV2` 静态资源

## 背景

Web Companion 与 Mac App 的对齐对象是关键任务、交互语义、Host 权威、安全边界和跨设备连续性，
不是窗口、侧栏、面板密度或系统控件的视觉复刻。

先前两轮方案先后落入“桌面 App 搬到浏览器”和“深色管理后台”的问题：工具框架持续抢占注意力，
照片没有成为主角。项目所有者再次明确要求从行业优秀网站中提炼设计规律，为 Web 建立真正独立、
现代且有表现力的外观。

## 参考研究

本次只提取成熟产品与优秀网站的设计原则，不复制任何单一产品的品牌、组件或页面：

- [Immich](https://immich.app/) 与 [Ente Photos](https://ente.com/)：照片时间线、搜索、地图和安全状态
  围绕媒体本身组织；
- [Adobe Lightroom Web](https://lightroom.adobe.com/)：把摄影作品而非工具栏设为第一视觉层；
- [mymind](https://mymind.com/) 与 [Cosmos](https://www.cosmos.so/)：以宽松画布、强图像、少量常驻
  控件形成视觉探索感；
- [Are.na](https://www.are.na/)：内容集合可以保持克制、编辑化和非后台式的表达；
- [Awwwards Interaction Design](https://www.awwwards.com/websites/interaction-design/)：动效与空间层级应服务
  状态反馈和导航，而不是成为持续干扰。

## 决策

Web Companion 采用 **ImageAll Helios** 作为独立视觉系统：

1. 默认使用暖白画布、悬浮白色表面和受控的紫罗兰、珊瑚、青色、青柠强调色；深色主题保留但不再
   决定产品的默认气质；
2. 桌面导航收敛成 72 px 图标轨，标题栏悬浮，关闭的检视器不占布局，让媒体工作区超过视口宽度的
   90%；
3. 图库采用大幅、无边框、圆角影像卡片；高级筛选默认折叠，在桌面与移动端都以按需层呈现；
4. 移动筛选使用可滚动的玻璃抽屉，不把图库向下挤出视口；
5. 概览、审查、地图、训练、瘦身、来源、存储、标签、活动、设置和认证共享同一套排版、表面、
   状态色和焦点语言，而不是只给图库换皮；
6. 合成测试媒体使用确定性的彩色抽象缩略图，既能验证真实视觉密度，也不引入用户照片；
7. 渐变、阴影、模糊和悬停抬升只用于建立空间层级；减少动态、高对比、强制颜色和放大文字模式
   必须有静态兜底。

## 不变契约

- Mac Host 继续是列表、修改、任务和设置的唯一权威，网页不伪造成功；
- 路由、URL 筛选、选择语义、快捷键、右键菜单、撤销、灯箱返回上下文与分页契约不变；
- 10k 图库继续使用虚拟化；PWA 只缓存公开壳层，不缓存私有媒体或会话数据；
- 390 px 触控布局、键盘操作、焦点恢复和 WCAG 2.1 A/AA 继续受自动化约束；
- 自动化只使用合成 Host 与合成媒体，不读取、遍历或写入受保护真实图库。

## 取舍

- 图标轨提高了内容占比，但新用户需要依靠悬停标签、当前页标题和命令搜索理解入口；
- 接触印样为提高浏览密度会裁切缩略图，精确构图判断必须进入 `contain` 灯箱；
- 玻璃表面和多色强调比纯色后台更依赖渲染能力，因此基础颜色、边框和焦点环不能依赖模糊存在；
- Web 与 Mac 不再追求像素级一致，今后的对齐评审必须分别检查“行为契约”和“Web 视觉质量”。

## 验证

- Playwright：158 项中 152 项通过、6 项按浏览器项目配置跳过、0 失败；
- 10k 合成图库：首卡可交互 919 ms，DOM 781，卡片 36，选择反馈 p95 17.5 ms，灯箱 p95
  82.2 ms，长任务 0，滚动锚点偏差 0 px；
- `format:check`、lint、typecheck、31 个 Vitest 单元/契约测试通过；
- macOS `build-for-testing` 通过，构建产物内 WebCompanionV2 与源资源无差异；
- 桌面与移动截图位于 `docs/web-companion-refactor/evidence/`，只包含合成媒体。
