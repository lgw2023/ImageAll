# ADR-071：Photos 原图副本仅写入用户选择的位置

- 状态：Accepted
- 日期：2026-09-07
- 取代：ADR-044 中“默认写入 Application Support 并无限期保留”的策略
- 范围：图库瘦身相同检测、Photos 原图副本、App 设置、旧版副本兼容

## 背景

Photos 的字节级“相同”检测必须读取原始编码内容。旧实现无论原图原本位于本机还是需要从 iCloud 获取，
都会把成功读取的完整字节写入 `Application Support/ImageAll/Photos Originals/v1`，且不设 TTL 或容量淘汰。
用户没有选择该位置，也不会在写入前看到容量影响，大图库可能因此静默占满系统盘。

## 决策

1. 没有用户设置时，生产 `PhotosOriginalCacheService` 不具有写入根目录。相同检测仍可通过 PhotoKit 按需读取
   原图并当次计算 SHA-256、dHash 与像素签名，但完整原图不得写入磁盘。
2. “设置 → 通用 → Photos 原图副本”提供明确的保存位置选择器。用户选择父目录后，ImageAll 在其中使用
   `ImageAll Photos Originals/v1`，保存安全作用域书签，并提示重启后生效。
3. 当前选择是唯一写入根。每次更改位置时保留历史书签；启动后历史根和旧版 Application Support 根只用于
   读取及显式清理，防止路径切换制造不可见孤儿文件。
4. 旧版副本不自动移动或删除。存储面板继续显示数据库登记的总数量和大小，并明确说明统计包含旧版副本；
   用户清理时同时检查当前、历史和旧版根，只删除合法 UUID 文件及其登记。
5. 选择位置不授权修改 Apple Photos，也不授权自动访问项目受保护的真实测试数据。自动化只使用临时目录、
   合成图片、伪书签和临时数据库。

## 验收标准

1. 全新偏好没有 Photos 原图写入根，相同检测成功后 `photos_original_cache_entry` 仍为零且不创建原图目录。
2. 用户选择位置后保存书签，设置页显示最终完整路径并提示重启；启动解析以最新位置写入。
3. 二次选择后，最新位置是写入根，先前位置仍在只读/清理根列表中。
4. 已配置位置的原有持久化、内容校验、资产版本绑定、清理安全和字节级相同结论继续通过。

## 后果

未配置保存位置时，重复删除指纹或重新计算可能再次从 PhotoKit 读取或下载原图；这是以用户磁盘控制权换取的
明确成本。旧版副本不会因升级被静默移动或删除，用户可先核对用量，再通过既有二次确认清理。
