# ADR-061：文件夹来源的层级导航

- 状态：Accepted
- 日期：2026-08-24
- 范围：Mac 来源侧栏、目录范围查询、文件夹扫描提交与目录索引
- 安全边界：不增加 security-scoped bookmark，不遍历 Apple Photos 包，不修改来源文件

## 背景

文件夹来源天然可能包含多级子目录。现有扫描已经递归读取并把文件相对路径写入 `asset.relative_path`，但来源
侧栏和分页筛选只认识来源 ID，因此用户看到的是被展平的媒体集合。把每个子目录注册成独立来源会重复授权、
产生重叠扫描和独立任务，也会破坏“来源是授权根”的安全模型。

## 决策

1. “来源”继续表示用户授权的根目录；“目录”只表示该来源内部的导航范围，不创建 bookmark、来源记录或扫描
   任务。Apple Photos 来源没有文件夹树。
2. 目录树只包含至少一个当前已索引媒体的目录及其祖先；空目录和只含被忽略文件的目录不显示。点击来源根部
   显示该来源全部媒体，点击目录默认递归包含全部后代。
3. 新增 `source_folder` 物化索引。成功完成文件夹扫描时，在同一数据库事务内按当前资产重建该来源的目录树；
   失败、暂停或取消的扫描保留上一棵完整树。既有数据库在 v037 migration 中一次性回填。
4. 资产目录筛选使用 `(source_id, relative_path)` 的二进制前缀范围，避免把 `%`、`_`、反斜线或大小写当作
   模式字符；目录路径必须通过既有相对路径规则，不接受绝对路径、空组件、`.`、`..` 或 NUL。界面和查询契约
   不暴露来源绝对路径。
5. Mac 侧栏用来源 DisclosureGroup 和嵌套目录节点显示层级；所有来源默认折叠，只有用户展开的直接子层级才
   查询和创建视图，每批最多 100 个并通过“显示更多”继续分页。超过 500 个直接子目录时显示总数和目录搜索，
   搜索最多显示 50 个匹配项并把 `%`、`_` 等字符当作普通文本。不得按来源名称或导出工具特判目录行为。
6. 选中目录时显示来源到目录的面包屑。成功重扫后清除已加载的目录分支缓存；若当前目录消失，按主键逐级检查
   并回退到最近仍存在的祖先，若祖先均不存在则回退到来源根部。这个检查不得读取整棵目录树。
7. Web Companion 本次不实现，但不得为 Mac 引入与后续 Web 无法复用的目录语义；远端 DTO/API 留待单独切片。

## 验收标准

1. 合成多级临时目录扫描后，目录索引包含所有媒体目录及祖先，根目录文件不制造虚假目录。
2. 目录分页只返回同一来源、所选目录及其后代的资产；`%`、`_`、反斜线和相似前缀不能越界匹配。
3. 完成重扫会移除已消失目录；不完整扫描不替换最后一棵完整目录树。
4. Mac 来源初始折叠；展开 1 万个同级目录的来源时首批只返回并创建最多 100 个目录节点，后续显式分页。
5. Mac 可展开来源、选择任意层级目录、查看递归结果并通过面包屑返回祖先或来源根；超宽根目录可搜索未加载
   目录，单次结果不超过 50 个。
6. 目录查询使用轻量索引；既有 1 万、10 万、100 万资产查询与构建门不退化。
7. 自动化验证仅使用临时目录和合成数据库，不读取受保护真实照片目录。

## 后果与边界

目录树是“已索引媒体视图”，不是磁盘文件管理器的完整镜像。若以后需要展示空目录或未支持文件，扫描契约需
另行持久化物理目录事实。目录重命名在当前模型中表现为旧路径消失、新路径出现；资产稳定身份仍由既有移动
识别规则处理。
