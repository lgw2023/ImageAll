# ADR-110：手机导入任务的持久恢复

> 2026-10-21 更新：项目所有者已允许修订旧 ADR。恢复阶段采用 [ADR-111](ADR-111-STAGED-USB-RECOVERY.md) 的“接收进度恢复、完整性待核验”契约；封存/发布仍全量校验。下文早期 ≤5 秒与禁止重定义指标的记录是历史决策，不再覆盖 ADR-111。新指标实机结果另列，不能声称旧完整字节重验指标达标。


2026-10-20，P1 任务恢复、状态查询与独立 USB 生命周期已通过相应验收；来源降级重验进度已部署并通过独立实机界面验收。2,889 项/4 GiB 手机冷恢复功能通过，首次有效进展 10.34 秒未达 ≤5 秒，P1 性能门未关闭。P0 已通过。

## 差异与选择

现有资源 checkpoint 和 Mac durable offset 已持久化，但手机 LocalShareTask、原选择、
目标 Mac 与仅封存意图只在内存中。进程重启会回到“开始导入”，缺少原任务的显式继续入口。
本切片补齐这一条用户路径，不更改资源 journal、已批准数据库 migration 或 ACK 语义。

- 将任务状态、选择 UUID、相簿选项、目标身份/指纹和任务 UUID 原子保存到手机应用私有目录。
  首次拿到来源身份和迁移 ID 时绑定并保存，后续不得静默改绑。
- 重启将 running/pausing 转为 paused。保留首个明确暂停原因；没有原因时写 processInterrupted，
  不猜测 USB 断线。保留 transferSelection/sealReceived 意图，必须由用户手动继续。
- 已绑定迁移 ID 的恢复必须重开相同 checkpoint；缺失或冲突要报错，不能自动创建新批次。
  首次尚未建立迁移 ID 的准备阶段仍可继续准备；现有来源版本与资源复验保持原有规则。
- 文件损坏、未知版本或读写失败均阻止新传输并显示原因；不能将读取失败视作首次使用。
  “开始下一次导入”只在已有接收回执时显式重置任务记录，不删除传输资料。
- 持久记录不保存 Photos locator、原件文件名、令牌或错误详情。已有诊断仍只记录聚合信息。

## 验证与边界

用合成 2,889 项选择证明重启同任务/迁移 ID、仅封存意图、显式暂停、目标/范围冲突与损坏拒绝；
再运行现有分享界面和断点恢复相关回归。构建当前 iOS 项目，不自动安装、重传或改动真实手机任务。
所有合成运行保留 512 MiB 独立保护，正在运行的 Mac App 保留 1 GiB 保护。

这一步不宣称 P1 全部门禁完成。普通已验证冷恢复 ≤5秒、完整单任务跨手机/Mac 发布状态、
4 GiB 中断续传及部署后的手机 UI 验收须分别记录；下文新增合成协议闭环证据，真实手机完整路径仍待验收。

## 2026-10-20 合成恢复闭环与内存修复

新增生产 RemoteLibraryClient → 合成进程内 HTTP 适配器 → 生产接收账本 → 校验封存的场景。
2,889 项共 4,456,558,592 字节，其中一个 4 GiB 文件已提交 4,286,578,688 字节，剩余 8 MiB。
初始账本由生成器构造为既有持久状态，不表示本轮已通过 USB 完成首次上传。

首轮冷恢复断点 2.96秒可用，随后客户端重读已提交前缀时触发 512 MiB 合成保护。
接收账本的提交偏移未增加、未封存。核查发现接收端已有逐次 read 的 autoreleasepool，
客户端 uploadMigrationFile 与 migrationFileDigest 仍直接调用 FileHandle.read。
补齐客户端逐次读取的临时对象释放，保留前缀重哈希、完整摘要校验与原 ACK 语义。

修复后同一场景：

- 第一个进程断点 3.11秒可用，首个资源 PUT 偏移为 4,286,578,688，仅发送 8 MiB（2 块）；
  2,888 项跳过，全部 2,889 项完成校验封存；物理峰值 33.59 MiB。
- 第二个独立进程断点 3.61秒可用，2,889 项全部跳过，原件及元数据新增上传均为 0；
  migrationID、清单 SHA-256 与封存资源数/字节数相同；物理峰值 26.41 MiB。
- 11 项客户端迁移回归通过，当前 iOS Debug 构建通过，未安装到手机。

这里的首次有效进展指校验后的接收端断点可用于跳过资源；不包含 PhotoKit、USB/TLS、
手机 UI 的前置准备或 Mac 入库发布。4 GiB 稀疏合成文件用于内存/偏移契约，
不构成真实吞吐或原 75GB 批次冷恢复 ≤5秒的证明。完整 P1 仍需跨端任务状态和部署验收。
证据：`/Volumes/SSD1/.codex-builds/USB-P1-Resume-20261020/Evidence/REPORT.md`。

  确认。只查数据库，不重读原件、不回放整理信息，接收暂存区移除后仍可查询。

  旧手机记录缺清单摘要时说明无法关联，保留 Mac 手工核对入口，不重传补记录。
- 原件准备/来源重验/接收端复验仍使用现有具体阶段；Mac 明示本地验证读盘，不算上传速率。

## 2026-10-20 完整规模独立手机冷恢复验收方案

手机重新连接后，以独立验收 Bundle、新任务和新配对执行 2,889 项/4 GiB 合成冷恢复。
预置接收器中 2,888 份已验证资源及大资源的 4 GiB−8 MiB 前缀，文件使用实际写入的非零字节，
不把预置前缀计作 USB 上传证据。手机先保存同一任务，再终止进程冷启动，必须暂停等待明确继续。
计时分别记录任务加载、点击继续至已核对 Mac 断点、首次新块 ACK，不能混称；
≤5 秒门槛针对已核对的有效断点。真实 USB 只续传剩余 8 MiB，发布后再次冷启动并核对零新增上传。
复用生产任务、客户端、接收修复、导入发布和状态查询代码；合成协调器不访问 PhotoKit，
不能据此宣称原 75 GB 批次或生产照片导出控制器的冷恢复性能已通过。
