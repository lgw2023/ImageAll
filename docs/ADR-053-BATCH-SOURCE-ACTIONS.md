# ADR-053：来源区提供安全的全部来源批量操作

> 状态：已决定并实施（2026-08-06，项目所有者对话批准）
> 相关：`ADR-047-MANUAL-ORIGINAL-ASPECT-THUMBNAIL-CACHE.md`、
> `ADR-049-DELETE-SOURCE-FROM-APP.md`、`LOCAL-TEST-DATA-SAFETY.md`

## 背景

来源右键菜单已经能对单个来源重扫、生成普通或原比例缩略图缓存、重新授权、更新回收权限和删除，
但来源较多时必须逐行重复操作。缓存和刷新天然可以覆盖全部来源；系统权限选择器和删除确认则不能
静默合并，否则会隐藏每个来源独立的授权或破坏性边界。

## 决策

1. 来源分区标题同时提供显式菜单按钮和右键菜单，作为“所有来源操作”的统一入口。
2. “立即更新所有来源”一次为全部活跃文件夹来源入队对账，并对全部活跃 Apple Photos 来源请求同步；
   当前正在浏览哪个来源不改变批量范围。
3. 普通缩略图和原比例缩略图缓存都按来源顺序串行执行。工具栏显示当前来源及批次位置，取消会停止
   剩余来源，但保留已经生成的缓存。两类缓存均先按当前内容修订、表示版本和缓存变体批量盘点，已有
   有效缓存不再逐项加载；只有缓存缺失且来源活跃、资产可用、格式受支持的项目进入生成队列。缺失、
   不可读、不支持或来源离线的项目只计为“不可处理跳过”，不在每次点击时重复解码。进度和完成摘要
   分别显示待生成、复用已有缓存、不可处理跳过与失败，避免把目录枚举误解为重新生成全部缓存。
   原比例缓存仍不改变展示缓存与分析特征的隔离契约。
4. 访问授权和文件夹回收权限采用“逐个系统窗口”的批处理。任意一次取消即停止后续来源，已经完成的
   授权保留；Apple Photos 写入权限仍按系统图库全局请求一次。
5. “在图库中查看”批量语义是进入全部照片。完整修复和删除不提供一键全量执行：完整修复仍需明确的
   Apple Photos 确认，删除仍按 ADR-049 对每个来源独立预检和确认。
6. 自动化只使用合成来源和资产，不读取 `/Volumes/HDD2` 受保护真实照片路径。

## 后果与验收

- 用户可以从一个入口更新或缓存全部来源，并看到批次级完成、失败或取消摘要。
- 重复执行普通或原比例缓存时，已命中的项目不会再次进入加载/生成循环；不可处理项目不会制造重复
  失败和虚假的慢进度。
- 不可用或需要访问授权的来源不会进入普通刷新；禁用或需要授权的来源不会进入缓存批次。
- 批量权限不会绕过系统选择器，批量操作也不会引入批量删除。
- 覆盖普通缓存、原比例缓存、全部来源刷新和两类权限批处理的针对性测试通过，Debug 构建成功。
