# iPhone → Mac 导入：可靠性与交付契约

状态：2026-10-19 收敛本系列实机反馈；关联 ADR-103、ADR-104、ADR-105。
本页是当前需求索引，历史 ADR 记录保留。原件导入、元信息保留和验收是同一个任务。

## 用户路径及不变量

| 编号 | 必须满足的行为 | 验收证据 |
|---|---|---|
| USB-01 | 原选择、来源身份、原配对、目的目录和 USB-only 绑定同一批次；恢复不能静默创建新批次 | 冷启动、动态元数据变化、错误身份/范围拒绝测试；实机 migrationID |
| USB-02 | 已校验资源批量恢复，未完成资源按已提交字节续传；恢复回执不是实时完整性证明 | 回执重放、偏移、同大小损坏在封存被拒绝；新增上传字节 |
| USB-03 | 内存随缓冲上界而非批次总量增长；所有文件校验循环释放临时缓冲 | 合成大批次/大文件独立进程内存保护、冷启动及封存；不可仅凭构建 |
| USB-04 | 用户暂停、进入后台、USB 断开、其他取消必须区分；恢复原任务意图，不自动切网络 | 状态机测试、匿名原因码、终止阶段；不能据取消推断镜像超时 |
| USB-05 | 部分可读集合仅经用户显式确认封存；每个资源必须已有原批次回执，缺证据即停 | 子集正向/拒绝测试；保留完整选择、待处理差集及零原件上传 |
| USB-06 | 暂停后继续“仅封存”仍不得落入上传路径；原选择数、实际封存数、待处理数分别显示 | 暂停/重试意图、2866+23 展示测试；冷启动仍需显式选择仅封存入口 |
| USB-07 | 设备接收、封存、Mac 入库、完整范围验收是不同状态 | 原件和事实摘要回执、catalogCommitted、逐项元信息比较；禁止从目录存在推断完成 |
| USB-08 | 相簿名称/层级/顺序/空相簿及范围内成员、红心、标签、集合都需保留 | 清单与事实快照身份一致，Mac 目录/成员/字段逐项比较；0 项也明确记录 |
| USB-09 | 列表刷新只发现曾封存的候选批次，不重新读全部原件；同一页面刷新互斥 | 冷打开历史 journal，资源损坏不阻塞列表，但实际入库必须拒绝损坏 |
| USB-10 | 长校验期间诊断更新；传输速率只统计本轮 ACK 字节/活动时间，不能把等待冒充吞吐 | 低频匿名快照、阶段变化、终止停止心跳；回执已收到不显示“整批入库完成” |

源端默认零写入、不下载 iCloud、不删除选择/手机原件、不重置配对。真实数据仅走具体授权的产品流程；合成测试不得读取受保护 HDD2 路径。发生异常保留断点和副本，不能靠重装清数据或反复重启恢复。

| 问题 | 已有措施 | 本轮补齐 |

| 封存时诊断停留在旧恢复阶段 | 原诊断只在项目/字节推进时落盘 | 活动任务低频心跳和阶段快照，完成/暂停停止心跳 |

## 本轮范围与部署门

实现 USB-04/06/09/10 的缺口。Mac 列表仅表示 journal 曾封存，UI 不称其为本次复验完成。
不把历史标志作为导入凭证，不缓存并跳过最终字节检查，不改入库数据库 migration。接收 journal 新增可选 `factsUpdatePending`，写 facts 前置为 true，完整封存后置 false；旧 journal 缺少字段时仅补验 facts，避免旧版本中间态被列为已封存。历史列表本身不承诺内容未遭外部修改。
普通传输与仅封存共用同一任务和原 checkpoint；仅封存仍显式确认，默认导入不自动排除不可访问项。

当前授权的真实 2866 项 Mac 入库继续运行；新代码用独立构建目录、直接无宿主测试和合成 fixture 验证，不重启或覆盖运行 App。新版本实机验收安排在当前入库/对账完成后；构建通过不等于已部署。

## 后续明确保留的工作

- 入库仍有独立副本发布及多次完整性检查。后续可以设计单次读取中复制和计算摘要、带阶段字节进度的可取消任务，但必须先证明损坏/变更拒绝与数据库原子性，不能只删除 verify 调用提速。
- 接收 journal 每块仍整体原子重写；增量 journal 属于独立格式迁移，不夹带本轮。
- App 被系统终止时没有可靠后台传输承诺；冷启动沿用 checkpoint，任务意图的跨启动恢复需与已保存回执和范围绑定后另行实现，不能凭 UI 缓存自动传输。
- 不可访问项的排查与后续交付、独立备份、来源清理、SSD1 迁移分别需要对应任务与授权，本轮不执行。
