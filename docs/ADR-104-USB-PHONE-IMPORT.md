# ADR-104：同一手机导入流程增加 USB 通道

日期：2026-10-08。状态：已实现；真实照片导入人工验收待完成。补充 ADR-103。

所有者明确要求有线传输，以避免占用无线带宽。保留手机 PhotoKit 授权、选择范围、同批原件/相簿/红心/标签快照和 Mac 原子入库；增加传输通道，不增加另一套照片导入功能。

## 最小纵向实现

Mac 经系统 usbmuxd 的 USB 设备连接访问手机 App 的 TCP 监听器。手机仅监听 loopback，首次收到连接请求后由用户确认 Mac；随后把手机本地 loopback HTTP/TLS 请求反向转发至 Mac 原有 Host。TLS 字节不解密，既有证书指纹和 bearer 配对身份继续校验。Mac 只转发到本机固定 Host 端口，不接受任意转发目标。

控制连接带随机会话密钥；每个数据连接必须匹配会话。手机把待确认请求显示给用户，不自动替换当前配对。已保存配对的 Host ID/指纹必须匹配；新配对复用短期一次性 offer，在线缆上传递，不必扫码。USB 设备 ID 只用于路由，不能当作 ImageAll 身份。

2026-10-09 实机反馈：旧配对身份不一致时，原实现拒绝并要求跳到“Mac 图库”清除配对，中断了主路径。改为在当前 USB 请求中显示新旧身份与具体差异，提供二次确认的重新配对入口。只有用户明确确认当前请求后才删除旧连接凭据；确认绑定完整 offer 和 USB 会话，超时、断开或换请求均不得使用旧确认。Keychain 删除失败时保留旧配对并停止。重新配对不修改本地分享范围、整理事实或 Photos。不能仅由截图判断身份变化来自 Mac ID 还是证书，也不自动重置 Mac 身份。

同日后续反馈：二次确认提示请求已失效。发现 App 把 `inactive` 与 `background` 都映射为停止 USB，且控制请求只有 110/120 秒等待，短于既有 5 分钟 offer。改为临时失焦保留会话，仅真正进入后台时关闭；手机与 Mac 依据同一 offer 剩余有效期等待，最长 5 分钟，手机显示确认截止时间。过期/断开仍拒绝旧确认。截图本身不能证明本次来自失焦还是超时，需实机合成生命周期与用户主路径分别验收。

第三次反馈的截图中，二次确认弹窗打开时背景已显示“已拒绝 USB 连接”。在独立 iOS Simulator 使用实际 `USBPhoneConnectionSection` 和 `Form`、合成凭据，以坐标点击复现：同一行的默认自动按钮样式同时触发“重新配对”和“拒绝”，记录 `explicitRejectionCount=1`、请求关闭、验收失败。此前直接调用模型方法的合成测试未覆盖按钮点击。修复为该区域显式 `.buttonStyle(.borderless)`，每个按钮只接受自身点击；保留原有身份校验与确认失效规则。失焦/等待期调整保留，但不再将其当作本次立即失败的已证实根因。

USB 被选为当前通道后，不根据 Wi-Fi/蜂窝状态决定可用性。拔线或后台关闭监听器时清除通道并暂停会话；不自动回退到网络。用户显式切换回网络才恢复网络客户端。每次原件分片都核验原 Host/设备和通道会话，防止传输途中改道。

用固定数量反向连接和有界读写缓冲实现背压，不将整张照片存入内存；进度沿用资源分片确认，速率显示已确认字节。保留现有中断重试，不能把 TCP 发送成功当作照片入库成功。

## 2026-10-09 传输性能优化

用户观察到约 300 KB/s，拔线暂停后要求全面优化。只读诊断发现实际客户端每块上限 64 KiB，每块都执行整批 PhotoKit fetch 和 `observe` 数据库写入；HTTP 每请求关闭，接收端每块同步文件和原子日志。该开销与有线链路带宽无关，尤其会放大机械盘同步成本。原速度均值还包括提交目录、PhotoKit 原件准备和哈希时间，不能当作 USB 链路吞吐。

本轮保留同一导入协议、批次身份与已落盘续传偏移，调整以下热路径：

- 客户端内存上限改为 1 MiB 分块，仍取接收端最大值与此上限的较小值。旧小分块接收进度可继续使用；串行背压、每块 SHA-256、整文件源哈希、资源独立复验、额度检查和 ACK 前同步落盘均不改变。HTTP 关闭连接的次数随分块数量降低；本轮不改整个 Host 的连接生命周期。
- 每块检查取消、当前照片权限、分享身份/范围版本、Host/设备/USB 通道。传输专用可见性租约缓存完整 fetch；资源准备前、上传前、复验前及封存前强制重查。Photos change 回调在自身回调队列立即使租约失效，随后才调度 UI 刷新；重新查询途中再变化则停止。权限状态变化也重新查询，撤销不删除已选范围。热路径不再写入整批观察事实；开始与结束快照仍读取并保存相簿、红心与整理信息。
- 手机 USB 字节泵改为专用串行 I/O 队列，控制/UI 留在 MainActor。每方向最多 256 KiB，上一发送完成后才接收下一块；两方向半关闭、控制关闭、会话密钥及 TLS 原字节转发约束保留。
- 使用单调时钟区分准备、传输、Mac 复验和封存阶段。原件速率只统计本轮 ACK 的新增字节及原件上传阶段时间（包含请求、校验与落盘等待，不是纯 USB 总线速度）；旧批次已确认前缀不计入新增字节。另显示总耗时，暂停后停止计时，重试重新计算本轮速率。

没有为性能取消 fsync、降低 TLS/身份校验、增加并行原件缓存或改动真实照片。机械盘、线材与 USB 设备实际速率需新版实机人工续传验证；如仍明显受请求建连成本限制，再基于实测设计仅传输路由的持久连接，不直接改变公网 Host 全部路由。

## 验证

2026-10-09 接收目录决策：用户要求把产品拦截范围修正为已有来源目录。原设置界面硬编码拒绝整个 HDD2，导致独立目标也无法选择；改为复用归档导入器对数据库中全部已保存文件夹来源的隔离校验（包括停用来源）。目标与来源相同、在其内部、包含来源时均拒绝；来源书签失效或无法判断关系时仍停止并提示重新授权。Photos Library 包和包内目录不能作为目标。接收设置不再按卷名或年份前缀拒绝；USB 和网络共用此规则。设置失败以弹窗和页面消息显示，成功才更新路径。高级迁移/恢复/备份的原有阶段限制不在本次修改范围内。此产品规则变更不授权开发工具向受保护真实数据写入；自动化验证只使用临时合成目录。

同日用户反馈“导入手机照片包”点击无反应，实际界面显示该手动入口仍保留整个 HDD2 的旧拦截。修正普通离线导入入口，使写入目标沿用归档导入器的来源隔离校验；高级迁移/恢复/备份限制保持不变。按钮改名“导入离线照片包…”，说明 USB 上传由手机“待分享”发起，普通接收目录不是离线包。选择源目录后先检查包清单结构，无包则直接弹窗说明下一步，不再继续询问保存位置。手动和已接收批次入库都显示处理中指示、失败弹窗和完成统计；成功后选中本次导入的批次。源包检查拒绝 Photos Library 包和清单符号链接，不修改手机原件。

协议边界与关闭/恢复使用合成 fixture；直接 XCTest，不启动生产 Photos 宿主。连接真实手机只执行显式 Debug 合成探针，不创建真实 Photos 模型。验证 USB 数据通路和断线后禁止网络回退；实际 Photos 导入需用户选片和接收位置。不变更来源写入/删除或 iCloud 下载边界。

macOS 沙盒访问系统 usbmuxd 必须在签名 App 中验证，不能以无沙盒 CLI 成功代替。当前为 Xcode 开发功能；正式分发前另核验沙盒例外与分发要求，不默认宣称已满足商店分发。

本机验证普通 USB/network entitlement 及文件读写例外均不足以连接该 Unix socket（EPERM）；最小可用配置为 `temporary-exception.sbpl` 中仅放行 `network-outbound` 的 `/private/var/run/usbmuxd` literal。不增加文件读写例外、不关闭 App Sandbox。此项是开发构建适配，不属于已获 Apple 分发审核的承诺。

## 2026-10-09：准备、恢复与封存请求超时修正

手机真实使用反馈：点击导入约 15 秒后报 `The request timed out`；所示阶段尚处于目录与整理信息准备，不能把此错误当作传输完成。只读核对指定接收目录后，确认两个旧批次均未封存、无最终清单，原件已部分落盘。该检查未重新哈希原件或修改接收内容。

实现审计发现三个独立截止时间：普通客户端请求 15 秒、Mac 从接入到响应的 15 秒计时、固定证书 URLSession 整个请求的 120 秒上限。只延长其中一处无法支持大量目录提交或慢盘恢复／封存。

本次决策：协议共享一份有界处理时限，目录和整理信息请求 180 秒，批次开始／查询和单原件复验 600 秒，整批封存 1,800 秒，分块写入仍为 90 秒。Mac 只有在完整请求已解析且已通过配对设备 bearer 验证后才切换到长处理时限；请求头接收、未授权请求、普通 UI/API 仍使用原有 15 秒限制。证书固定 session 的资源总时限至少为 1,860 秒，普通请求本身仍为 15 秒。取消、USB 中断停止、证书核验、禁蜂窝归档、数据块哈希、恢复检查和最终独立复验保持原契约。

手机分别展示目录／旧回执核对、目录发送并等待回执、整理信息同步、原件准备、传输、Mac 复验及封存；超时错误带具体阶段，说明旧进度保留。不会仅因重试、更新或服务启动自动继续写入真实接收目录。

本轮验证：旧配置 RED；修复后 RemoteClient 80 项、RemoteProtocol 96 项、Mac 5 项针对性直接 XCTest 共 181 项通过。两端构建及严格签名通过。当前 Xcode Scheme ImageAll / My Mac 构建后已运行新版，gwlee 有线安装/启动新版 iOS 成功；接收目录配置保留，已发起新的 USB 请求等待手机核实身份，未自动恢复照片传输。证据：`/Volumes/SSD1/.codex-builds/USBImportTimeoutFix-20261009/Evidence/REPORT.md`、`runtime.json` 和测试/构建日志。实机原范围续传及最终完整项数核对仍待用户操作；不把上述合成结果标为真实照片导入完成。

## 2026-10-09：导入准备阻塞 UI 导致 USB 心跳误断开

用户反馈在手机点击导入、短暂检查传输后 USB 自动断开，导入按钮因 `isConnected == false` 禁用。实现审计发现数据字节转发虽已移出 MainActor，控制心跳仍在每次 receive 后跳回 MainActor；大量 PhotoKit/相簿或目录准备占用 UI actor 时，会超过 Mac 8 秒心跳响应期限。
